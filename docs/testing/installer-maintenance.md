# Windows 安装器维护隔离验收

依据：[已确认设计](../superpowers/specs/2026-10-22-installer-maintenance-design.md)与
[实施计划](../superpowers/plans/2026-10-22-installer-maintenance.md)。

本文描述可重复执行的验收步骤，不代表这些场景已经通过。自动化命令和隔离安装场景分别记录结果，
不能用配置断言、成功编译或源码审查替代真实安装、UAC 与界面验证。

## 1. 环境与证据准备

1. 使用 Windows 虚拟机、Sandbox 或专用测试用户；先记录 Windows 版本、账户类型、语言、
   显示缩放、测试安装包版本、文件哈希和签名状态。当前开发用户的真实安装不作为测试目标。
2. 为测试环境创建可恢复快照。需要同时使用标准用户和另一管理员账户验证跨账户 UAC；
   只具备管理员账户的 Sandbox 不能替代该场景。
3. 准备两个不同的稳定版本包，二者都包含本次维护逻辑；其中一个用作已安装版本，另一个用作更新包。
   例如 `0.9.0` 与 `0.10.0` 可同时验证数值比较，包版本应与文件名和应用版本一致。
4. 仅在隔离测试环境准备独立临时会话 fixture，可使用
   [扫描器测试](../../tests/usageScanner.test.ts)中的合成 JSONL 内容；不复制真实会话日志。
   在应用中选择该 fixture，并设置可辨认的语言、主题和预算。
5. 每轮操作前关闭应用，记录测试用户 `%APPDATA%\codex-token-usage` 中全部文件的相对路径、
   SHA-256 与权限，以及 fixture 的文件清单、SHA-256 与权限。记录原安装路径、安装范围、
   Windows 卸载登记、桌面和开始菜单入口。
6. 每轮操作完成后先取消“启动应用”，对照第 5 步的快照，再单独验证启动。否则正常运行产生的
   缓存写入会干扰“安装过程保留应用数据”的断言。
7. 如需检查是否访问 fixture，使用测试环境的文件访问跟踪记录；内容哈希不变只能证明内容未改，
   不能单独证明安装器未读取文件。任何跟踪均只针对合成 fixture，不访问真实会话目录。

删除文件和修改登记只在已确认的测试安装范围内进行，使用虚拟机快照复位各场景。
不要把任意用户目录、盘符根目录或系统目录作为实际安装/删除目标。

## 2. 自动化检查

先运行与打包配置相关的最小检查：

```powershell
npm test -- tests/packagingConfig.test.ts
npm run lint:docs -- README.md docs/testing/installer-maintenance.md
```

实际 NSIS 策略测试必须编译并执行安装器使用的函数；仅在 JavaScript 中重写版本状态逻辑不构成
安装器行为验证。测试使用独立临时目录和唯一测试产品注册键，不能写入真实产品登记。

交付前运行项目门禁和实际安装包构建：

```powershell
npm test
npm run typecheck
npm run lint
npm run build
npm run build:win
```

若使用已有本地 Electron 二进制，执行 `npm run build:win:cached` 并记录这一方式。
记录每条命令的退出码与失败根因；安装器签名状态与构建成功分开记录。

## 3. 首次安装与正常维护

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 当前用户首次安装 | 无登记时运行安装包，分别选默认路径与含空格的自定义路径 | 显示首次安装向导；目录选择和应用子目录行为兼容，无主动提权 |
| 所有用户首次安装 | 选择所有用户安装，完成一次授权并另测取消授权 | 使用原生 UAC；取消时不安装，不留下成功状态 |
| 同版本修复 | 安装后再次运行同版本包 | 显示已安装版本、包版本、路径和范围；修复可用，更新不可用且原因可读 |
| 新版本更新 | 运行更高版本包 | 更新可用；修复原版本不可用并提示需要对应包；实际更新至包版本 |
| 维护路径与范围 | 执行修复和更新，检查页面与实际登记 | 不重新选择目录或范围；实际位置和范围不变；保留一份对应卸载登记 |
| 完成页 | 成功后分别取消启动与勾选启动 | 目标版本准确；取消启动时应用不运行，勾选后以正常用户上下文运行 |

## 4. 损坏恢复与快捷方式

每个损坏场景都从正常测试安装快照开始，关闭程序，只移除表中指定的测试文件，然后运行同版本包。

| 场景 | 操作与预期结果 |
| --- | --- |
| EXE 丢失 | 删除测试安装的 `CodexTokenUsage.exe`；仍识别已有安装并恢复程序，版本不变 |
| 资源丢失或被修改 | 移除或修改测试安装中的资源文件；修复后与同版本包对应文件一致，应用可启动 |
| 卸载器丢失 | 删除测试安装的卸载器；修复后恢复卸载入口，随后通过系统入口可以卸载 |
| 开始菜单入口丢失 | 删除测试安装的开始菜单快捷方式；修复后重建正确入口 |
| 曾取消桌面入口 | 首次安装取消桌面快捷方式后更新；更新不重新创建桌面入口 |
| 已选择桌面入口 | 首次安装选择桌面快捷方式后修复或更新；快捷方式目标仍正确，只有一份入口 |
| 手动删除桌面入口 | 删除测试桌面入口后修复；核对保存偏好及修复页选择，分别验证恢复和不创建 |
| 旧版没有偏好登记 | 使用真实历史包或移除仅测试安装的桌面偏好登记；维护默认采用操作前状态，修复页仍允许恢复入口 |
| EXE 与桌面入口同时丢失 | 在 EXE 缺失时再次覆盖桌面选择场景，防止原生快捷方式分支意外重建用户取消的入口 |

修复是重新部署当前包管理的文件，不承诺清除全部未知残留文件、逐文件完整性扫描或修复系统环境。
卸载器缺失的场景应记录是否有残留文件，不能只依据安装器退出成功认定完整恢复。

## 5. 拒绝路径与静默安装

拒绝场景均需核对：已有程序文件、登记、快捷方式、应用数据与 fixture 未被更改，未部署程序或
调用旧卸载器；退出结果不是成功。上游初始化可能在自定义拒绝检查之前创建空目标目录，不能把
“没有替换程序”写成“文件系统零写入”；已确认的复现和验收边界见第 5.1 节。

| 场景 | 操作与预期结果 |
| --- | --- |
| 低版本包 | 已安装高版本后运行含维护逻辑的低版本包；说明禁止降级并停止替换 |
| 异常版本 | 在测试登记中分别设置缺失版本、非法字符串、预发布后缀、构建元数据；均不能误判为首次安装或版本零 |
| 登记矛盾 | 在测试环境构造缺少必要路径或安装登记不一致；停止维护，不从同名 EXE 猜测身份 |
| 两个范围均有安装 | 在测试环境构造当前用户与所有用户副本；维护停止，不误卸载其中任何一个 |
| 路径迁移参数 | 对已有安装传入不同 `/D=` 目录；拒绝迁移，不替换原目录或向候选目录部署程序，单独记录初始化创建的空目录 |
| 范围迁移参数 | 对已有安装传入相反范围参数；拒绝切换，不能把原安装当作首次安装 |
| 删除数据参数 | 对修复和更新传入 `--delete-app-data`；在调用旧卸载器前拒绝，应用数据保持不变 |
| 异常目标路径 | 仅在隔离登记中模拟根目录、系统目录或相对路径；验证安装器在任何替换前拒绝，不能实际删除这些目标 |
| 静默维护 | 分别用 `/S` 执行同版修复和新版更新；使用相同版本、路径与安全校验，不显示自定义维护页 |
| 静默拒绝 | 将以上拒绝场景各运行一次 `/S`；自定义检查按第 5.2 节返回对应非零退出码，不能因跳过页面而漏检 |

静默验证由父进程等待安装器结束并记录退出码，不能只观察“没有窗口”。NSIS 的 `/D=` 参数必须放在
命令行末尾；静默命令应基于本轮已记录的测试包绝对路径构造，不复用开发环境的安装目录。

### 5.1 已确认的原生初始化限制

electron-builder 26.15.3 的 `templates/nsis/installer.nsi` 在 `.onInit` 中先执行
`SetOutPath $INSTDIR`，然后才调用 `preInit`、`initMultiUser` 和 `customInit`。
因此 `/D=` 指向尚不存在的目录时，原生初始化可能先创建空目录，再由维护检查拒绝操作。
该限制不表示已执行程序部署或旧版本卸载；验收时应分别记录空目录创建与实际文件替换。

2026-10-22 已在 Windows `10.0.26200.0` 使用 electron-builder 缓存中的 NSIS
`nsis-3.0.4.1`（`makensis /VERSION` 返回 `v3.04`）完成以下最小复现。两个程序和目标路径均
位于工作区唯一私有临时目录，不运行实际产品安装包、不操作产品注册表，也不访问应用或会话数据。

```nsis
Unicode true
RequestExecutionLevel user
SilentInstall silent
Name "NSIS initialization audit"
OutFile "${OUTPUT_EXE}"
Function .onInit
!ifdef AUDIT_SETOUTPATH
  SetOutPath $INSTDIR
!endif
  SetErrorLevel 23
  Quit
FunctionEnd
Section -Unused
SectionEnd
```

复现步骤：在私有临时目录保存上述源码，分别在未定义和定义 `AUDIT_SETOUTPATH` 的情况下编译，
为每个程序准备一个尚不存在的独立目标目录；用 `/S /D=<该目标的绝对路径>` 启动并等待退出。
`/D=` 必须在最后，目标只能位于本轮私有临时目录内。记录退出码、目录是否存在及目录条目数，
最后仅清理已核对绝对路径属于本轮临时目录的产物。

| 程序 | 退出码 | 目标目录 | 目录内容 |
| --- | --- | --- | --- |
| 无 `SetOutPath` 的对照程序 | 23 | 不存在 | 不适用 |
| 执行 `SetOutPath $INSTDIR` 后立即退出 | 23 | 已创建 | 0 项 |

本地源码、两个最小程序和结果保存在
`out/installer-init-audit-ad4da657b6be4216bbd32bc0b8088118/`，结果文件为 `evidence.json`。
证据中的 `root` 是执行时的私有临时目录，`artifactDirectory` 是核对路径后移入的当前产物位置；
这些产物不作为版本库测试 fixture，也不代表完整安装包已通过验收。

这项实证仅验证初始化语句的副作用，不能替代完整安装包的拒绝、UAC 或数据保留验收。

### 5.2 自定义维护检查退出码

以下映射由本项目的维护检查提供，静默调用方可据此区分失败原因；它不是所有 NSIS 失败的统一
退出码规范。原生 UAC、旧卸载器或解包失败继续沿用 electron-builder 的原生退出语义。

| 退出码 | 原因 | 含义 |
| --- | --- | --- |
| 17001 | `invalid-version` | 版本缺失或不符合支持的稳定版本格式 |
| 17002 | `downgrade` | 安装包版本低于已安装版本 |
| 17003 | `registration` | 安装或快捷方式登记无法可靠识别 |
| 17004 | `path` | 目标路径不安全或与登记不一致 |
| 17005 | `scope` | 安装范围冲突或不一致 |
| 17006 | `parameters` | 参数试图迁移位置、改变范围或删除配置 |
| 17007 | `changed` | 安装状态在操作期间发生变化 |
| 17008 | `write` | 自定义维护步骤未能完成，例如快捷方式写入失败 |
| 1603 | 未知原因 | 自定义检查的兜底失败码 |

已核对模板所附 `UAC.nsh`：正常启动并等待提升子进程结束时，`UAC_RunElevated` 将其退出码放入
`$2` 并设置外层 NSIS 错误级别，原生外层随后执行 `Quit`。这不覆盖取消提权或启动失败分支，
也不代表跨账户 UAC 已实测；隔离验收仍须等待最外层进程并记录实际退出码。

## 6. 提权、占用与失败

1. 分别在当前用户和所有用户安装中保持测试应用运行，执行维护，验证关闭提示、取消和重试。
   其他应用或其他目录中的同名进程不能被新增自定义逻辑批量关闭。
2. 所有用户维护时取消 UAC；确认未替换程序文件、没有成功完成提示，也未启动应用。
3. 从标准用户发起所有用户维护，输入另一管理员账号凭据；分别测试两个账户均无冲突、外层账户
   有用户级副本、管理员账户有用户级副本。任一可见账户存在会被连带卸载的副本时必须停止。
4. 对所有用户安装运行静默维护；确认外层和提升后内层均校验目标，未授权外层不部署程序或调用
   旧卸载器；原生初始化创建空目录的限制按第 5.1 节单独记录。
5. 仅在测试安装中制造可重复的文件占用或权限拒绝，记录具体条件。验证失败不显示成功、不自动
   启动残缺应用，并提供可读错误；不将上游失败处理描述成任意阶段事务回滚。
6. 在实际写入前返回上一步、重新进入维护页和取消，验证选择不串联、版本与目录重新校验。

## 7. 界面与数据保留

- 中英文系统各执行一次维护，检查标题、版本、范围、禁用原因、错误和完成文本。
- 使用 Tab、方向键、空格、回车和取消键完成操作；被禁用的选项应有静态说明，可访问名称清楚。
- 在 100%、150% 和 200% 缩放检查长路径、版本、标题和按钮；高对比度下不能只靠颜色表示状态。
- 修复、更新和卸载后、启动应用前，核对应用数据和 fixture 的清单、哈希与权限；卸载仅移除
  程序和受管理入口，应用配置保留。跟踪记录中安装器不应读取或修改 fixture。
