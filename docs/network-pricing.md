# 联网价格目录维护

## 客户端行为

价格用于按当前单价重算历史用量，始终是本地估算，不代表实际账单。用户手动覆盖优先于联网目录，联网目录优先于内置目录。长上下文、缓存写入和运行模式只使用对应模型已核对的声明式规则，缺少条件时显示参考估算与原因，不跨模型推导倍率。

新版支持官方未提供缓存输入价格的模型：目录使用显式 `null`，输入和输出仍正常计价。只有实际缓存读取用量缺少单价的部分计入未计价 Token，不填 0、不按普通输入价格补齐。明确数值 0 仍表示免费；手动覆盖可以提供完整三项价格。

应用先加载本地缓存，网络不阻塞启动。默认自动更新，每 24 小时检查；失败和未计价模型请求最多每小时自动重试。预算中心的模型价格页可关闭自动更新或手动刷新。新缓存位于 userData 的 `pricing-cache-v3.json`，首次不存在时只读导入旧 `pricing-cache.json` 的有效目录与偏好并保存新文件，旧文件保留供应用回滚使用。不写入会话目录，不上传会话数据。

## 托管与首次启用

新版地址为 https://raw.githubusercontent.com/Nancyingcode/token-usage/pricing/catalog-v3.json 。仓库必须允许匿名读取该分支文件；私有仓库不能直接提供公开目录，不向客户端分发 GitHub Token。

1. 用户将实现和工作流合入默认分支。本地开发不会自动提交或推送。
2. 在 GitHub Actions 手动运行 Update pricing catalog。工作流需要 contents: write 权限，并受仓库规则约束。
3. 检查采集、验证和发布均成功；确认 pricing 分支根目录同时包含 `catalog.json`、`catalog-v2.json`、`catalog-v3.json`，匿名读取返回匹配版本的有效 JSON。
4. 在应用点击立即更新，确认目录版本和联网来源。检查无缓存价模型显示“官方未提供”，有缓存用量时对应 Token 显示未计价。

新客户端下载 v3，仅 HTTP 404 才回退 v2，再仅 404 回退 v1。网络错误或格式错误不触发回退；成功缓存 v3 后，不接受旧格式覆盖。首次发布前全部文件可能返回 404，此时继续使用内置价格并显示失败。

## 采集与发布

工作流每天读取官方模型 Markdown 目录，发现 GPT 文本模型和 Codex 模型的明确 ID，再读取其价格节。解析器按标题层级定位 Text tokens 三列表格，逐行核对美元与每百万 Token 单位；不读取比较表、音频价格或独立 Batch 价表。

结构完整、输入与输出有效且缓存行完全不存在时记录 `null`。畸形或重复行、改名指标、非法价格、错误单位和网络错误均使任务失败。已发布的数字缓存价突然消失也使任务失败，需要维护者核对，不能静默降低历史覆盖率。旧目录中不再列出的模型仍保留，别名不能自动丢失或产生冲突。

本地命令：

```sh
npm run pricing:validate
npm run pricing:update
npm run pricing:update -- --output-dir <独立临时目录>
npm run pricing:validate -- --output-dir <独立临时目录>
```

采集器按 v3、v2、v1 的顺序读取历史基准，只有 404 才继续；全部 404 才使用仓库 v3 种子。输出目录可以独立于种子目录，因此联网验证不必覆盖仓库种子。采集与整份目录校验成功后才写入文件；写入失败退出，后续校验拒绝混合快照，不进入发布。

三份目录来自同一快照：

| 文件 | schemaVersion | 内容 |
| --- | --- | --- |
| catalog-v3.json | 3 | 全部历史模型，缓存价允许 null，包含已核对条件规则 |
| catalog-v2.json | 2 | v3 中三类单价完整的模型，保留条件规则 |
| catalog.json | 1 | 与 v2 相同模型集合，去除条件规则 |

三份文件共享 version 与 publishedAt，旧客户端无法表达的空价模型仅出现在 v3。发布前校验文件内容正好符合上述投影，并基于当前父提交检查历史模型、别名、单价完整性与发布时间没有退化。

发布器通过 GitHub Git Data API 在一个 tree 和提交中写入三份文件，一次非强制 ref 更新后才对客户端可见；并发发布冲突会失败。发布脚本仅允许在配置仓库的 GitHub Actions 环境运行，不修改源码分支。

## 字段和维护约束

- currency 为 USD，unit 为 per-million-tokens。
- version 标识目录版本，publishedAt 为目录发布时间。
- effectiveAt 表示该价格条目的观察日期，不保证是官方历史调价时间；空缓存价补齐成数值也更新该日期。
- sourceUrl 指向官方模型页；aliases 只能使用已确认的别名，所有 ID 与别名在目录中必须唯一。
- 输入、输出及非空缓存价格均为有限非负数。v3 的缓存字段必须明确为数字或 null，字段缺失和字符串不合法；v1/v2 仍只接受数字。
- 缺缓存价不代表模型不支持缓存，也不能自动解释为按普通输入价收费。
- 官方页面布局不是稳定 API。发生解析失败时先检查日志中的模型与 URL，更新对应 fixture，再重跑完整采集；不能通过忽略失败模型恢复发布。
- 新的计费规则需要明确适配，不能仅凭新增目录模型宣称支持。
- 纠正价格时发布新的 version/publishedAt，不能回退时间戳或删除已收录模型。不能将本地验证成功描述为远程已上线。

仓库 v3 种子由既有 v2 种子生成，保留原有历史价格与观察日期，不代表重新核价。正式发布前必须完成真实源采集和三份目录一致性校验。修复设计与验证要求见[设计文档](./superpowers/specs/2026-10-21-pricing-collector-repair-design.md)。
