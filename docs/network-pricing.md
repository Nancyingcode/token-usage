# 联网价格目录维护

## 客户端行为

第一阶段只同步美元每百万 Token 的标准输入、缓存读取和输出价格。历史用量使用当前价格重算，不代表实际账单，不支持长上下文、Fast、Batch 和缓存写入等条件费用。用户手动覆盖优先于联网目录，联网目录优先于内置目录。

应用先加载本地缓存，网络不阻塞启动。默认自动更新，每 24 小时检查；失败和未计价模型请求最多每小时自动重试。可在预算中心的模型价格页关闭自动更新或手动刷新。缓存位于应用 userData 的 pricing-cache.json，不写入任何会话目录，不上传任何会话数据。

## 托管与首次启用

托管地址为 https://raw.githubusercontent.com/Nancyingcode/token-usage/pricing/catalog.json 。仓库必须允许匿名读取该分支文件；私有仓库不能直接提供这个公开目录，不应向客户端分发 GitHub Token。

1. 用户将实现和工作流合入默认分支。本次开发不会自动提交、推送或启用远程服务。
2. 在 GitHub Actions 手动运行 Update pricing catalog。工作流需要 contents: write 权限，并受仓库规则约束。
3. 检查采集、验证和发布步骤均成功；确认 pricing 分支根目录出现 catalog.json，匿名读取返回有效 JSON。
4. 在应用模型价格页点击立即更新，确认目录版本、联网来源和 Astra 基础价格。

首次发布前客户端可能收到 404，此时显示网络失败并继续使用内置价格，不代表远程目录已经上线。

## 采集与发布

工作流每日运行。采集器读取官方模型 Markdown 目录，发现 GPT 文本模型和 Codex 模型的明确 ID，再读取各模型的价格节。只接受明确的三类价格和每百万 Token 单位；不推测缺失缓存价格或模型别名。旧目录中不再列出的模型仍保留，防止历史会话丢失计价。

本地命令：

```sh
npm run pricing:validate
npm run pricing:update
```

update 下载完整上次目录（首次 404 才使用仓库种子），所有模型解析成功并通过客户端同一校验器后才写文件。解析或网络失败不会发布部分更新；应检查 Actions 失败记录，修复解析器及对应 fixture 后重跑。官方页面布局不是稳定 API，本地环境当前访问官方 Markdown 返回 403，首次上线必须确认真实源结构与可达性；fixture 测试不能替代这项验证。

发布器通过 GitHub Git Data API 创建 pricing 分支目录提交，不修改源码分支，不强制覆盖分支头。发布脚本仅允许在配置仓库的 GitHub Actions 环境运行。目录包含完整历史模型集合；回滚价格时应以新的 publishedAt 和 version 发布纠正目录，不能发送旧时间戳或删除已收录模型。

## 字段和维护约束

- schemaVersion 固定为 1；不兼容格式由客户端拒绝。
- currency 为 USD，unit 为 per-million-tokens。
- version 标识目录版本，publishedAt 为目录发布时间。
- effectiveAt 表示该价格条目的记录日期，不保证是官方历史调价时间。
- sourceUrl 指向官方模型页；aliases 只能使用已确认的别名。
- 价格为有限非负数；所有模型 ID 和别名在目录中必须唯一。
- 新的计费规则需要升级计算逻辑，不能仅凭目录扩展宣称已支持。

种子目录保留现有内置历史价格，并加入 2026-09-10 核对的 Astra 基础价格。其余旧条目并未重新核价，正式发布必须先完成采集任务。
