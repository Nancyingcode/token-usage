# 会话模型、思考强度与 Fast 占比实施计划

[已确认的设计](../specs/2026-11-28-session-model-effort-fast-share-design.md)

1. **模型与思考强度归属。** 先用合成日志测试同一强度下换模型、同一模型换强度、字段缺失和冲突，以及没有增量的回合和累计回退。复用现有回合身份和用量归属逻辑，独立保存每轮的模型与强度，按两项组合汇总。保留累计值未增长时跳过重复用量的回归。
2. **线程速度统计。** 先测试首次快照晚到、同轮切换、重复累计值、相同时间戳、空或陌生档位、匿名回合身份合并及分叉文件归属。读取速度快照时记录已纳入的 Token 小计，用相邻设置之间的小计差计算用量。通过同一回合身份记录最早的开始位置，在确定所属线程后归入开始时的设置。未知用量和未知回合均计入分母。
3. **扫描缓存。** 先测试旧版本失效、损坏字段拒绝，以及原始压缩文件移除后的导入副本仍能重算。升级扫描缓存，验证模型及速度的汇总字段。复用当前的用量 IPC 和导入流程。
4. **会话详情。** 先测试同一模型和强度的不同组合、两个百分比的分子分母、未知量、全部未知、零分母和已知的 0%。用模型列和思考强度列展示分组，突出 Fast 的 Token 占比，并展示回合占比、切换历史和实际服务档位。沿用现有本地数字格式及中英文翻译，检查宽窄窗口和键盘操作。
5. **构建和实机验收。** 运行相关测试、全量测试、类型检查、lint、生产构建和 Electron 布局检查。生成 Windows x64 安装包，校验构建结果并重新安装，用同一条历史会话核对各组总计为 22,589,102 Token、Fast 设置期间记录 12,398,515 / 22,589,102 Token（54.89%）、开始时设为 Fast 的回合 4 / 14（28.57%，其中 1 轮起始设置未知）。确认真实会话原文件在验证前后的哈希一致。

## 验证记录

- 新增断言先在旧实现上复现缺少模型分组、Fast 占比和缓存重建的问题，修复后定向用例通过。扫描缓存升至 v5，普通文件和已导入压缩文件的回归均通过。
- `npm test -- --maxWorkers=2` 复跑通过，共 170 个测试文件、1,212 项用例。`npm run typecheck`、`npm run lint`、生产构建及 `npm run test:layout -- --motion` 均通过。首次全量执行的 ESLint 规则测试超时，首次布局检查的概览动画计数波动，两项在复跑通过。
- Windows x64 安装器返回 0，安装后的可执行文件和应用归档与构建产物的哈希相同。实机界面中的两组用量加总到 22,589,102 Token，两项 Fast 占比与验收值一致。应用的 v5 缓存与独立日志对账一致，会话原文件的哈希在验证前后一致。
