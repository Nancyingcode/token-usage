# 价格更新修复与部分计价实施计划

依据：[已批准设计](../specs/2026-10-21-pricing-collector-repair-design.md)。用户最初授权本地实施和完整验证，随后于 2026-10-21 授权提交本次改动并合入 master；不推送、不发布远程目录。

## 任务与顺序

1. 目录与采集发布：先用真实官方价格片段复现子标题和三列表格失败，再实现严格解析、v3 空缓存价、历史保留与退化检查、v1/v2 兼容投影和三文件一致发布。补充网络、格式、写入与并发失败回归。
2. 计价核心与下游：先补空缓存价与真实 0、零缓存和部分用量的回归，再调整价格类型、逐请求计算和汇总。同步预算、成本覆盖、诊断和节省建议，保证未计价与条件假设不重叠。
3. 主进程同步与缓存：先补 v3 下载、仅 404 回退、版本对应、缓存导入与回滚保护测试，再实现同步与独立 v3 缓存。保持已有安全与生命周期规则。
4. 界面：先补无缓存价展示、空编辑值、未计价原因提示和覆盖率回归，再同步中英文文案与交互。空值不得显示或保存为免费。
5. 联合验证与维护文档：核对全链路类型与行为，更新维护说明，使用全部 42 个已下载官方页面回放及独立临时目录真实网络采集，检查三份目录关系。只运行本地校验，不调用远程发布。
6. 执行完整 `npm test`、`npm run typecheck`、`npm run lint`、`npm run build`、`npm run pricing:validate` 和差异检查。记录成功数量、环境限制和未完成的远程发布验收。

目录/采集、计算、同步和界面在确定共享契约后可并行实施，各任务限定文件范围；共享文件由单个任务负责。所有行为修改先见到有意义的失败测试，再实现并运行最小相关测试集，最后运行完整门禁。

### 回归与独立复核

- 原有价格基线为 5 个测试文件、32 个测试通过。官方 Markdown、v3 目录、同步与迁移、部分费用计算、界面空价与编辑均先复现失败，再实现并通过对应测试。
- 独立复核补充两类先红后绿回归：损坏的无分隔符缓存行不能被误当成缺价；部分计价的当前观测或历史基线不能产生异常回落的现金节省结论。完整历史与完整用量仍正常产生建议，混合历史仅使用完整样本。
- 运行时回归覆盖缓存价数值 → null → 数值：总计与项目快照、诊断结果均重算；同值更新复用缓存，Token 索引不重新扫描或持久化。
- 42 个已下载官方原文完成全流程回放，生成 v1/v2 各 34 个模型、v3 共 42 个模型，其中 8 个缓存价为 null。收紧解析器后全部原文仍通过。
- 最终解析器再次执行真实网络采集，结果与回放相同，三份目录一致性校验通过。输出仅保存在独立临时目录；仓库 v3 种子由原 v2 生成，v1/v2 种子价格未改。
