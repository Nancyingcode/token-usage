# 性能页缓存命中率详情实施计划

## 目标

将性能页现有的单一缓存百分比和错误的每日总 Token 折线，替换为可解释的缓存效率详情：展示整体缓存率、缓存/未缓存/总输入 Token 构成，以及最近最多 30 个日期的真实每日缓存率和精确日期详情。

## 架构

在 Renderer 新增缓存效率纯函数，将当前筛选后的 `UsageSummary` 转换为带空值和异常状态的稳定视图模型。独立的缓存详情组件消费该模型，负责汇总、构成条、每日趋势、详情浮层和键盘焦点状态；`PerformanceView` 只负责组合现有性能指标。该变更不修改主进程、IPC、preload、扫描器或 Codex 会话数据，并保留工作区现有的活跃时段详情改动。

涉及文件：

- 新建 `tests/cacheEfficiency.test.tsx`
- 新建 `src/renderer/utils/cacheEfficiency.ts`

步骤：

1. 为整体和每日缓存率、缓存输入、未缓存输入及总输入添加失败测试。
2. 验证真实 `0%` 与无输入 `null` 的区别。
3. 验证只保留最近最多 30 个日期，并保持日期顺序。
4. 验证缓存输入大于总输入时保留原值、未缓存输入不为负、百分比限制在 `100%` 且输出异常标记。
5. 冻结输入数据，验证聚合函数不修改 `UsageSummary` 及其数组。
6. 运行 `npm test -- tests/cacheEfficiency.test.tsx`，确认测试因功能尚未实现而失败。

## 任务 2：实现缓存效率纯函数

涉及文件：

- 新建 `src/renderer/utils/cacheEfficiency.ts`
- 修改 `tests/cacheEfficiency.test.tsx`

步骤：

1. 定义每日详情和整体详情接口，明确 `percentage: number | null`。
2. 用具名常量实现百分比计算、合法范围限制和最近 30 日截取。
3. 以 `Math.max(0, inputTokens - cachedInputTokens)` 计算未缓存输入，不修改原始 Token。
4. 汇总和每日分别计算异常状态，整体异常状态同时覆盖任一每日异常。
5. 运行缓存效率测试达到绿色，再消除重复计算逻辑。
