# 思考强度与 Fast 模式实施计划

[已确认的设计](../specs/2026-11-28-reasoning-effort-fast-mode-design.md)

1. **回合与用量。** 先以合成 JSONL 验证强度切换、多请求、重复回合上下文、缺字段、明确零与无记录、归属冲突和累计回退。扩展共享会话类型，在主进程逐轮归属用量并生成每档的回合数、总 Token 和推理输出 Token，核对各档总数与既有会话统计。
2. **线程速度与缓存。** 先测试同一线程切换、连续相同的快照、晚到事件、陌生或空档位、分叉记录和费用不变。由解析器输出按文件顺序去重的速度变化和时间。升级扫描缓存格式和校验，使用临时目录验证普通 JSONL 与已导入压缩会话重新解析、重复扫描及缓存复用结果一致。
3. **会话详情。** 先为普通会话和无历史数据的会话编写界面测试，再接入每个会话共用的详情入口，展示强度用量、最近的线程速度、可展开的变化记录和实际服务档位的记录状态。复用日期与数字格式化，补齐中英文文案和宽窄窗口布局。
4. **集成验收。** 对受影响模块运行定向测试，用隔离的合成数据在宽屏和 1024 × 680 窗口检查键盘展开、收起后的焦点和内容可读性。执行 `npm test`、`npm run typecheck`、`npm run lint` 和 `npm run build`，记录结果及环境限制。

## 实施记录

- 回合强度按可识别的回合去重。结束后迟到、且仍能用 ID 唯一匹配的用量可计入原回合。跨越新的回合或会话边界后，缺少归属证据的用量归入“未知”。只有累计记录时仍能展示已识别的回合数。
- 扫描缓存升为 v3。普通文件从数据源只读重建，已导入的压缩会话使用应用私有原文重建。测试覆盖原压缩文件已移除的情况。
- 会话详情和内部的速度记录分别按需加载。300 条速度记录的回归覆盖展开后收到第 301 条记录时的焦点、展开状态和收起行为。

## 验证结果

- `npm test -- --maxWorkers=2` 通过，共 170 个测试文件、1,191 项用例。测试使用合成日志与隔离目录。
- `npm run typecheck`、`npm run lint` 和 `npm run build` 通过。主进程、preload 和渲染进程均已完成生产构建。
- `npm run test:layout -- --motion` 通过。隔离 Electron 窗口覆盖 1024 × 680 和 1440 × 900 下的中英文详情，验证 Enter、空格、收起后的焦点、速度历史及展开内容无横向溢出。
