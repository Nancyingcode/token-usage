# 条件计价第二阶段实施计划

依据：[已确认设计](../specs/2026-09-10-conditional-pricing-design.md)。用户已明确确认，实施中不提交、不推送。

1. 为逐请求长上下文、缓存写入、模式缺失和覆盖规则编写失败测试，再实现纯函数计价内核与用量上下文。
2. 为日志解析与可重建缓存编写失败测试，再保留真实字段并升级扫描和成本索引，所有聚合保留请求粒度。
3. 为 v1/v2 兼容与双目录发布编写失败测试，再实现条件规则校验、下载回退和采集发布适配。
4. 将预算、性能、成本趋势、诊断和情景计算统一接入，传播条件假设与覆盖率，排除不可靠货币化建议。
5. 扩展价格编辑与中英文界面，提供明确的规则来源和缺失条件提示，补充交互测试。
6. 执行 npm test、npm run typecheck、npm run lint、npm run build、目录验证和差异检查。真实源 403 与未发布状态单独报告。

## 约束

不将 API 响应字段当作已确认的 JSONL 字段；当前日志缺少运行模式时标记标准模式假设。缓存写入正数的分区语义需官方证据，无法确认时保留数据并标记不完整，不强行激活猜测算法。第一阶段已安装客户端继续使用 catalog.json，新客户端优先 catalog-v2.json。

## 完成记录（2026-09-10）

以上六项本地实施任务已完成。逐请求计价保留请求边界，成本索引版本更新为 3、扫描缓存版本更新为 2；旧缓存触发只读重解析。已核实规则单独保存在声明式配置中，新模型没有规则时明确标记参考估算，不继承 Astra 倍率。

价格采集生成 catalog.json 和 catalog-v2.json，发布器校验基础快照一致后在同一提交中发布两者。下载器仅在 v2 返回 404 时回退；有效 v2 缓存拒绝被 v1 降级。预算、概览、性能、预测与模型比较统一使用逐请求计价，条件假设与未知模型兜底分别统计；不可靠的货币化诊断和建议被排除。

手动覆盖默认保留固定价格，并提供显式勾选目录规则和规则预览。新增中英文条件缺失原因、缓存写入费用构成及系统通知说明。
