# 首屏加载速度优化设计

## 1. 背景

本次“首屏优化”只指应用冷启动后，从进程就绪到概览数据可用的加载速度，不调整概览的信息层级、卡片布局或视觉样式。

当前启动链路存在以下阻塞：

1. 主进程依次读取语言、主题、数据目录、预算配置和成本优化配置，并完整加载及校验成本优化缓存；这些工作完成后才创建窗口。
2. 成本优化缓存校验会重建并核对多个索引集合。缓存越大，窗口创建前的主线程工作越多，但概览首屏并不依赖成本优化结果。
3. 首次用量扫描完成后，`UsageRuntime` 会等待预算评估、成本预算同步和成本索引更新全部串行完成，才把扫描结果返回 Renderer。概览所需的用量数据因此被非首屏分析阻塞。
4. 主进程启动监控与 Renderer 首次挂载都会触发刷新。运行时的单飞逻辑可合并重叠请求，但如果后台首次扫描先于 Renderer 请求完成，仍可能紧接着执行第二次完整扫描。
5. 用量扫描器的解析缓存只存在于当前进程内。每次冷启动都要重新读取并解析全部会话 JSONL 文件，即使文件从上次退出后没有变化。
6. Renderer 在创建 React 根节点前等待一次语言 IPC，并将全部页面组件静态打入首包；成本优化与数据目录状态也会在概览首次挂载时立即请求。

React `StrictMode` 只会在开发环境帮助暴露副作用问题，生产构建不会因此执行两次首屏 Effect，本次不通过移除它规避开发期重复调用。

## 2. 目标

1. 尽早创建并展示应用窗口，不再让成本优化缓存加载与校验阻塞窗口创建。
2. 首次扫描一旦得到有效 `UsageScanResult`，立即向概览交付；预算通知和成本优化分析转入有序后台处理。
3. 每次启动只执行一次首次扫描，Renderer 复用正在进行或已经完成的启动扫描。
4. 为用量解析增加本地持久化缓存，使后续冷启动只解析新增或发生变化的会话文件。
5. 缩小 Renderer 首包，并避免概览阶段请求非首屏数据。
6. 保持扫描结果、预算、成本优化、错误降级、本地只读边界和费用估算语义正确。

## 3. 非目标

- 不调整概览页标题、指标卡、趋势图、活动日历或响应式布局。
- 不改变 Token 聚合、价格匹配、预算判断、异常诊断或预测算法。
- 不上传会话数据、缓存、启动指标或任何遥测。
- 不在真实 Codex 会话目录中创建或修改缓存；所有新增缓存只写入 Electron `userData`。
- 不承诺所有机器上的固定毫秒值。验收以关键路径消除、调用次数、缓存命中和同一环境的前后测量为准。
- 不依赖提高无上限并发数换取速度，避免大量会话文件同时读取造成磁盘抖动。

## 4. 性能边界与测量口径

本次关注两个时间点：

- **窗口可见时间**：`app.whenReady()` 后，到主窗口开始加载 Renderer 的时间。
- **概览数据可用时间**：`app.whenReady()` 后，到 Renderer 收到首次有效 `UsageScanResult` 并进入 ready、empty 或 period-empty 状态的时间。

开发验证可以使用 `performance.now()` / `performance.mark()` 记录以下阶段，但只输出到本地开发日志，不持久化、不上传：

1. 基础偏好读取完成。
2. 窗口创建。
3. 首次扫描开始与结束。
4. 首次用量结果交付。
5. 后台预算处理与成本优化处理结束。

自动化测试不使用脆弱的绝对耗时断言，而验证事件先后顺序、调用次数、是否等待以及缓存命中。人工前后测量使用相同构建、相同 fixture 或同一只读数据源，至少执行一次无缓存冷启动和一次有缓存冷启动。

## 5. 启动关键路径重构

### 5.1 并行读取基础偏好

语言偏好、主题偏好和用量数据目录互不依赖，改为并行读取。主进程 i18n 仍在语言确定后初始化；窗口背景仍在主题确定后生成；扫描器仍在数据目录确定后启动。

预算配置体积较小且概览费用估算依赖其中的价格覆盖与未知模型价格，预算运行时继续在首屏关键路径上初始化，避免概览先显示误导性的零费用或不完整价格再跳变。

### 5.2 成本优化延迟初始化

成本优化配置和持久化索引不参与概览首屏。成本优化运行时改为后台初始化，不再阻塞 IPC 注册和窗口创建。

应用运行时维护成本优化初始化 Promise 作为就绪屏障：

- 用量首次扫描不等待该屏障。
- 成本优化 IPC 在读取或修改前等待屏障；用户极快进入成本优化页时看到该页面现有加载状态，而不是未初始化的空快照。
- 用量变更在后台分析队列中先等待成本优化就绪，再按顺序应用。
- 初始化失败时只让成本优化能力进入错误状态，不阻止窗口、概览和基础用量浏览。

预算运行时初始化失败仍作为配置错误处理，不使用未验证价格生成概览费用。

### 5.3 同步传递初始语言

主进程创建窗口时已经知道有效语言。与初始主题相同，将经过验证的初始语言通过安全的窗口启动参数交给 preload，再由类型化 API 同步提供给 Renderer。

Renderer 使用该值创建 i18n 实例，不再在挂载 React 前等待 `locale.get()` IPC。后续语言更新仍沿用现有订阅与持久化流程。启动参数只允许预定义 locale，不接受任意字符串。

## 6. 首次扫描单飞与快速交付

### 6.1 明确区分“首次加载”和“手动刷新”

新增类型化的首次用量读取能力，例如 `getInitialUsage()`：

- 若启动扫描正在进行，返回同一个 Promise。
- 若启动扫描已经完成，直接返回内存中的最后成功结果。
- 若尚未开始或上次没有成功结果，触发一次扫描。

现有 `scan()` 保留“用户明确刷新”的语义，成功后必须执行新扫描。Renderer 首次挂载改用首次读取能力，刷新按钮继续调用 `scan()`。

这样不再依赖请求恰好重叠来避免重复扫描，并保持手动刷新可预测。

### 6.2 用量结果不等待派生分析

扫描阶段完成文件发现、文件指纹检查、必要解析和 `UsageSummary` 构建后，立即：

1. 更新 `UsageRuntime` 的最后成功结果。
2. 通知用量订阅者。
3. 解析首次读取或手动刷新 Promise。
4. 将本次 `UsageScanCycle` 送入后台分析队列。

概览只依赖步骤 1 至 3，不等待步骤 4。

### 6.3 后台分析顺序

后台队列继续保持现有业务顺序：

```text
UsageScanCycle
  → 预算按最新用量评估与通知
  → 成本优化同步最新预算上下文
  → 成本优化应用用量变更集
```

队列必须满足：

- 同一时间只处理一个 cycle，不能让后一次扫描越过前一次扫描。
- 单次后台分析失败不得把已经成功交付的用量结果改写成扫描失败。
- 预算失败时标记预算数据不可用或陈旧；成本失败时标记成本优化数据不可用或陈旧。
- 错误必须被观察和记录，不能产生未处理 Promise rejection。
- `stop()` 不再接收新任务，并清理订阅；已经开始的文件写入仍按原子写入约束安全结束。

工具栏的扫描中状态只表示用量扫描本身。预算或成本分析的后台状态由对应页面管理，不延长概览的扫描动画。

## 7. 持久化用量解析缓存

### 7.1 存储位置与内容

在 Electron `userData` 下新增版本化缓存文件，例如 `usage-scan-cache.json`。缓存不写入默认或用户选择的 Codex 会话目录。

缓存按来源文件保存：

- 规范化的来源文件路径。
- 由文件大小与修改时间组成的指纹。
- `parseSessionJsonl` 产生的已解析 `UsageSession`，但不固化会话索引中的线程名称。

线程名称继续在每次扫描时从 `session_index.jsonl` 读取并合并，因此名称变化不要求重新解析会话 JSONL。

缓存可能包含从本地会话派生出的项目路径、Token 用量、时间和会话结果，只能保存在本机应用数据目录，不得通过日志或网络导出。

### 7.2 启动与命中规则

扫描器创建时加载并校验缓存：

- schema 版本、数据目录或数据结构不匹配时丢弃缓存并正常全量扫描。
- 已发现文件的指纹与缓存一致时直接复用解析结果。
- 新增或修改文件才读取并解析。
- 已删除文件从下一版缓存移除。
- 数据目录切换时清空旧目录缓存并执行完整重建。
- 文件 stat 或读取出现短暂失败时遵循现有失败语义，不把旧缓存伪装成新鲜结果。

### 7.3 写入时机

首屏结果交付不等待缓存落盘。成功扫描生成下一版缓存快照，并通过独立单写队列原子保存：

- 临时文件写入完成后 rename 替换。
- 多次快速扫描只按顺序写入，较旧快照不得覆盖较新快照。
- 写入失败产生本地警告，但不使已经成功的扫描失败。
- 退出时不执行破坏性清理；不完整临时文件由下次写入或安全清理流程处理。

成本优化索引缓存与用量解析缓存暂时保持独立。合并两种缓存会扩大迁移与数据模型范围，不属于本次目标。

## 8. Renderer 首包与非首屏工作延迟

### 8.1 页面级代码拆分

应用外壳、标题栏、侧边栏、加载状态和 Overview 保持在首包中。以下页面组件通过 `React.lazy` 动态加载：

- 预算工作区。
- 成本优化工作区。
- 会话列表与诊断详情。
- 项目、性能和设置页面。

每个懒加载页面使用现有本地化加载状态作为 `Suspense` fallback。类型继续通过 type-only import 引用，避免重新引入运行时代码。

本次只拆分 JavaScript 页面代码；现有单一 CSS 入口继续保留，避免同时进行大范围样式依赖重组。

### 8.2 延迟非首屏请求

成本优化 Hook 增加显式 `enabled` 条件：

- 进入成本优化页或会话页时启用。
- 概览、预算、项目、性能和设置页不主动请求或订阅成本优化快照。
- 已加载快照在当前 Renderer 生命周期中保留，返回页面时不无条件清空。

数据目录设置只在首次进入设置页时读取，之后复用内存状态；更新与重置继续立即替换该状态。

预算和主题仍在启动时加载。预算提供概览价格，主题避免视觉闪烁，均属于首屏依赖。

## 9. IPC 与安全边界

本次新增或调整的 IPC 仍通过 shared channel 常量、preload 类型化 API 和 Renderer 全局类型声明维护：

- 新增首次用量读取通道，和显式刷新通道区分语义。
- 初始语言通过受控启动参数同步暴露，不向 Renderer 暴露 `process.argv`。
- 成本优化 IPC 通过运行时就绪屏障等待初始化。

Renderer 仍不直接访问文件系统。用量缓存加载与保存全部由主进程负责。真实会话目录始终只读，只允许发现、stat 和读取文件。

## 10. 错误与降级

- 持久化用量缓存缺失或损坏：忽略缓存并全量扫描，不阻止启动。
- 缓存保存失败：保留本次扫描结果，下次启动可能回退到全量解析，并通过现有警告机制提供可诊断信息。
- 成本优化初始化失败：概览和基础分析可用；成本优化页面显示错误，不返回未初始化的伪快照。
- 首次扫描失败且没有旧结果：保持现有完整错误状态和重试能力。
- 后续扫描失败：保持最后一次成功结果并显示旧数据提示。
- 后台预算或成本处理失败：不得把成功的用量扫描标记为失败；对应派生数据明确标记为 stale 或 error。
- 动态页面 chunk 加载失败：页面边界显示可重试错误，应用外壳和概览不崩溃。

## 11. 预计变更范围

### 主进程与共享边界

- `src/main/main.ts`：并行偏好读取、提前创建窗口、启动扫描与后台成本初始化。
- `src/main/applicationRuntime.ts`：初始化屏障和有序后台分析队列。
- `src/main/usageRuntime.ts`、`src/main/usageMonitor.ts`：首次结果复用与快速交付语义。
- `src/main/usageScanner.ts`：持久化缓存的水合、命中和快照输出。
- 新增主进程用量缓存 Store，并采用版本化、校验和原子写入。
- `src/main/ipc.ts`、`src/shared/ipcChannels.ts`、`src/preload/preload.ts`：首次用量读取和成本就绪屏障。
- `src/main/windowConfig.ts` 及共享 locale 定义：受控初始语言参数。

### Renderer

- `src/renderer/main.tsx`：同步读取初始语言并立即挂载。
- `src/renderer/App.tsx`：首次读取、非首屏请求启用条件和页面懒加载编排。
- `src/renderer/components/AppContent.tsx`：页面级 `Suspense` 边界。
- `src/renderer/hooks/useCostOptimizationSnapshot.ts`：按需启用并保留已加载状态。

### 测试与配置

- 运行时顺序、首次扫描单飞、缓存 Store、扫描缓存命中、IPC、preload、窗口参数、Renderer 请求和代码拆分测试。
- 不新增第三方依赖。

## 12. 实施与测试策略

设计确认后先编写中文实施计划，并按红—绿—重构拆分：

1. 用回归测试证明窗口初始化被成本缓存阻塞、扫描结果等待派生分析以及首次扫描可能重复的现状。
2. 实现启动屏障和首次用量读取语义，验证结果交付顺序。
3. 实现版本化用量缓存 Store，再接入扫描器，验证命中、修改、删除、目录切换、损坏和写入失败。
4. 实现同步初始语言、页面级代码拆分和非首屏请求延迟。
5. 使用仓库 fixture 或独立临时目录进行冷启动与缓存命中验证，不修改真实会话目录。

最小相关测试通过后，完成前运行：

```powershell
npm test
npm run typecheck
npm run lint
npm run build
```

本次会修改 Electron 主进程、preload、IPC 和构建输出，因此 `npm run build` 为必需门禁。生产构建后还需确认 Overview 保留在入口 chunk，非首屏页面生成独立 chunk。

## 13. 验收标准

- 成本优化配置与索引缓存尚未完成加载时，主窗口已经创建并开始加载 Renderer。
- Renderer 挂载不再等待 `locale.get()` IPC，初始语言仍正确且无未验证输入。
- 一次成功扫描结束后，首次用量 Promise 和订阅者先收到结果，预算与成本优化随后在有序后台队列中完成。
- 启动监控和 Renderer 首次读取无论是否时间重叠，都只触发一次首次扫描；刷新按钮仍始终请求新扫描。
- 第二次冷启动中，未变化的会话文件只执行发现与 stat，不重新读取或解析；新增、修改、删除和目录切换结果正确。
- 用量缓存只写入 Electron `userData`，真实会话目录保持只读，缓存损坏或保存失败不阻止用量浏览。
- 概览首次挂载不请求成本优化快照或数据目录设置；首次进入相关页面后能够正常加载。
- 生产构建将非首屏页面拆分为独立 JavaScript chunk，概览和应用外壳无需等待这些 chunk。
- 预算价格、未知模型未计价标记、费用本地估算说明、刷新错误和 stale 状态保持正确。
- 相同环境的开发计时显示窗口创建不再包含成本优化缓存校验阶段，有缓存冷启动不再包含全量 JSONL 解析阶段。
- 全量测试、类型检查、lint 和生产构建全部通过。
