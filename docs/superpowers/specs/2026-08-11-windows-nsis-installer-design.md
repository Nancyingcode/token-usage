# Windows 品牌化 NSIS 安装器设计

## 1. 背景

项目当前通过 `npm run build:win` 先生成 Electron/Vite 产物，再执行
`electron-builder --win`。仓库尚未声明稳定的 Windows 应用标识、产品显示名称、目标架构、
安装模式、升级标识、安装器图标和向导资源，因此实际使用 electron-builder 的 Windows 默认
NSIS 目标和默认一键安装体验。

本次采用已确认的方案 A：保留 electron-builder 与 NSIS，在现有构建链上增加品牌化的传统
安装向导、稳定升级边界和可验证的 Windows 安装产物。该方案面向从 GitHub Release 或其他
下载页直接获取安装包的普通 Windows 用户。

## 2. 目标

1. 将默认一键安装器改为中英文品牌化 NSIS 安装向导。
2. 让用户能够选择当前用户或所有用户安装，并允许修改安装目录。
3. 明确开始菜单、桌面快捷方式和安装完成后启动应用的行为。
4. 固定应用 ID、安装器 GUID、可执行文件名和产物命名，保证后续版本能够原位升级。
5. 在产品显示名称变化后继续使用现有 Electron `userData` 目录，保留用户配置和缓存。
6. 保证安装、升级和卸载过程不读取、复制、写入或删除 Codex 会话数据源。
7. 为以后接入 Windows 代码签名和自动更新保留稳定基础，但不在本次引入自动更新。
8. 提供自动化配置检查、完整构建验证和可重复的 Windows 安装/卸载验收步骤。

## 3. 非目标

- 不切换到 MSI、MSIX、Squirrel.Windows、WiX Burn 或自研安装器框架。
- 不实现在线安装器、差分下载或应用内自动更新。
- 不发布 Microsoft Store 包，不增加 ARM64、x86 或便携版产物。
- 不安装驱动、Windows 服务、运行库或其他第三方前置组件。
- 不在安装器中选择或扫描 Codex 会话目录；数据源仍由应用设置页管理。
- 不在没有经过确认的法律文本时增加许可协议或隐私政策确认页。
- 不把签名证书、密码、令牌或其他发布凭据写入仓库。
- 不删除现有用户配置、可重建缓存或只读会话数据。

## 4. 安装产物与应用身份

### 4.1 产品身份

Windows 包使用以下稳定身份：

- npm 包名：保留 `codex-token-usage`。
- 产品显示名称：`Codex Token Usage`。
- 应用 ID：`io.github.nancyingcode.tokenusage`。
- 可执行文件名：`CodexTokenUsage.exe`。
- 开始菜单与桌面显示名称：`Codex Token Usage`。

应用 ID 一旦随正式安装包发布，不再因品牌文案或仓库名称变化而修改。NSIS 安装器使用显式、
固定的 GUID；该 GUID 在首次发布前生成并写入配置，后续版本永久复用，避免升级时产生并列安装。

### 4.2 平台与命名

第一阶段只生成 Windows x64 NSIS 安装包：

```text
dist/Codex-Token-Usage-Setup-<version>-x64.exe
```

构建命令显式指定 NSIS 和 x64，避免开发机器架构或 electron-builder 默认值改变发布结果。
`dist/` 继续作为忽略的生成目录，不提交安装产物。

## 5. 安装向导体验

### 5.1 语言

安装器只包含英文和简体中文，默认按照 Windows 系统语言选择；不额外显示启动前语言选择框。
安装器语言与应用内部保存的语言偏好相互独立，升级安装不得覆盖应用语言设置。

### 5.2 页面顺序

安装器使用辅助安装模式，页面顺序为：

1. 品牌化欢迎页。
2. 安装范围页：当前用户或所有用户。
3. 安装目录页。
4. 快捷方式选项页。
5. 安装进度页。
6. 完成页。

当前用户安装作为普通用户路径，不要求管理员权限；选择所有用户安装时由 Windows 触发提权。
安装目录默认值由 NSIS 根据安装范围决定，用户可以修改。

仓库目前没有经过确认的 EULA 或许可协议文件，因此第一阶段不显示许可协议页。未来若需要该页，
必须先由用户提供或确认对应中英文法律文本，不能由实现自行编写。

### 5.3 快捷方式与完成行为

- 开始菜单快捷方式默认创建并保持启用。
- 桌面快捷方式默认勾选，用户可以在向导中取消。
- 完成页默认勾选“运行 Codex Token Usage”，用户可以取消。
- 快捷方式全部指向稳定的 `CodexTokenUsage.exe`，升级时复用而不是重复创建不同名称。

桌面快捷方式选择通过受限的 NSIS include 宏实现，不替换 electron-builder 维护的完整 NSIS
脚本。自定义脚本只负责页面和选项接入，不复制安装、升级、卸载或签名校验主体逻辑。

## 6. 品牌资源

在 `build/` 中维护 electron-builder 专用资源，包括应用 ICO、安装器/卸载器图标、向导侧边图、
顶部图和受限的 `installer.nsh`。

第一版视觉遵循现有应用的品牌色和数据分析语言，使用中性的 Token/趋势图形，不使用 OpenAI
旋涡标志或其他可能暗示官方出品的商标。资源在 Windows 100%、150% 和 200% 缩放下保持清晰，
文字由 NSIS 原生控件渲染，不烘焙进位图，以免语言切换和高对比度模式失效。

若实施前没有提供独立品牌资产，则按上述约束创建简洁的项目图标和安装器背景；这组资产视为
项目自身视觉，不声称与 OpenAI 或 Codex 官方品牌存在从属关系。

## 7. 用户数据与只读数据源边界

### 7.1 稳定的 `userData` 路径

应用当前直接使用 `app.getPath('userData')` 保存以下文件：

- `budget-config.json`
- `cost-optimization-config.json`
- `cost-optimization-cache.json`
- `locale-preferences.json`
- `theme-preferences.json`
- `usage-data-path.json`

设置 `productName` 可能改变 Electron 推导出的默认目录名。为兼容现有开发包和已经手工生成的
安装包，主进程在读取任何配置之前，将 `userData` 显式固定为：

```text
%APPDATA%/codex-token-usage
```

路径解析封装为可单元测试的纯函数；主进程只负责在初始化早期调用 `app.setPath`。不执行目录
搬迁，不复制文件，也不创建第二份配置。这样新品牌名称只影响显示，不改变持久化所有权。

### 7.2 Codex 会话数据源

安装器和卸载器不得对默认或自定义 Codex 会话目录执行读取、遍历、监听、写入、重命名、删除、
权限修改或网络上传。应用运行后的扫描仍遵循现有只读边界，本次不修改扫描器或 IPC 契约。

自动化与手工安装验证只使用仓库 fixture 或独立临时目录，不使用真实 Codex 会话目录。

## 8. 升级、重装与卸载

### 8.1 升级和重装

- 相同应用 ID、NSIS GUID 和可执行文件名用于识别已有安装。
- 新版本原位替换应用二进制和安装器管理的快捷方式。
- 升级前如应用正在运行，使用 electron-builder/NSIS 的标准关闭与重启处理，不自定义终止逻辑。
- 升级和重装保留整个稳定 `userData` 目录，不重置配置、语言、主题或数据源路径。
- 安装器版本来自 `package.json`，不另设可能漂移的第二版本号。

### 8.2 卸载

卸载器删除应用二进制、开始菜单项、桌面快捷方式和安装器自身管理的注册信息，但保留
`%APPDATA%/codex-token-usage`。第一阶段不提供“删除个人数据”选项，避免把可重建缓存和用户
配置与只读会话源混淆。

无论应用数据是否保留，卸载器都不得访问或删除 `%USERPROFILE%/.codex` 或用户选择的任何
会话数据源。README 将明确说明卸载后配置仍会保留，以及用户需要手动删除配置目录时的准确
范围；该说明不得把 Codex 会话目录列为清理目标。

## 9. 代码签名与发布边界

本次配置允许 electron-builder 从发布环境注入 Windows 代码签名凭据，但本地开发构建在没有
证书时仍可生成未签名安装包。仓库、测试日志和构建产物不得包含证书私钥或密码。

验收必须明确区分：

- 未签名本地安装包：用于构建和安装流程验证，Windows 可能显示未知发布者或 SmartScreen
  提示。
- 正式发布安装包：发布前必须使用可信证书和时间戳服务签名，并验证 EXE 与卸载器签名。

没有可用发布证书时，可以完成安装器实现和本地验证，但不得声称已完成可信发布签名。

## 10. 配置与文件组织

预计新增或修改：

- `electron-builder.yml`：集中维护产品身份、Windows x64 NSIS 目标、产物名和安装选项。
- `package.json`：让 `build:win` 显式使用受控配置和目标架构。
- `build/icon.ico`：应用、可执行文件和快捷方式图标。
- `build/installer-sidebar.bmp`、`build/installer-header.bmp`：安装器品牌图。
- `build/installer.nsh`：欢迎页和快捷方式选项所需的受限扩展宏。
- `src/main/appPaths.ts`：解析稳定 `userData` 路径的纯函数。
- `src/main/main.ts`：在配置存储初始化前设置稳定路径。
- `tests/appPaths.test.ts`：保护路径兼容行为。
- `tests/packagingConfig.test.ts`：保护关键安装器身份和安全不变量。
- `README.md`：更新产物名、安装/卸载、签名状态和数据保留说明。

如果实现过程中发现标准 assisted NSIS 已经提供满足需求的快捷方式选项，则优先删除对应
自定义宏，只保留必要扩展，降低脚本维护范围。

## 11. 测试与验证策略

### 11.1 自动化测试

行为代码按红—绿—重构执行：

1. 先为稳定 `userData` 路径添加失败测试，再实现纯路径解析和主进程接入。
2. 添加安装配置测试，验证稳定应用 ID、显式 NSIS x64 目标、辅助安装模式、可修改安装目录、
   固定 GUID、稳定产物名以及保留应用数据。
3. 配置测试同时约束安装器脚本不得引用 `.codex`、`sessions` 或会话索引路径。
4. 更新文档检查，确保新增说明为 UTF-8、代码围栏闭合且本地链接有效。

最终至少运行：

```powershell
npm test
npm run typecheck
npm run lint
npm run build
npm run build:win
```

由于本次修改构建配置、Electron 主进程和打包配置，`npm run build` 与实际 Windows 安装包
构建均为必需验证项。

### 11.2 手工安装验收

安装器 UI、UAC、快捷方式和卸载行为无法通过现有 Vitest 环境稳定完整复现，因此在 Windows
Sandbox、测试虚拟机或隔离的测试用户中记录并执行以下步骤：

1. 以当前用户安装到默认目录，验证无 UAC、中文/英文自动选择、快捷方式选项和完成后启动。
2. 以当前用户安装到自定义目录，验证应用能够启动且开始菜单/桌面入口正确。
3. 选择所有用户安装，验证只在该路径触发 UAC，取消 UAC 后安装安全中止。
4. 在独立临时目录准备会话 fixture，记录文件哈希，让应用选择该目录后重装和卸载，再确认哈希
   与权限均未变化。
5. 在稳定 `userData` 目录写入或通过应用生成语言、主题、预算和自定义数据路径配置，执行重装
   与卸载，确认文件仍存在且重新安装后能够继续读取。
6. 验证卸载器移除应用二进制和安装器管理的快捷方式，但不删除稳定 `userData` 或 fixture。
7. 在 100%、150% 和 200% 显示缩放下检查图标、侧边图、标题和按钮没有裁切或模糊到不可辨认。
8. 对未签名构建如实记录 Windows 警告；取得证书后再补充 Authenticode 与时间戳验证。

真正的跨版本原位升级需要两个不同版本的安装包。首次实现先由固定 ID、GUID 和配置测试保护，
产生后续版本时再使用“旧版本安装—写入配置—安装新版本—验证配置与单实例”的步骤完成发布
前升级验收。

## 12. 风险与控制

- **产品名导致配置丢失假象**：在主进程初始化前固定兼容的 `userData` 路径。
- **修改应用 ID 或 GUID 产生并列安装**：使用显式常量和配置测试，正式发布后禁止修改。
- **自定义 NSIS 脚本偏离上游**：只使用 include 宏，不替换完整脚本，并限制到页面级扩展。
- **所有用户安装扩大权限**：默认走当前用户路径，只在用户主动选择时触发 UAC。
- **卸载误删数据**：不自动删除应用数据，不在安装器脚本中引用任何 Codex 会话路径。
- **品牌误导**：不使用 OpenAI 标志，不声称官方出品，在应用说明中保持第三方本地工具定位。
- **未签名包触发安全警告**：本地测试允许未签名，正式发布必须单独完成可信签名验收。
- **位图在高 DPI 下失真**：按 NSIS 资源规格生成多尺寸图标，并在三档 Windows 缩放下验收。

## 13. 验收标准

- `npm run build:win` 稳定生成命名为
  `Codex-Token-Usage-Setup-<version>-x64.exe` 的 NSIS 安装包。
- 安装向导支持英文和简体中文、当前用户/所有用户、安装目录、快捷方式和完成后启动选择。
- 普通当前用户安装不要求管理员权限，所有用户安装正确触发 UAC。
- 安装后的应用、快捷方式和 Windows 应用列表均显示 `Codex Token Usage`。
- 升级身份由稳定应用 ID 和固定 NSIS GUID 保护，不产生另一个产品条目。
- 产品显示名称变化后，应用仍读取 `%APPDATA%/codex-token-usage` 中的现有配置。
- 安装、重装和卸载均不改变测试会话 fixture 的内容、权限或路径。
- 卸载移除程序文件和快捷方式，但保留应用配置与缓存。
- 图标和向导资源在常用 Windows 显示缩放下可辨认且无明显裁切。
- README 准确描述产物、安装范围、卸载数据保留和未签名/正式签名边界。
- 全量测试、类型检查、lint、应用构建和 Windows 安装包构建全部通过；任何未完成的签名验证
  必须作为发布阻塞项单独列出。

## 14. 待确认假设

本设计按以下假设进入实施计划：

1. 第一阶段只发布 Windows x64 安装包。
2. 产品显示名称使用 `Codex Token Usage`，应用 ID 使用
   `io.github.nancyingcode.tokenusage`。
3. 安装器创建开始菜单入口；桌面快捷方式默认勾选但可取消。
4. 仓库没有已确认 EULA，因此不显示许可协议页。
5. 没有外部品牌资产时，创建不含 OpenAI 标志的中性 Token 分析图标。
6. 没有代码签名证书时先完成未签名本地安装验证，正式发布仍以可信签名为前置条件。
