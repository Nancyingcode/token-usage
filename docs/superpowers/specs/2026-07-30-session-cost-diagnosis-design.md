# 会话高消耗诊断设计

## 1. 背景

当前应用已经能够展示会话、项目、模型和日期维度的 Token 与本地费用估算，并提供异常检测、趋势预测和节省建议。现有能力可以回答“哪里消耗较高”或“哪里偏离历史水平”，但不能稳定回答“某个会话为什么消耗高”。

本功能在现有成本优化工作台中增加一个可解释的会话诊断闭环：

1. 自动找出当前范围内影响较高的会话。
2. 使用本地元数据识别可能的消耗原因。
3. 展示结论对应的原始指标、历史基线、样本量和时间范围。
4. 允许从会话列表直接进入同一个诊断详情。

## 2. 目标

- 自动排列当前周期和项目范围内的高影响会话。
- 首版识别以下五类原因：
  - 输入 Token 足迹持续放大。
  - 缓存复用信号偏低或中途下降。
  - 输出或推理 Token 占比异常。
  - 高单位成本模型主导费用，或模型切换后单位成本明显上升。
  - 用量事件次数或持续时间异常，形成累积消耗。
- 每条发现都提供严重程度、置信度和结构化证据。
- 历史或定价不足时安全降级，不强行生成结论。
- 继续遵守本地、只读和费用仅为估算的产品边界。

## 3. 非目标

首版不包含：

- 读取或分析提示词、回复正文、工具参数或任务语义。
- 使用 LLM 猜测失败原因。
- 修改、删除或上传 Codex 会话数据。
- 自动执行模型替换、缓存优化或其他建议。
- 将重叠原因换算或累加为节省金额。
- 为每个检测器提供高级阈值设置界面。
- 报告导出、团队共享或跨设备同步。
- 将本地估算描述为 OpenAI 实际账单。
- 虚拟列表、分页或新的图表依赖。

## 4. 隐私与数据边界

诊断只使用应用已经解析的元数据：

- Token 用量切片及其时间。
- 输入、缓存输入、输出、推理输出和总 Token。
- 模型标识和模型切换。
- 会话开始与结束时间。
- 用量事件数。
- 项目路径、会话 ID 和会话显示名称。
- 本地模型价格覆盖。

功能不得读取或向 Renderer 暴露会话正文。Codex 会话目录始终只读，诊断结果不得写回会话文件。

## 5. 用户流程

### 5.1 成本优化入口

在“成本优化”工作台增加“会话诊断”标签。

“异常消耗”和“会话诊断”的职责不同：

- 异常消耗回答“哪里偏离了历史水平”。
- 会话诊断回答“这个会话为什么消耗高”。

诊断列表沿用全局周期和成本优化项目筛选。默认显示“需要关注”，用户可以切换到“全部会话”，并按主要原因、严重程度和置信度筛选。

### 5.2 诊断列表

每行显示：

- 会话名称或短 ID。
- 项目。
- 开始时间。
- Token 总量。
- 已计价费用及定价覆盖率；只有覆盖率为 100% 时才称为完整费用估算。
- 相对历史基线。
- 主要原因。
- 其他发现数量。
- 严重程度和置信度。

默认排序顺序为：

1. 是否需要关注。
2. 严重程度。
3. 影响度。
4. 开始时间倒序。
5. 稳定诊断 ID。

### 5.3 会话详情

点击列表行后，在当前标签内进入完整详情页。返回列表时保留筛选条件和滚动位置。

详情采用已确认的“原因优先”布局：

1. 会话身份和返回入口。
2. Token、已计价费用、定价覆盖率、相对基线和用量事件数。
3. 主要原因、结论摘要和三个关键证据。
4. 共享时间轴上的分轨证据图。
5. 其他发现。
6. 五个检测器的完整状态和计算依据。

时间线不得把百分比和 Token 放在同一个纵轴：

- Token 轨道显示输入、输出和推理消耗。
- 缓存轨道单独显示缓存率。
- 两条轨道共享时间轴。

### 5.4 Sessions 入口

Sessions 页面为已经获得主要诊断结论的会话显示原因徽标。徽标同时包含文字，不以颜色作为唯一信息。

点击徽标时：

1. 将成本优化项目筛选切换为该会话的项目。
2. 将成本优化标签切换为“会话诊断”。
3. 打开该会话的同一个诊断详情。

## 6. 导航与 Renderer 状态

跨页面导航需要由 `App` 管理以下状态：

- 当前顶层视图。
- 当前成本优化标签。
- 当前诊断会话 ID。

`CostOptimizationView` 的活动标签从内部状态改为受控状态，避免通过副作用同步跨页面请求。

从诊断列表打开详情只改变当前诊断会话。返回操作清除当前诊断会话，但保留成本优化标签、项目筛选和全局周期。

Sessions 的原因徽标需要当前周期的全局诊断摘要，不得依赖成本优化页面可能存在的项目筛选。`useCostOptimizationSnapshot` 因此维护：

- 当前成本优化查询快照。
- 同一周期、不带项目筛选的全局诊断摘要快照。

当当前成本优化查询本身没有项目筛选时，两者复用同一快照，不发起重复查询。运行时已经支持多个活动查询；本功能复用该能力，不在 Renderer 重新计算诊断结果。

## 7. 索引与缓存模型

### 7.1 索引扩展

`IndexedUsageSource` 在现有 `fingerprint` 和 `contributions` 之外保存最小会话元数据：

- `sessionId`
- `threadName`
- `startedAt`
- `endedAt`
- `projectPath`
- `projectName`
- `eventCount`
- `sourceFile`

这些字段来自已经完成的会话解析，不触发第二次文件读取。

### 7.2 Schema 升级

`CostOptimizationIndex.schemaVersion` 从 1 升级为 2。缓存加载器发现旧版本时：

1. 不尝试猜测或补齐缺失元数据。
2. 将旧缓存视为不兼容。
3. 从当前只读会话扫描结果安全重建索引。
4. 保留明确但非阻塞的缓存重建说明。

成本优化缓存始终是可安全重建的数据，不影响 Codex 会话文件。

## 8. 领域模型

新增诊断专用类型，不复用节省建议的置信度类型：

- `SessionDiagnosisCause`
  - `input-growth`
  - `cache-degradation`
  - `generation-concentration`
  - `model-cost-dominance`
  - `interaction-accumulation`
- `SessionDiagnosisSeverity`
  - `warning`
  - `critical`
- `SessionDiagnosisConfidence`
  - `low`
  - `medium`
  - `high`
- `SessionDetectorState`
  - `finding`
  - `not-found`
  - `insufficient-data`
  - `not-applicable`

`SessionDiagnosisSummary` 用于列表和 Sessions 徽标，包含：

- 稳定诊断 ID、会话 ID、来源文件和显示信息。
- Token、已计价费用和定价覆盖。
- 影响度和候选原因。
- 相对基线、基线范围和样本数。
- 主要发现与其他发现数量。

稳定诊断 ID 由来源文件和会话 ID 通过共享分隔符组合。它只用于进程内查找和类型化 IPC，不作为用户可见文案；仅使用会话 ID 不足以区分异常或重复来源。

`SessionDiagnosisDetail` 在摘要基础上增加：

- 五个检测器的完整结果。
- 类型化证据。
- 按时间排序的图表数据。
- 数据完整性说明。

共享层只返回原始值、枚举和 i18n key，不生成最终显示文案。

## 9. 诊断计算架构

诊断实现为共享层纯函数，并按以下边界拆分：

1. `buildSessionObservations`
   - 从索引来源构建会话级观测。
2. `selectDiagnosisCandidates`
   - 计算影响度、候选状态和稳定排序。
3. `resolveDiagnosisBaseline`
   - 根据检测器选择历史样本和回退范围。
4. 五个独立检测器
   - 每个检测器只处理一个原因。
5. `summarizeSessionDiagnosis`
   - 选择主要原因并生成轻量摘要。

`costOptimizationRuntime` 负责组合索引、查询、设置和价格，不包含具体诊断公式。

成本优化快照增加轻量 `diagnostics` 摘要列表。完整详情通过同一成本优化命名空间下的类型化 IPC 按需获取，避免把所有会话的完整时间线重复发送给 Renderer。

运行时可以维护与快照版本绑定的内存详情映射。扫描、价格、设置、周期或项目查询变化时，旧映射失效；诊断结果不单独持久化。

## 10. 第一阶段：高影响会话选择

### 10.1 查询范围

候选选择只对当前 `CostOptimizationQuery` 周期和项目范围内的会话生成列表。历史基线可以读取查询周期之前的索引数据，但不得读取当前会话之后的数据。

### 10.2 影响度

每个会话始终计算 Token 百分位。

当该会话的定价覆盖达到现有 `minimumPricingCoveragePercentage` 时，同时在同样达到安全覆盖阈值的会话集合中计算已计价费用百分位。影响度取可用百分位的最大值：

```text
impactPercentile = max(tokenPercentile, safeCostPercentile?)
```

百分位使用稳定的中秩经验排名。范围内只有一个观测时，百分位为 1；否则：

```text
percentile = (strictlyLowerCount + (equalCount - 1) / 2) / (observationCount - 1)
```

结果限制在 `[0, 1]`。因此并列值共享同一百分位，不会因输入顺序得到不同结果。

### 10.3 默认关注条件

满足任一条件的会话进入默认“需要关注”列表：

- 现有异常检测已经为该会话生成 session 级异常。
- `impactPercentile` 达到具名常量 `HIGH_IMPACT_PERCENTILE = 0.8`。

未满足条件的会话仍保留在“全部会话”中。

定价覆盖低于安全阈值时，该会话只使用 Token 百分位并显示定价不完整状态。达到安全阈值但未达到 100% 时，界面必须把数值标为“已计价费用”并同时显示覆盖率，不得暗示它是完整费用。

## 11. 历史基线

### 11.1 通用规则

- 只使用发生在当前会话之前的历史观测。
- 使用现有 `anomalyHistoryWindow` 限制最近样本数。
- 使用现有 `anomalyMinimumSamples` 判断历史是否充足。
- 复用当前异常检测的中位数、MAD 和零 MAD 安全尺度。
- warning 阈值使用现有 `anomalySensitivity`。
- critical 阈值为 warning 阈值的两倍。

“主要模型”定义为会话内贡献总 Token 最多的模型。总 Token 相同时，使用规范化模型 ID 的字典序打破并列；未知模型使用稳定的未知模型键。

### 11.2 检测器回退范围

不同检测器使用适合自身的基线：

- 输入增长：
  - 同项目同主要模型。
  - 同主要模型。
  - 全局。
- 缓存复用：
  - 同项目同主要模型。
  - 同主要模型。
  - 同项目。
  - 全局。
- 输出或推理占比：
  - 同项目同主要模型。
  - 同主要模型。
  - 全局。
- 模型成本：
  - 使用当前价格表和会话内模型贡献，不要求历史基线。
- 交互累积：
  - 同项目。
  - 全局。

如果所有范围都不满足最小样本数，依赖历史的检测器返回 `insufficient-data`，不得把全局固定阈值伪装成历史异常。

## 12. 五类原因检测

所有内部阈值必须使用靠近检测器的具名常量，不进入全局常量文件。首版不把这些阈值暴露为用户设置。

### 12.1 输入 Token 足迹持续放大

前置条件：

- 至少有 `MIN_INPUT_GROWTH_SLICES = 3` 个时间有效的用量切片。

计算：

1. 按时间稳定排序切片。
2. 将切片等分为前、中、后三段；不能整除时多余切片优先放入中段。
3. 计算前段和后段输入 Token 中位数。
4. 计算增长倍数和绝对增长量。
5. 与历史会话的增长倍数及绝对增长量比较。

历史充足时，增长倍数和绝对增长量都达到正向异常阈值才生成 finding。

历史不足时仅在以下两个保守条件同时满足时生成低置信度 finding：

- 后段中位数至少是前段的 `INPUT_GROWTH_FALLBACK_RATIO = 2` 倍。
- 绝对增长至少达到 `INPUT_GROWTH_FALLBACK_MIN_TOKENS = 8192`。

增长倍数达到 `INPUT_GROWTH_CRITICAL_RATIO = 4` 且绝对增长达到 warning 条件时可升级为 critical。

文案描述“输入 Token 足迹放大”，不得声称已读取或理解上下文内容。

### 12.2 缓存复用信号偏低或下降

前置条件：

- 输入 Token 大于 0。
- 缓存输入 Token 能够安全限制在输入 Token 范围内。

计算：

- 整体缓存率：将缓存输入限制在 `[0, inputTokens]` 后除以输入 Token。
- 前半段和后半段缓存率。
- 与历史缓存率的负向稳健偏差。
- 与现有 `targetCachePercentage` 的差距。

生成 finding 的条件为以下任一项：

- 历史充足且缓存率达到负向异常阈值。
- 当前缓存率低于目标至少 `CACHE_TARGET_GAP_POINTS = 10` 个百分点。
- 后半段低于前半段至少 `CACHE_DECLINE_POINTS = 15` 个百分点。

目标差距达到 `CACHE_CRITICAL_GAP_POINTS = 30`，或历史负向分数达到 critical 阈值时，严重程度为 critical。

由于元数据不能证明请求一定具备缓存资格，该原因的置信度最高为 medium。文案使用“缓存复用信号”，不得断言缓存系统失效。

### 12.3 输出或推理 Token 占比异常

分别计算：

- 输出 Token 占总 Token 的比例。
- 推理输出 Token 占总 Token 的比例。

只有历史充足时才进行异常判断。输出和推理分别与相同模型优先的历史比例比较。达到正向异常阈值的指标生成一个 `generation-concentration` finding，并在 subtype 中标明：

- `output`
- `reasoning`
- `both`

严重程度取两个指标中的较高等级，证据同时保留两个比例，避免因 subtype 隐藏另一项数据。

### 12.4 模型成本主导或切换后上升

前置条件：

- 会话定价覆盖达到现有安全阈值。
- 所有参与判断的模型都存在明确价格。

计算：

- 每个模型的会话费用贡献。
- 每个模型基于该会话实际输入、缓存和输出组合得到的有效单位成本。
- 模型切换前后贡献的有效单位成本。

“当前价格表中位有效单位成本”使用同一会话的实际普通输入、缓存输入和输出比例，分别套用每个已计价模型的价格后计算，再取中位数。不得直接平均输入价、缓存价和输出价，也不得假设三类 Token 占比相同。

满足任一条件时生成 finding：

- 单一模型贡献至少 `DOMINANT_MODEL_COST_SHARE = 0.5` 的会话费用，且其有效单位成本至少为当前价格表中位有效单位成本的 `HIGH_UNIT_COST_RATIO = 1.5` 倍。
- 模型切换后的有效单位成本至少为切换前的 `MODEL_SWITCH_COST_RATIO = 1.5` 倍，且切换后贡献至少 `MODEL_SWITCH_MIN_COST_SHARE = 0.2` 的会话费用。

该结论只解释费用构成，不表示模型质量、速度或能力等价，也不自动建议替换模型。

价格不完整时返回 `not-applicable`，并保留未计价 Token 和模型列表。

### 12.5 交互累积消耗

观测值：

- 用量切片数量。
- 会话持续时间。
- 最大单个切片占会话总 Token 的比例。

用量切片数或持续时间达到历史正向异常阈值，且最大切片占比不高于 `SINGLE_SPIKE_MAX_SHARE = 0.5` 时，生成 `interaction-accumulation` finding。

如果最大切片占比超过该阈值，则该会话更接近单次突增，不归因为累积交互。界面使用“用量事件”而非“对话轮数”，因为 `token_count` 事件不保证与用户轮次一一对应。

时间戳无效时仍可使用切片数量；持续时间证据标记为不可用。

## 13. 严重程度、置信度与主要原因

### 13.1 严重程度

- `warning`：达到检测器 warning 条件。
- `critical`：达到检测器 critical 条件。

严重程度表达观测偏离强度，不表达结论可信度。

### 13.2 置信度

- `high`
  - 历史样本充足。
  - 数据完整。
  - 检测器不存在额外可解释性限制。
- `medium`
  - 使用可靠的会话内证据或完整价格，但没有完整历史基线。
  - 缓存原因即使历史充足也最高为 medium。
- `low`
  - 仅满足保守回退条件，或可用切片接近最低要求。

数据不足且不满足回退条件时返回 `insufficient-data`，不生成低置信度 finding。

### 13.3 主要原因

主要原因从 finding 中按以下顺序确定：

1. critical 优先于 warning。
2. 标准化证据分数较高者优先。
3. 置信度 high、medium、low。
4. 固定原因顺序：
   - 输入增长。
   - 缓存下降。
   - 输出或推理集中。
   - 模型成本。
   - 交互累积。

标准化证据分数由各检测器返回，必须是有限且限制在 `[0, 1]` 的数值。它只用于同一会话内排序，不显示为节省比例，也不跨原因相加。

如果高影响会话没有 finding，摘要显示“未能从现有元数据定位原因”，并允许查看五个检测器的状态。

## 14. 详情图表

详情时间线由后端返回已经按时间排序的结构化点：

- 时间。
- 输入 Token。
- 缓存输入 Token。
- 输出 Token。
- 推理输出 Token。
- 总 Token。
- 模型 ID。

Renderer 负责：

- 按共享时间轴绘制 Token 与缓存率分轨图。
- 本地化数字、百分比和时间。
- hover 与键盘聚焦提示。
- 在模型切换位置显示带文字的标记。

Renderer 不重新判定原因、严重程度或置信度。

无效时间点不进入时间线，但其 Token 仍保留在会话汇总和非时间型检测中。界面显示被跳过的数据点数量。

## 15. 错误与降级状态

### 15.1 定价不完整

- Token、缓存、输入增长、输出/推理和累积检测继续运行。
- 不显示完整费用或费用百分位。
- 模型成本检测返回 `not-applicable`。
- 显示未计价 Token 和模型，不猜测价格。

### 15.2 历史不足

- 依赖历史的检测器返回 `insufficient-data`。
- 允许输入增长和缓存检测使用明确的保守回退条件。
- 相对基线不显示虚假数值。

### 15.3 时间数据损坏

- 跳过无效时间点。
- 依赖持续时间或时间顺序的证据降级。
- 不影响仍可从总量得到的检测结果。

### 15.4 刷新失败

- 复用现有 stale 横幅。
- 保留最后一次成功快照和诊断结果。
- 不把旧结果标记为 fresh。

### 15.5 会话消失

如果用户打开详情后，会话在下一次成功扫描中消失：

- 返回诊断列表。
- 保留周期、项目和筛选条件。
- 显示会话已不在当前数据中的说明。
- 不自动选择其他会话。

### 15.6 空状态

- 当前周期没有会话：沿用现有周期空状态。
- 有会话但没有需要关注项：显示成功型空状态，并提供“查看全部会话”。
- 高影响会话没有可证明原因：显示明确的未定位状态，而不是空白或强制原因。

## 16. 国际化与可访问性

- 所有新增用户可见文案同时维护英文和简体中文。
- React 组件不得硬编码用户可见文案。
- 金额、百分比、数字和时间使用现有 locale formatter。
- 原因、严重程度、置信度和检测器状态都同时使用文字与视觉标记。
- 列表行、筛选器、返回操作、原因徽标和展开控件支持键盘操作。
- 图表提供可访问名称、摘要和键盘可聚焦数据点。
- hover 信息也必须能通过键盘获得。
- 不使用颜色作为状态、原因或置信度的唯一表达方式。

## 17. 性能与增量行为

- 不增加第二次磁盘扫描。
- 未变化 JSONL 不重新读取或解析。
- 单文件变化只更新该来源及受影响的聚合桶。
- 价格或分析设置变化只重新评估诊断，不重建 Token 索引。
- 完整时间线按需通过 IPC 获取，不在列表快照中复制所有切片。
- 诊断计算可以重新评估当前查询范围内的会话和历史基线，但不得重新解析未变化文件。
- 性能测试验证读取、解析、索引和评估次数，不使用易受机器影响的固定毫秒阈值。

首版不增加分页或虚拟列表。只有真实数据规模证明 Renderer 列表成为瓶颈时，再单独设计。

## 18. 测试策略

### 18.1 纯函数单元测试

- 会话观测构建不修改索引输入。
- Token 与安全费用百分位正确、稳定并处理并列值。
- 单会话范围的百分位为 1。
- 高影响候选和现有 session 异常都进入默认列表。
- 定价不足时只按 Token 排名。
- 历史只使用当前会话之前的数据。
- 每个检测器按规定范围回退。
- 五个检测器覆盖正常、warning、critical、数据不足、不适用和异常输入。
- 缓存 finding 的置信度不会超过 medium。
- 输出与推理 subtype 正确。
- 单次突增不会被归类为交互累积。
- 主原因选择和并列排序稳定。
- 标准化证据分数限制在 `[0, 1]`。

### 18.2 索引与缓存测试

- 新索引保存最小会话元数据。
- 新增、修改和删除来源正确更新诊断输入。
- 旧 schema 缓存安全失效并重建。
- 缓存损坏保留现有安全恢复行为。
- 未变化文件不重新读取或解析。

### 18.3 运行时与 IPC 测试

- 当前项目查询和全局诊断查询相互独立。
- 周期、项目、价格和设置变化使对应诊断失效并重新评估。
- 价格变化不重建 Token 索引。
- 详情 IPC 只返回请求的会话。
- 不存在或已删除的会话返回类型化 not-found 结果。
- stale 状态保留最后成功结果。
- preload API 和 IPC channel 完整卸载。

### 18.4 React 测试

- 新标签和诊断列表渲染。
- “需要关注”与“全部会话”切换。
- 原因、严重程度和置信度筛选。
- 原因优先详情布局。
- 返回后保留筛选和滚动位置。
- Sessions 原因徽标跨页面导航。
- 定价不足、历史不足、时间损坏、stale、会话消失和空状态。
- 英文与简体中文文案。
- 键盘语义、可访问名称和非颜色状态表达。

## 20. 验收标准

- 用户能在当前周期和项目范围内看到自动排列的高影响会话。
- 用户能查看所有会话，不因候选筛选丢失数据。
- 每条 finding 都包含严重程度、置信度和可核验的结构化证据。
- 详情首屏优先展示主原因，时间线用于验证而不是替代解释。
- 五个检测器均明确显示 finding、未发现、数据不足或不适用。
- 定价不足时不显示伪造费用或模型成本结论。
- 历史不足时不显示伪造基线。
- 用户能从 Sessions 原因徽标进入同一详情，并可靠返回。
- 诊断不读取正文、不修改会话、不上传数据。
- 未变化文件不重新解析；价格和设置变化不重建 Token 索引。
- 新界面支持英文、简体中文、键盘操作和非颜色状态表达。
- 完整测试、类型检查、lint 和生产构建全部通过。
