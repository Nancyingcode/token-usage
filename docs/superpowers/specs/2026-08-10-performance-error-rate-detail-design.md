# 性能页错误率详情设计

## 1. 背景与问题

当前“性能”页的“错误率”卡片并没有读取真实错误数据，而是固定展示 `0.00% (0/会话数)`。这会产生三个问题：

1. 即使 Codex 回合真实失败，卡片仍显示 `0%`；
2. 分母使用会话数，但“应用错误”实际发生在会话内的回合层级，指标口径不一致；
3. 用户无法看到成功、失败、中断、发生日期、错误类型或最近错误，因此无法判断错误是否集中出现以及可能原因。

扫描器现有的 `UsageWarning` 表示 JSONL 损坏、Token 字段无效或文件不可读等本地数据质量问题。项目此前已明确将扫描警告与应用错误率解耦，本次继续保持该边界，不把解析警告重新包装成 Codex 错误。

Codex 官方协议把成功完成、错误终止和回合中断定义为不同事件：`TurnComplete` 可携带终止错误，`Error` 表示回合错误，`TurnAborted` 表示中断。协议枚举是非穷尽的，未来可能增加事件与错误类型，因此解析逻辑必须对未知字段和未知错误码保持兼容。

参考：

- [Codex protocol v1](https://github.com/openai/codex/blob/main/codex-rs/docs/protocol_v1.md)
- [Codex protocol event definitions](https://github.com/openai/codex/blob/main/codex-rs/protocol/src/protocol.rs)

## 2. 目标

错误率详情需要回答以下问题：

1. 当前所选时间范围内，多少可判定回合成功、失败或被中断；
2. 真实回合错误率是多少，指标分母是什么；
3. 错误率最近最多 30 个有终态日期如何变化；
4. 错误主要属于哪些类型；
5. 最近错误发生在何时、哪个会话或项目，以及 Codex 记录了什么错误信息；
6. 旧日志缺少回合终态时，当前指标覆盖了多少数据以及为什么不能计算。

## 3. 指标定义

### 3.1 回合终态

解析器将可识别的回合终态归一化为：

- `completed`：存在明确的成功完成事件，且该回合没有会影响终态的错误；
- `failed`：完成事件携带终止错误，或兼容旧日志时，活跃回合出现会影响终态的错误后结束；
- `interrupted`：存在 `turn_aborted`，包括 `interrupted`、`replaced`、`review_ended` 和 `budget_limited` 等中断原因；
- 未出现明确终态的回合不猜测结果，不进入任何终态计数。

同一回合可能先记录 `error`，随后又记录带 `error` 的完成事件。解析器必须按 `turnId` 或当前活跃回合去重，一个回合最多产生一个终态。较新的带终态完成事件优先于兼容旧日志得到的暂存错误。

工具命令非零退出、MCP 调用失败、补丁失败和扫描警告本身不直接计为“回合失败”。这些事件可能被 Codex 后续恢复并最终成功；只有回合终态失败才进入错误率。工具级可靠性可作为后续独立指标，不与本次回合错误率混用。

### 3.2 错误率

```text
可判定回合数 = 成功回合数 + 失败回合数
回合错误率 = 失败回合数 / 可判定回合数 × 100%
```

中断回合单独展示，不进入错误率分母。用户主动中断或新输入替换当前回合不代表应用错误，把它加入分母或分子都会扭曲可靠性。

当可判定回合数为 `0` 时，错误率为 `null`，界面显示 `—` 和“暂无可判定回合终态”，不得展示 `0%`。真实存在可判定回合且失败数为 `0` 时才显示 `0%`。

### 3.3 数据覆盖

为了避免旧版日志缺少 `task_started` / `task_complete` 时产生过度确定的结论，卡片同时展示终态覆盖：

```text
有终态数据的会话数 / 所选范围内的会话数
```

这里“有终态数据”指至少解析出一个 `completed`、`failed` 或 `interrupted` 的会话。覆盖不足不会阻止对已识别回合计算错误率，但界面必须显示覆盖数量，并说明结果只基于可识别的本地回合终态。

## 4. 错误分类

解析器保留 Codex 提供的原始错误码和消息；Renderer 将错误码归入稳定的展示类别：

- 上下文限制；
- 用量或预算限制；
- 身份验证；
- 网络或响应流；
- 服务过载或内部错误；
- 沙箱或执行环境；
- 请求或策略；
- 其他。

已知但不影响回合终态的错误，例如 `active_turn_not_steerable` 和 `thread_rollback_failed`，不把回合标记为失败。未知错误码不得导致解析失败；当它出现在明确的终止错误位置时归入“其他”，并保留原始码供明细展示。

分类只是便于聚合的展示层规则，不覆盖或改写原始错误信息。

## 5. 界面设计

### 5.1 卡片布局

错误率详情保留在性能指标网格的最后，但改为跨两列的宽卡片；窄屏自然回落为单列。卡片从上到下分为四部分：

1. **汇总区**
   - 标题改为“回合错误率”，避免继续与会话数混淆；
   - 大号错误率；
   - 固定口径说明：“失败回合占成功与失败回合的比例，中断不计入错误率”；
   - 四个常驻数据项：成功、失败、中断、终态覆盖。
2. **每日趋势**
   - 展示最近最多 30 个存在终态数据的本地日期；
   - 纵轴固定为 `0%–100%`；
   - 每个日期提供可聚焦数据点或柱，鼠标悬停和键盘聚焦时显示日期、错误率、成功、失败与中断数；
   - 当某日只有中断而没有可判定回合时显示“—”，不伪装成 `0%`。
3. **错误类型分布**
   - 按失败回合数降序列出错误类别、数量和占全部失败的比例；
   - 没有失败时显示“所选时间范围内没有回合错误”；
   - 颜色只能辅助区分，类别文本、数量和比例必须常驻。
4. **最近错误**
   - 最多展示最近 5 个失败回合；
   - 每项展示本地日期时间、会话名称（无名称时回退为项目名）、错误类别和原始错误消息；
   - 不展示源文件绝对路径；
   - 原始消息允许换行或视觉截断，但完整文本必须能通过可访问名称或原生展开方式读取。

### 5.2 空状态与兼容提示

存在所选会话但没有可识别回合终态时：

- 错误率显示 `—`；
- 成功、失败和中断均显示真实的 `0`；
- 终态覆盖显示 `0 / 会话数`；
- 趋势、分类和最近错误合并为紧凑空状态：“本地日志没有可用于计算错误率的回合终态”；
- 补充说明旧版或不完整 Codex 日志可能不包含这些事件。

存在可判定回合但没有失败时：

- 错误率显示真实的 `0%`；
- 每日趋势显示真实的零值；
- 分类和最近错误区域显示无错误状态，不隐藏成功与中断明细。

性能页整体没有会话时仍由现有上层页面负责，本次不新增第二套页面级空状态。

### 5.3 文案与格式化

新增或修改的用户可见文案同时维护英文和简体中文资源，不在 React 组件中硬编码。数字、百分比和日期时间使用现有 locale formatter。

中文核心文案建议如下：

- 回合错误率
- 失败回合占成功与失败回合的比例，中断不计入错误率
- 成功回合
- 失败回合
- 中断回合
- 终态覆盖
- 每日错误趋势
- 错误类型
- 最近错误
- 暂无可判定回合终态
- 所选时间范围内没有回合错误

英文资源提供等价表达。

## 6. 数据结构与解析

在 `src/shared/usageTypes.ts` 增加回合终态数据：

```ts
export type UsageTurnStatus = 'completed' | 'failed' | 'interrupted';

export interface UsageTurnError {
  code?: string;
  message: string;
}

export interface UsageTurnOutcome {
  turnId?: string;
  occurredAt: string;
  status: UsageTurnStatus;
  interruptReason?: string;
  error?: UsageTurnError;
}

export interface UsageSession extends TokenUsage {
  // 现有字段省略
  turnOutcomes: UsageTurnOutcome[];
}
```

`sessionParser.ts` 在现有单次 JSONL 遍历中同步识别回合开始、完成、错误和中断事件，不增加第二次文件读取，也不修改 Codex 会话文件。解析采用宽容的运行时校验：

- 同时接受协议兼容名称 `task_started` / `turn_started` 与 `task_complete` / `turn_complete`；
- 优先读取完成事件中的 `error`、`started_at`、`completed_at` 和 `duration_ms`，缺失时使用 JSONL 外层时间戳；
- 对旧日志的独立 `error` 事件只在能关联到活跃回合且其错误类型会影响终态时暂存；
- 将 `turn_aborted` 记录为中断而非失败；
- 对未知事件、未知字段和未知错误码保持忽略或降级，不新增扫描警告；
- 不修改输入对象，返回排序稳定的 `turnOutcomes`。

成本优化缓存会从聚合索引重建简化的 `UsageSession`，无法恢复原始回合事件，因此该路径将 `turnOutcomes` 设为空数组。性能页继续使用实时只读扫描结果，不从成本优化缓存计算错误率。

全局时间范围仍沿用现有会话级筛选：先按会话开始时间筛选 `UsageSummary`，再只聚合入选会话的回合终态。本次不改变所有分析页面共同使用的周期语义。

## 7. Renderer 视图模型

新增 `src/renderer/utils/errorRateDetail.ts`，把当前筛选后的 `UsageSummary` 转换为不可变视图模型。建议结构如下：

```ts
interface ErrorRateDay {
  date: string;
  completedCount: number;
  failedCount: number;
  interruptedCount: number;
  errorRate: number | null;
}

interface ErrorCategorySummary {
  category: ErrorCategory;
  count: number;
  percentage: number;
}

interface RecentTurnError {
  occurredAt: string;
  sessionId: string;
  sessionLabel: string;
  projectName: string;
  category: ErrorCategory;
  rawCode?: string;
  message: string;
}

interface ErrorRateDetail {
  completedCount: number;
  failedCount: number;
  interruptedCount: number;
  assessedCount: number;
  errorRate: number | null;
  coveredSessionCount: number;
  totalSessionCount: number;
  days: ErrorRateDay[];
  categories: ErrorCategorySummary[];
  recentErrors: RecentTurnError[];
}
```

纯函数负责：

- 聚合回合终态并计算错误率；
- 保留 `null` 与真实 `0%` 的区别；
- 计算会话覆盖数量；
- 按本地日期聚合并截取最近最多 30 个有终态日期；
- 对失败进行稳定分类、排序和占比计算；
- 选取最近 5 个错误；
- 不修改 `UsageSummary`、会话或回合数组。

新增独立组件 `src/renderer/components/ErrorRateCard.tsx`，只消费视图模型并负责本地化格式化、趋势交互、类型分布、最近错误和空状态。`PerformanceView` 删除静态常量与现有 `Donut`，调用聚合函数并组合新组件。

无需新增 IPC 通道、preload API、持久化设置或网络请求。共享类型通过现有扫描结果传递到 Renderer。

## 8. 交互与可访问性

- 每日趋势数据点使用可键盘聚焦元素，鼠标悬停与键盘聚焦共享同一详情状态；
- 每个数据点的 `aria-label` 包含日期、错误率、成功、失败与中断数；
- 错误类型分布使用文本标签、数量和比例，不以颜色作为唯一表达；
- 最近错误使用语义化列表，日期、会话、类别与消息具备清晰阅读顺序；
- 原始错误消息不作为 `title` 的唯一承载方式，键盘和触屏用户也能获取完整文本；
- 焦点样式清晰可见，并尊重 `prefers-reduced-motion`；
- 小屏下趋势图允许横向滚动，汇总数据项和错误列表自动换行。

## 9. 测试策略

按红—绿—重构执行：

1. 先为 `sessionParser` 添加回归测试，覆盖成功、终止错误、中断、同回合错误去重、非终止错误、未知错误码、兼容事件名和缺失字段；
2. 更新所有 `UsageSession` 测试夹具，为新字段提供显式空数组，并验证成本优化缓存重建结果不会伪造回合终态；
3. 为错误率纯函数添加测试，覆盖正常比例、真实 `0%`、无分母的 `null`、中断排除、覆盖率、每日聚合、30 日截取、错误分类、最近 5 条和输入不可变；
4. 为错误率组件添加静态与交互测试，覆盖中英文文案、汇总数据、趋势点、分类、最近错误、无终态状态、无失败状态和键盘焦点；
5. 更新性能视图测试，先证明硬编码 `0.00% (0/N)` 不满足需求，再验证新宽卡片接入且缓存、费用和活跃时段详情仍保留；
6. 优先运行解析器、错误聚合、错误卡片和性能视图的最小测试集；完成后运行 `npm test`、`npm run typecheck` 和 `npm run lint`；
7. 该变更涉及 Electron 主进程中的会话解析器，完成前额外运行 `npm run build`。

不得通过把扫描警告计为错误、放宽有效断言、隐藏未知事件或删除旧测试来使测试通过。

## 10. 不纳入本次范围

- 不把本地扫描/解析警告计入回合错误率；设置页继续负责展示数据质量警告；
- 不把每次工具调用失败直接计为回合失败；
- 不统计 Codex Desktop 自身崩溃但日志没有留下终态的情况，因为本地数据无法可靠判断；
- 不修改全局周期筛选为回合级时间切片；
- 不新增错误导出、搜索、筛选或跳转到会话详情；
- 不上传错误消息、会话内容、项目路径或任何 Codex 会话数据；
- 不尝试根据错误消息文本猜测未知错误类型。

## 11. 验收标准

1. 错误率不再使用固定 `0`，而是来自所选范围内可识别的真实回合终态；
2. 指标明确使用回合而非会话，失败、成功和中断口径互不混淆；
3. 中断不进入错误率分子或分母，工具失败和扫描警告不被误计为回合错误；
4. 用户可查看终态覆盖、最近最多 30 日趋势、错误类型分布和最近 5 个错误；
5. 无终态数据显示 `—` 和原因，真实零错误才显示 `0%`；
6. 旧日志、未知事件和未知错误码不会使扫描失败或产生虚构数据；
7. 原始错误信息保持本地，不展示源文件绝对路径；
8. 中英文文案、locale 数字/百分比/日期格式和可访问标签完整；
9. Codex 会话目录保持只读，Renderer 不直接访问文件系统；
10. 最小相关测试以及完整测试、类型检查、lint 和生产构建全部通过。
