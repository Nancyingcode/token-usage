# 成本优化仅使用最新模型系列设计

## 1. 背景

当前成本优化工作台会把合并价格表中的全部已计价模型作为替代候选。以当前内置价格为例，`gpt-5.1-codex`、`gpt-5.2-codex`、`gpt-5.3-codex`、`gpt-5.5` 与 `gpt-5.6-*` 都可能进入候选列表，因而会产生跨代模型替代场景。

本次更新把模型替代计算限制在价格表中的最新模型系列。当前最高版本是 `5.6`，所以可参与替代计算的目标模型只有：

- `gpt-5.6-sol`；
- `gpt-5.6-terra`；
- `gpt-5.6-luna`。

这里的限制针对“选择哪个当前模型更节省”的优化计算，不改变历史用量的事实记录。

## 2. 目标

- 从当前合并价格表动态识别最高的 `gpt-<major>.<minor>` 模型系列。
- 成本优化的候选模型、替代场景和模型替代建议只使用该最新系列。
- 总览“优先建议”和节省建议只使用最新系列的贡献，不得显示或量化旧系列模型。
- 新安装或配置重置后，默认候选只包含最新系列，而不是全部已计价模型。
- 已保存的旧系列候选不再参与计算，并通过现有“候选不可用”机制提示用户修复设置。
- 用户覆盖最新模型价格后，仍保留该模型的最新系列身份。
- 未来加入更高版本（例如 `gpt-5.7-*`）时，无需修改筛选常量即可自动切换到 `5.7`。

## 3. 非目标

- 不删除旧模型的价格条目，也不修改“模型价格”页面。
- 不修改预算、总览和性能页面的历史费用估算规则。
- 不删除旧模型 Token，也不把旧模型历史用量伪装成未计价用量。
- 不改变异常检测、费用预测、会话诊断和历史实际成本的统计范围；这些功能仍需反映查询范围内的真实历史支出。
- 不推断模型质量、速度或能力等价。

## 4. 最新模型系列判定

在共享层新增无副作用纯函数，从 `ModelPricingEntry[]` 中解析最新系列并返回对应价格条目或规范模型 ID。

### 4.1 可解析格式

只解析规范模型 ID 中以 `gpt-<major>.<minor>` 开头、且版本后紧接字符串结束或连字符的条目，例如：

- `gpt-5.6` → 系列 `5.6`；
- `gpt-5.6-sol` → 系列 `5.6`；
- `GPT-5.6-TERRA` → 系列 `5.6`；
- `gpt-5.60-preview` → 系列 `5.60`；
- `gpt-5`、`gpt-test`、`my-gpt-9.0` → 不参与系列判定。

别名不参与“哪个系列最新”的竞争，避免某个历史模型新增前瞻别名后改变系列选择；选中价格条目以后，其别名仍按现有定价解析规则生效。

### 4.2 版本比较

`major` 与 `minor` 按非负整数比较，先比较 `major`，再比较 `minor`，不能使用字符串排序或浮点数比较。这样 `5.10` 会正确高于 `5.9`。

所有规范模型 ID 属于最高版本的价格条目共同组成最新系列。返回顺序沿用价格表顺序，避免界面和默认配置无意义抖动。

### 4.3 无可解析系列

若价格表中没有任何可解析的 `gpt-<major>.<minor>` 条目，则最新系列为空：

- 默认候选为空；
- 设置界面不提供新的模型候选；
- 不生成模型替代场景或模型替代建议；
- 历史实际成本及其他分析继续正常工作。

不回退到“全部已计价模型”，以免悄悄恢复跨代比较。

## 5. 计算与数据流

### 5.1 历史实际成本

`coverage`、`currentCostUsd`、`modelRows`、异常、预测与诊断继续接收完整合并价格表。旧模型的真实用量仍按其价格计入历史成本，保证工作台顶部总额、覆盖率和异常依据保持完整。异常可以正常展示旧模型事实，但不能据此生成优先节省建议。

### 5.2 替代计算

运行时从完整合并价格表派生 `latestModelIds`，并把它作为成本优化候选的唯一可用集合：

1. 设置中的 `candidateModelIds` 与 `latestModelIds` 求交集；
2. 只把交集传给 `evaluateSubstitutionScenarios`；
3. 模型替代建议仅消费这些场景，因此不会重新引入旧系列；
4. 来源模型仍来自真实历史用量，但只有来源本身属于最新系列时才生成替代场景。

第 4 条保证所有场景都严格发生在同一最新系列内部。例如 `gpt-5.5 → gpt-5.6-luna` 和 `gpt-5.3-codex → gpt-5.6-terra` 均不再计算；`gpt-5.6-sol → gpt-5.6-terra` 可以计算。

### 5.3 优先建议

生成节省建议前，按最新系列价格筛选贡献：

- 模型替代建议只消费最新系列内部的替代场景；
- 缓存提升建议只消费最新系列贡献；
- 异常回落建议仅在异常的全部贡献均属于最新系列时生成；混合新旧系列或仅含旧系列的异常继续展示，但不进入优先建议；
- 保守节省额只对上述最新系列建议去重汇总。

### 5.4 设置加载与保存

- 新配置的 `candidateModelIds` 默认为全部 `latestModelIds`。
- 保存设置时，候选只能来自 `latestModelIds`；旧系列候选按“候选模型不可用”拒绝保存。
- 加载旧配置时继续保留原始 `candidateModelIds`，不静默改写用户文件；其中非最新系列模型被视为不可用，并通过现有 warning 展示。
- 快照保留用户原始设置，设置抽屉可显示已经失效的旧候选及“不属于最新模型系列”状态，用户取消勾选后即可保存。

配置结构没有变化，因此不提升 schema 版本，也不迁移或重写现有文件。

## 6. Renderer 行为

设置抽屉的可选模型列表改为最新系列 ID。历史配置中已经选择、但不再属于最新系列的 ID 仍追加显示为不可用项。

需要同时更新英文和简体中文文案，使字段说明明确表达“最新模型系列候选”，避免用户误以为完整价格表条目丢失。

模型对比表仍展示所有历史实际模型；替代场景表只展示最新系列内部的组合。

## 7. 边界与不变量

- 所有筛选函数不得修改价格、设置、桶或场景输入。
- 模型 ID 比较忽略首尾空格和大小写，展示仍保留规范价格条目的原始写法。
- 同一最新模型通过规范 ID 或别名出现时，沿用现有价格索引归一化行为，不重复生成目标场景。
- 未知模型兜底价不能成为候选，也不能使旧系列绕过最新系列限制。
- Codex 会话目录保持只读；此次变更不增加文件读取或 Renderer 文件系统访问。
- 所有金额仍是本地估算，不描述为 OpenAI 实际账单。

## 8. 测试策略

按红—绿—重构实施，至少覆盖：

1. 最新系列解析正确比较 `5.9` 与 `5.10`，并忽略不符合格式的模型。
2. 当前内置价格表只返回 `gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-5.6-luna`。
3. 价格覆盖不会因内置价格被用户覆盖而丢失最新系列模型。
4. 默认成本优化配置只包含最新系列候选。
5. 保存旧系列候选失败，加载旧配置则保留候选并产生 warning。
6. `gpt-5.6-sol → gpt-5.6-luna` 可以产生替代场景。
7. `gpt-5.5 → gpt-5.6-luna`、`gpt-5.6-sol → gpt-5.5` 均不产生替代场景。
8. 旧模型历史实际成本、覆盖率、异常和预测仍保持原有结果。
9. 设置抽屉只提供最新系列可用项，同时显示已保存的失效旧项。
10. 输入价格表、设置数组和用量索引在计算后保持不变。

完成前运行最小相关测试，并最终运行：

- `npm test`；
- `npm run typecheck`；
- `npm run lint`。

此次变更涉及 Electron 主进程运行时与配置加载，额外运行 `npm run build`。

## 9. 验收标准

- 当前价格表下，成本优化候选只出现 `gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-5.6-luna`。
- 替代场景和模型替代建议不会包含 `5.6` 以外的来源或目标模型。
- 优先建议、节省建议及保守节省额不会包含 `5.6` 以外模型的贡献。
- 旧模型历史实际费用仍在实际成本、总额、覆盖率、异常和预测中正确反映。
- 加入更高的合法版本系列后，最新系列筛选自动切换。
- 旧配置可恢复且不会被静默覆盖，用户可以从设置抽屉移除失效候选。
- 双语界面、键盘操作和现有类型化 IPC 约束不退化。
