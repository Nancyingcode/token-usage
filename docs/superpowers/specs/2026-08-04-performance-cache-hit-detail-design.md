# 性能页缓存命中率详情设计

## 1. 背景与问题

当前“性能”页的“缓存命中率”卡片只展示一个汇总百分比和一条无标签折线，用户无法判断百分比由多少输入 Token 构成，也无法定位缓存效率在哪一天变好或下降。

现有折线还存在语义错误：它使用 `UsageDay.totalTokens` 绘图，表达的是每日总 Token，而不是每日缓存命中率。由于卡片没有图例或坐标说明，用户容易把总用量变化误认为缓存率趋势。

本次变更将缓存卡片升级为可解释的缓存效率详情。它继续服从全局时间范围筛选，只使用当前筛选后的本地会话数据，不修改扫描流程、Codex 会话文件或费用计算口径。

## 2. 目标

缓存详情需要同时回答以下问题：

1. 当前所选时间范围内的整体缓存命中率是多少；
2. 总输入 Token 中，缓存输入和未缓存输入分别是多少；
3. 最近最多 30 个有数据日期的缓存率如何变化；
4. 某一天的缓存率、缓存输入、未缓存输入和总输入分别是多少；
5. 没有输入 Token 时，为什么不能计算缓存率。

## 3. 指标定义

本页面沿用现有数据语义，将“缓存命中率”定义为缓存输入 Token 占全部输入 Token 的比例，而不是“命中缓存的请求数占请求数的比例”：

```text
缓存命中率 = cachedInputTokens / inputTokens × 100%
未缓存输入 Token = inputTokens - cachedInputTokens
```

汇总指标使用 `summary.totals`，每日指标使用 `summary.byDay`。所有数字均来自当前全局时间范围筛选后的 `UsageSummary`。

当 `inputTokens` 为 `0` 时，缓存率没有可计算的分母。视图模型使用 `null` 表示“不可计算”，界面显示 `—` 和“暂无输入 Token”，不显示 `0%`，避免把“没有输入”误解为“缓存表现为零”。

解析器目前只校验 Token 为非负有限数，没有保证 `cachedInputTokens <= inputTokens`。详情聚合不得修改原始 Token 数；若遇到缓存输入大于总输入的异常数据：

- 原始缓存输入和总输入仍按记录展示；
- 未缓存输入展示为 `0`，不产生负数；
- 用于百分比和图形长度的缓存率限制在 `0%–100%`；
- 卡片显示“缓存数据不一致”提示，说明本地记录中的缓存输入超过总输入。

## 4. 界面设计

### 4.1 卡片布局

缓存详情仍位于性能页指标网格的第一个位置，但改为跨两列的宽卡片。窄屏下自然回落为单列。已有“费用效率”“活跃时段”和“错误率”继续使用原有卡片，不改变指标口径；当前工作区正在开发的 24 小时活跃时段详情不受影响。

卡片从上到下分为三部分：

1. **汇总区**
   - 标题“缓存命中率”；
   - 大号整体百分比；
   - 一句固定定义：“缓存输入占全部输入 Token 的比例”；
   - 三个常驻数据项：缓存输入、未缓存输入、总输入。
2. **构成条**
   - 水平堆叠条展示缓存输入与未缓存输入的占比；
   - 下方使用带文本的图例同时给出名称、Token 数和百分比；
   - 颜色只是辅助表达，不能代替文本、图例和可访问名称。
3. **每日趋势**
   - 展示最近最多 30 个有数据日期；纵轴固定为 `0%–100%`，避免不同数据范围导致视觉尺度失真；
   - 横轴常驻显示首日和末日；只有一个日期时只显示一次；
   - 每个日期提供可聚焦的数据点，鼠标悬停或键盘聚焦后显示日期、缓存率、缓存输入、未缓存输入和总输入；
   - 没有输入 Token 的日期不连接到趋势线，以空心点或缺口表示“不可计算”，其详情显示 `—`；
   - 图表提供整体可访问名称和说明，每个数据点提供包含完整数值的 `aria-label`。

### 4.2 空状态

所选范围存在会话但总输入 Token 为零时：

- 汇总百分比显示 `—`；
- 三项 Token 明细仍显示真实的 `0`；
- 构成条显示空轨道；
- 趋势区显示“所选时间范围内暂无输入 Token”，不绘制一条 `0%` 的趋势线。

性能页整体没有会话的状态仍由现有上层页面负责，本次不新增第二套页面级空状态。

### 4.3 文案与格式化

新增或调整的用户可见文案同时维护英文和简体中文资源，不在 React 组件中硬编码。Token 数使用现有 locale number formatter，百分比使用现有 locale percent formatter，日期使用本地化日期格式。

中文核心文案建议如下：

- 缓存输入占全部输入 Token 的比例
- 缓存输入
- 未缓存输入
- 总输入
- 每日缓存趋势
- 所选时间范围内暂无输入 Token
- 缓存数据不一致

英文资源提供等价表达。

## 5. 组件与数据流

新增 Renderer 纯函数模块 `src/renderer/utils/cacheEfficiency.ts`，将 `UsageSummary` 转换为稳定的缓存效率视图模型。建议结构如下：

```ts
interface CacheEfficiencyDay {
  date: string;
  inputTokens: number;
  cachedInputTokens: number;
  uncachedInputTokens: number;
  percentage: number | null;
  hasInconsistentData: boolean;
}

interface CacheEfficiency {
  inputTokens: number;
  cachedInputTokens: number;
  uncachedInputTokens: number;
  percentage: number | null;
  hasInconsistentData: boolean;
  days: CacheEfficiencyDay[];
}
```

纯函数负责：

- 计算汇总和每日缓存率；
- 将未缓存输入限制为非负数；
- 将图形百分比限制在合法范围；
- 保留 `null` 与真实 `0%` 的区别；
- 截取最近最多 30 个日期；
- 不修改传入的 `UsageSummary` 或其中数组。

新增独立组件 `src/renderer/components/CacheEfficiencyCard.tsx`，只消费视图模型并负责本地化格式化、构成条、每日趋势、详情浮层和键盘焦点状态。`PerformanceView` 调用聚合函数后组合该组件，避免继续把统计和交互堆入现有文件。

无需新增主进程、IPC、preload 或持久化字段；现有 `UsageDay` 已包含实现所需的 `inputTokens` 和 `cachedInputTokens`。

## 6. 交互与可访问性

- 趋势数据点使用可键盘聚焦的 SVG 元素或透明命中区域；焦点样式清晰可见；
- 鼠标悬停和键盘聚焦共享同一详情状态模型；鼠标离开或失焦后关闭详情；
- 详情浮层仅补充视觉信息，完整数值同时存在于数据点 `aria-label` 中；
- 构成条使用文本图例和可访问描述，不以颜色作为缓存状态的唯一表达；
- 尊重 `prefers-reduced-motion`，禁用非必要过渡；
- 小屏允许趋势图横向滚动，汇总数据项自动换行，不压缩到不可读宽度。

## 7. 测试策略

按红—绿—重构执行：

1. 为缓存效率纯函数添加测试，覆盖正常比例、真实 `0%`、无输入的 `null`、每日聚合、30 日截取、异常缓存数据以及输入不可变；
2. 为缓存详情组件添加静态渲染测试，覆盖双语文案、汇总明细、构成图例、趋势数据点、无输入状态和异常提示；
3. 更新性能视图测试，先证明旧的每日总 Token 折线不满足需求，再验证宽卡片接入和现有费用、活跃时段、错误率仍保留；
4. 若交互测试环境支持 DOM 事件，补充鼠标悬停、键盘聚焦和失焦的详情状态测试；否则通过组件标记、`tabIndex` 与完整 `aria-label` 做静态契约测试；
5. 优先运行缓存聚合、缓存组件和性能视图的最小测试集；完成后运行 `npm test`、`npm run typecheck` 和 `npm run lint`。

该变更只涉及 Renderer、样式和翻译资源，不要求额外运行生产构建；若实施时实际触及构建配置、Electron 主进程或 preload，则补充运行 `npm run build`。

## 8. 不纳入本次范围

- 不把缓存率改成按请求或会话计数的“缓存命中次数”；现有会话数据没有可靠的请求命中字段；
- 不新增模型维度或项目维度排行榜；性能页已有项目页和会话诊断入口，本次优先解决汇总可解释性与时间趋势；
- 不估算“缓存节省金额”，避免把缓存详情与模型价格完整性、未知模型兜底价格耦合；
- 不修改概览页现有缓存摘要；
- 不修改 Codex 会话目录、扫描缓存或成本优化缓存；这里的“缓存”仅指缓存输入 Token。

## 9. 验收标准

1. 缓存卡片明确展示整体缓存率、缓存输入、未缓存输入和总输入；
2. 每日趋势真正使用每日 `cachedInputTokens / inputTokens`，不再使用 `totalTokens` 作为折线数值；
3. 用户可以通过鼠标和键盘查看每个日期的精确缓存明细；
4. 无输入数据显示 `—` 和明确空状态，不伪装成 `0%`；
5. 异常数据不会产生负数、超过 `100%` 的图形或无提示的错误展示；
6. 中英文文案、locale 数字/百分比/日期格式和可访问标签完整；
7. 与当前活跃时段详情改动共存，不覆盖其组件、样式、翻译或测试；
8. 最小相关测试和完整的测试、类型检查、lint 全部通过。
