# 性能页活跃时段详情设计

## 背景与目标

当前“性能”页的“活跃时段”卡片只显示“最活跃时间”和 12 根无标签柱形。现有柱形实际代表最近 12 个会话，而不是一天中的小时分布；峰值统计还会把一个会话的全部 Token 归到会话开始的小时。用户无法判断每个时段的 Token、占比、会话数和活跃日期，也容易误解图表含义。

本次变更将“活跃时段”改为基于本地时间的 24 小时分布，让用户既能快速识别高峰，又能查看每个小时的精确数据。其余性能指标、全局时间范围筛选和会话扫描流程保持不变。

## 展示方案

保留“活跃时段”在现有性能指标网格中的位置，但让该卡片使用更适合 24 小时数据的纵向布局，并展示以下内容：

1. 卡片标题下显示高峰摘要：高峰小时区间，例如 `14:00–15:00`。
2. 摘要同时显示该小时的 Token、占当前范围总 Token 的比例、会话数和活跃天数。
3. 主图改为 24 根小时柱，从 `00` 到 `23` 顺序排列；横轴至少常驻显示 `00:00`、`06:00`、`12:00`、`18:00` 和 `24:00`，避免用户只能猜测柱形含义。
4. 每根柱以 Token 数决定高度。鼠标悬停或键盘聚焦时显示详情浮层，包含：
   - 小时区间；
   - Token 数；
   - 占当前范围总 Token 的比例；
   - 在该小时产生用量的不同会话数；
   - 该小时在多少个不同日期产生过用量。
5. 高峰小时使用轮廓、峰值标记和文本共同强调，不只依赖颜色。

卡片继续响应现有“今天 / 近 7 天 / 近 30 天 / 全部”筛选。这里的“活跃天数”指当前筛选结果中，在对应本地小时至少有一条 Token 用量的不同本地日期数。

相比增加一个固定 24 行明细表，本方案优先采用“摘要 + 24 小时图 + 按小时详情浮层”：它能够提供完整精确数据，同时不会让性能页被大量重复行占满。后续若需要导出或跨小时精确比较，可再独立增加表格视图，不纳入本次范围。

## 统计口径

新增 Renderer 侧纯函数，将 `UsageSession[]` 聚合为固定 24 项的小时桶。每项至少包含：

- `hour`：本地小时，范围为 0–23；
- `totalTokens`：该小时的 Token 总量；
- `shareOfTotal`：该小时占所有小时 Token 总量的比例；
- `sessionCount`：在该小时产生用量的不同会话数；
- `activeDayCount`：在该小时产生用量的不同本地日期数。

统计优先使用 `usageSlices[].occurredAt`，把每条增量 Token 记入实际发生的本地小时。这样跨小时会话会按真实用量时间拆分，不再全部归到开始小时。

兼容缺少明细切片的会话：当一个会话没有可用 `usageSlices` 时，将该会话的总 Token 按 `startedAt` 归入一个小时桶。无效时间戳不进入小时分布，避免错误地归入午夜；这类数据不会修改或删除，原有总量和会话列表保持不变。

为了避免重复计数，同一会话在同一小时存在多条切片时，`sessionCount` 只增加一次；同一小时在同一本地日期存在多条切片时，`activeDayCount` 也只增加一次。小时占比以进入小时分布的 Token 总量为分母，因此无效时间戳导致的未分配 Token 不会让 24 个小时的占比之和小于 100%。

高峰小时按 `totalTokens` 最大值选择；Token 相同时依次选择会话数更多、活跃天数更多、小时更早的一项，保证结果稳定。所有小时 Token 都为 0 时不显示伪造的 `00:00` 高峰，改为本地化的“暂无 Token 活动”状态。

所有时间均按应用运行环境的本地时区显示，并在卡片辅助文案中明确标注“本地时间”。不新增时区选择，也不改变上游按会话开始时间执行的范围筛选规则。

## 组件与数据边界

- 新建 Renderer 纯函数模块负责 24 小时聚合、峰值选择和边界处理；不修改输入的 `UsageSession` 或 `UsageSlice`。
- `PerformanceView` 只消费聚合后的视图模型并负责本地化格式化，不把统计逻辑继续堆在 JSX 中。
- 将活跃时段图拆为独立组件，管理 hover/focus 对应的详情展示；状态只保存当前查看的小时索引，不保存可由 props 推导的统计结果。
- 不修改 Electron 主进程、preload、IPC、会话扫描器或共享扫描结果类型。
- 移除“最近 12 个会话柱形”专用逻辑；`TokenBar` 是否仍被其他界面使用由实施时检查决定，不为本功能顺带清理无关代码。

## 可访问性与国际化

- 新增或修改的用户可见文案同时维护英文和简体中文资源，不在 React 组件中硬编码。
- 图表提供本地化名称和说明；每个小时柱提供包含小时区间、Token、比例、会话数和活跃天数的完整可访问名称。
- 小时柱支持键盘聚焦；focus 与 hover 展示相同详情，失焦或移出后关闭。
- 横轴标签、峰值轮廓和文本标记保证颜色不是表达峰值的唯一方式。
- Token 和百分比使用现有 locale formatter；会话数与天数使用 i18next 复数规则。
- 详情浮层限制在卡片范围内，窄窗口下不被裁切；遵守 `prefers-reduced-motion`，内容读取不依赖动画。

## 响应式布局

- 宽屏下 24 根柱平均分配宽度，详情浮层靠近对应柱显示。
- 窄屏下保留 24 小时完整顺序，缩小柱间距与非关键轴标签；不通过隐藏小时数据换取空间。
- 若最窄支持宽度无法容纳可点击宽度，图表区域允许水平滚动，并保留可见的滚动提示或边缘渐隐；页面本身不产生水平溢出。

## 边界情况

- 当前筛选范围没有会话时，继续由上层期间空状态处理。
- 有会话但全部 Token 为 0 时，显示“暂无 Token 活动”，24 根柱保持零值且不强调任何峰值。
- 有 Token 但时间戳全部无效时，显示“无法按小时分配用量”的本地化说明，不将数据错误归入 `00:00`。
- 会话有多条跨小时切片时，各切片进入各自本地小时；会话数按小时去重。
- 跨日期、跨月和夏令时切换只依据每条时间戳转换后的本地小时与本地日期聚合。
- 当前范围为“全部”时，活跃天数按全部已扫描数据去重，不截断为最近 30 天。

## 测试与验证

开发按红—绿—重构执行：

1. 先新增小时聚合纯函数测试，覆盖 24 个固定桶、跨小时切片、本地小时转换、同会话去重、活跃日期去重、无切片回退、无效时间、零 Token、峰值并列规则和不修改输入。
2. 更新性能视图测试，先证明旧的 12 会话柱形不再满足需求，再验证 24 小时图、峰值摘要、常驻轴标签和中英文文案。
3. 增加交互测试，验证 hover/focus 显示同一份精确详情，移出/失焦关闭，并验证每个小时的本地化可访问名称。
4. 增加样式策略的最小必要断言，覆盖峰值的非颜色提示、窄屏布局和浮层边界。
5. 优先运行小时聚合和性能视图的最小测试集；完成后运行 `npm test`、`npm run typecheck` 和 `npm run lint`。

本次不修改构建配置、Electron 主进程、preload 或打包配置，因此不额外要求 `npm run build`。

## 非目标

- 不增加按项目、模型或工作日/周末拆分的二级筛选。
- 不展示无法从现有 Token 事件可靠推导的“连续工作时长”或“空闲时长”。
- 不修改全局时间范围筛选的语义。
- 不新增导出、下载或上传用量数据的能力。
- 不调整缓存命中率、费用效率和错误率的统计或视觉设计。
