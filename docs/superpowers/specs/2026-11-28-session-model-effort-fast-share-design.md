# 会话模型、思考强度与 Fast 占比

设计已确认。会话列表和详情列出用量切片或回合上下文中记录的模型。详情展示各模型与思考强度的用量，以及线程设置为 Fast 时记录的用量份额。[实施计划](../plans/2026-11-28-session-model-effort-fast-share.md) · [已有会话详情设计](2026-11-28-reasoning-effort-fast-mode-design.md)

## 模型与思考强度

会话列表显示去重后的模型名称。详情按「模型、思考强度」的组合列出回合数、总 Token 和其中的推理输出 Token。一个模型用过两档强度时显示两行，两个模型用过同一档强度时也显示两行。

两个字段分别采信同一回合的上下文。某个字段缺失或同一轮中有冲突时，只将该字段列为「未知」。回合无法识别的增量和只有整场累计的用量进入未知归属。每轮只计一次，各行 Token 加总等于会话总量。没有用量记录的可识别回合也显示其已记录的模型和强度，用量显示「未记录」。[当前回合归属规则](../../../src/main/sessionEffortUsage.ts)

## Fast 占比

在速度变化记录上方显示「Fast 设置期间记录的 Token 占比」，同时显示分子和分母。分子是写入有效 Token 增量时，本线程最近一次速度设置为 Fast 的 Token 总数。分母是整场会话的总 Token，包含设置未知的部分。这一数值描述本地记录时的线程设置。请求实际服务档位需要独立的响应证据，费用继续使用现有计价规则。

例如，一场会话记录 1,000 Token，其中 Fast 期间记录 400、标准期间记录 500、首次设置之前记录 100。详情显示「40.00%（400 / 1,000 Token）」及「设置未知 100 Token」。有未知用量时，这个百分比只表示已观察到的 Fast 份额。

- 沿用文件内顺序和所属线程身份。相同时间戳按日志先后处理，后写入的速度设置只影响后续记录。分叉继承的其他线程设置不参与本线程归属。[线程速度历史](../../../src/main/threadSpeedHistory.ts)
- 复用会话总计已采纳的增量，累计值未增长时跳过重复快照。只有累计而无可归属增量时，整场用量记为「设置未知」。[会话解析器](../../../src/main/sessionParser.ts)
- `priority` 和 `fast` 合并为 Fast，标准和已识别的 `ultrafast` 各保留其档位。首次设置之前、空设置和未识别的档位进入未知用量，原始档位仍可在历史中查看。
- 会话总量为零，或全部用量归属未知时，显示「无法计算」。有已知设置且已知均为非 Fast 时，可显示已观察到的 0%，同时列出任何未知用量。

Token 占比作为主指标，回合占比作为辅助指标。辅助指标标为「开始时设置为 Fast 的回合」，分母是全部可识别回合。以每轮开始时已知的设置为准，缺少开始边界或开始时设置未知的回合单列。第一条设置有时出现在首轮开始之后、首次用量之前，因此同一轮的回合归属与 Token 归属可能不同。没有回合或全部回合的起始设置未知时，回合占比显示「无法计算」。

## 验收

- 使用合成会话覆盖换模型、换强度、缺失或冲突字段及仅累计可用。核对模型与强度的合计、会话总 Token 和思考输出 Token。
- 覆盖标准切 Fast 再切回、同轮内切换、同一时间的多条记录、重复累计、分叉线程、未知设置、无设置和零分母。逐笔对账分子、分母和未知用量。
- 主进程按文件解析一次。新增会话汇总字段后更新扫描缓存版本，使普通文件和已导入的压缩文件均可重建。中英文界面可直接读取指标名称、百分比、分子、分母和未知量。
