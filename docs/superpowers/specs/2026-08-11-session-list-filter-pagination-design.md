# 会话列表筛选与分页设计

## 背景与目标

当前侧边栏“会话”页面展示当前全局时间范围内的全部本地会话，只支持从“项目”页面下钻时附带的单项目筛选。页面已经展示会话所属项目、Token 用量、文件告警状态和主要诊断原因，但不能在会话页直接组合筛选；会话数量较多时，完整列表也会造成浏览和渲染负担。

本次在“会话”页面增加本地筛选工具栏和客户端分页，使用户能够按项目与诊断原因定位会话，并通过可调整的每页条数浏览结果。筛选和分页只消费 Renderer 已取得的 `UsageSession[]` 与 `SessionDiagnosisSummary[]`，不修改会话扫描、诊断计算、IPC 契约或只读数据源。

## 筛选条件

筛选采用“条件之间取交集、单个条件内单选”的组合规则，并在分页前执行：

1. **关键词**：匹配会话名称、完整会话 ID 和项目完整路径；去除首尾空白并忽略大小写。该条件补足用户知道会话名称或 ID、但不知道项目和诊断分类时的定位能力。
2. **项目**：默认“全部项目”，选项从当前时间范围内的会话派生。项目名相同时以完整路径区分，未知项目使用现有本地化名称。项目选项按展示名称排序，名称相同时按路径稳定排序。
3. **诊断原因**：默认“全部原因”，可选择现有五类主要原因：输入增长、缓存退化、生成集中、模型成本主导、交互累积；另提供“无明确诊断”选项。具体原因只匹配 `primaryFinding.cause`，不以次要发现命中，避免列表徽标与筛选结果口径不一致。“无明确诊断”匹配没有 `primaryFinding` 的会话。
4. **诊断严重程度**：默认“全部级别”，可选择“警告”或“严重”。没有主要诊断的会话不匹配具体严重程度。该条件用于在同一原因下优先定位影响更高的会话。

现有全局时间范围继续由顶部工具栏负责，不在会话页重复提供日期筛选。表格原有“状态”列描述会话文件告警，不与诊断严重程度混用，本次不新增文件告警筛选。

从“项目”页面点击“查看会话”时，仍进入会话页并把项目下钻路径设置为项目筛选值。会话页项目下拉框与该导航状态使用同一数据源；用户可以直接切换项目或恢复“全部项目”，不再同时维护相互冲突的项目筛选和项目标签。

## 筛选结果与清除行为

- 标题区域展示“匹配会话数 / 当前时间范围总会话数”，使分页后仍能看到完整结果规模。
- 任一筛选不是默认值时，显示“清除筛选”操作，一次恢复关键词、项目、诊断原因和严重程度的默认值。
- 无匹配结果时，在表格面板内显示通用筛选空状态和清除筛选操作；若只有全局时间范围导致无会话，继续由现有上层空状态处理。
- 筛选纯函数不得修改传入会话、诊断摘要或项目数组；结果顺序沿用当前会话列表顺序，避免本次分页顺带改变既有排序语义。

## 分页规则

- 支持每页 `10`、`20`、`50`、`100` 条，默认 `10` 条。
- 先完成全部筛选，再根据当前页和每页条数截取表格行。
- 分页区域显示当前结果范围、匹配总数、当前页/总页数、上一页和下一页；首尾页禁用不可用操作。控件使用原生按钮与 `select`，提供本地化可访问名称和禁用状态。
- 修改任一筛选条件或每页条数时回到第 1 页。
- 会话刷新、全局时间范围变化或项目下钻变化导致当前页超出新总页数时，把当前页收敛到最后一个有效页；无结果时内部页码保持第 1 页。
- 动效索引以当前页内顺序计算，翻页或筛选后使用新的稳定动效键；仍遵循 `prefers-reduced-motion`。

## 每页条数记忆

仅记住用户最后选择的**每页条数**，不记住关键词、筛选条件和当前页。这样重新启动应用后仍保留用户偏好的列表密度，但不会因旧筛选或旧页码造成“会话消失”的误解。

Renderer 使用与全局时间范围偏好相同的防御式 `localStorage` 模式，键名为 `codex-token-usage.sessions-page-size`：

- 没有记录、记录不是整数或不属于 `10/20/50/100` 时使用默认值 `10`；
- 读取失败时使用默认值，不阻止页面渲染；
- 写入失败时保留当前内存选择，不向会话数据源或主进程写入任何内容。

偏好解析和保存实现为独立纯逻辑模块，并以可注入的最小存储接口测试，不在组件测试中依赖真实浏览器存储。

## 组件与数据流

- `App` 继续持有当前项目筛选路径，并向会话页提供统一的项目筛选变更回调，兼容项目页下钻导航。
- `SessionsView` 持有关键词、诊断原因、严重程度和当前页；每页条数以已校验偏好初始化。
- 新增 Renderer 纯函数，将会话与按 `sourceFile` 索引的诊断摘要组合筛选，并返回分页所需的匹配结果。
- `globalDiagnostics` 仍是诊断原因与严重程度的唯一事实来源；找不到对应摘要的会话按“无明确诊断”处理。
- 不把分页参数传入主进程。当前数据规模下采用客户端分页，保证筛选口径与已经加载的当前周期数据一致，也避免扩大 IPC 与缓存协议。

## 国际化、响应式与可访问性

- 新增筛选标签、选项、结果计数、空状态和分页文案时，同时维护英文与简体中文资源，两个 namespace 的叶子键保持一致。
- 每个输入控件都使用可见 `<label>`；关键词使用 `type="search"`，项目、原因、严重程度和每页条数使用原生 `select`。
- 筛选结果数量变化通过普通可见文本表达；翻页后的列表更新提供非打断式 `role="status"` 页码信息，避免仅依赖视觉变化。
- 窄屏下筛选控件允许换行并保持完整可访问名称；表格继续使用现有横向滚动策略，分页控件不得被表格最小宽度一起撑出视口。
- 诊断严重程度继续同时使用图标、文案和颜色，不以颜色作为唯一表达。

## 非目标

- 不新增服务端分页、游标分页、虚拟列表、排序、日期范围或文件告警筛选。
- 不按次要诊断发现筛选，也不改变主要诊断的选择算法。
- 不修改会话文件、诊断模型、价格计算、预算、持久化配置文件或 Electron IPC。
- 不记住筛选条件、关键词、当前页或滚动位置。
- 不向网络上传任何会话或筛选数据。

## 测试与验证策略

按红—绿—重构实施：

1. 先为关键词、项目、诊断原因、无明确诊断、严重程度的组合筛选添加失败测试，并验证输入数组不变。
2. 为分页边界添加失败测试，覆盖默认 10 条、四种每页条数、尾页、无结果、筛选后回到第 1 页和数据缩减后的页码收敛。
3. 为偏好模块添加失败测试，覆盖合法值、缺失值、非法值以及存储读取和写入异常。
4. 更新会话组件测试，覆盖项目下钻与下拉框同步、清除筛选、结果计数、分页按钮禁用、每页条数变更和可访问名称。
5. 更新双语资源并运行 i18n 键一致性测试；补充窄屏样式并检查键盘操作和空状态。
6. 完成前运行最小相关测试，并最终运行 `npm test`、`npm run typecheck` 和 `npm run lint`。

## 验收标准

- 会话页可按关键词、项目、主要诊断原因和诊断严重程度组合筛选。
- 从项目页进入会话页时，项目筛选正确显示且可在页面内切换或清除。
- “无明确诊断”能找到没有主要诊断的会话，原因筛选结果与列表展示的主要诊断徽标一致。
- 列表默认每页 10 条，可切换为 20、50 或 100 条；上一页、下一页、结果范围和总页数在边界情况下正确。
- 重启 Renderer 后恢复最后一次合法的每页条数；非法或不可用存储不会破坏页面。
- 所有新增文案均有中英文版本，筛选与分页支持键盘和辅助技术。
- 现有全局时间筛选、项目下钻、诊断详情打开、只读会话目录和本地估算语义不退化。
