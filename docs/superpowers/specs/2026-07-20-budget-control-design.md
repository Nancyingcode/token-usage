# Token 预算控制功能设计

## 1. 背景

当前应用可以从本地 Codex 会话日志中统计 Token 使用量，并按时间、项目和会话展示趋势。下一阶段需要从“查看消耗”扩展为“控制消耗”：用户可以为全局或单个项目设置 Token 与预估费用预算，在达到阈值时获得应用内预警和系统通知。

本功能只负责监控、计算和提醒，不介入或阻止 Codex 运行。

## 2. 目标

- 同时支持全局预算和项目预算。
- 全局及项目预算均支持自然日、自然周、自然月周期。
- Token 限额和预估费用限额可以独立启用和设置。
- 费用按模型价格表计算，内置价格允许用户覆盖。
- 无法识别或没有价格的模型不得猜测价格，应明确标记为未计价。
- 达到阈值时同时提供应用内预警和系统通知。
- 应用运行期间自动刷新数据，同时控制重复扫描和重复通知。
- 延续当前 Lumo 风格，使用独立预算中心承载完整配置与状态。

## 3. 非目标

首版不包含以下能力：

- 强制停止或限制 Codex 运行。
- 云端同步及多设备共享。
- 联网自动更新模型价格。
- 美元以外的货币换算。
- 应用退出后的后台常驻监控。
- 预算配置或历史数据的导入导出。

## 4. 核心决策

### 4.1 存储方案

采用 Electron 主进程 JSON 存储，并通过 Preload 暴露类型化 IPC。配置文件保存在 Electron `userData` 目录，不使用渲染进程 `localStorage`，也不引入 SQLite 或原生数据库依赖。

### 4.2 页面入口

侧栏新增独立 `Budgets` 页面。概览页不内嵌预算卡片，预算的查看、编辑、价格维护和预警处理均在预算中心完成。

### 4.3 编辑方式

新增和编辑预算使用右侧抽屉。抽屉打开时保留预算列表上下文，适合展示范围、项目、周期、Token 限额和费用限额等字段。

### 4.4 周期规则

预算使用本机时区下的自然周期：

- 日：当天 `00:00` 至当前时间。
- 周：周一 `00:00` 至当前时间。
- 月：当月 1 日 `00:00` 至当前时间。

现有 Overview 的滚动 Today、Week、Month 筛选保持不变。预算周期与趋势筛选是两套明确的时间语义，不能复用滚动窗口计算预算。

## 5. 数据模型

### 5.1 预算策略

预算策略包含以下字段：

```ts
type BudgetScope = 'global' | 'project';
type BudgetPeriod = 'day' | 'week' | 'month';

interface BudgetPolicy {
  id: string;
  scope: BudgetScope;
  projectPath?: string;
  period: BudgetPeriod;
  tokenLimit?: number;
  costLimitUsd?: number;
  createdAt: string;
  updatedAt: string;
}
```

规则如下：

- `project` 范围必须提供规范化后的完整项目路径。
- `global` 范围不得保存项目路径。
- `tokenLimit` 和 `costLimitUsd` 至少提供一个，二者可独立启用或关闭。
- 限额必须为大于 0 的有限数字。
- `scope + normalizedProjectPath + period` 构成唯一业务键。
- Windows 项目路径比较忽略大小写并统一路径分隔符，展示时保留原始路径。

### 5.2 全局阈值

```ts
interface BudgetThresholds {
  warningPercent: number;
  criticalPercent: number;
}
```

默认阈值为 80% 和 100%。用户可以全局修改，必须满足 `0 < warningPercent < criticalPercent <= 100`。阈值同时用于 Token 和费用预算。

预算使用率达到 `warningPercent` 时进入预警状态，达到 `criticalPercent` 时进入严重状态。达到或超过 100% 始终视为已超预算。

### 5.3 模型价格

```ts
interface ModelPricing {
  modelId: string;
  aliases: string[];
  inputUsdPerMillion: number;
  cachedInputUsdPerMillion: number;
  outputUsdPerMillion: number;
  sourceUrl?: string;
  effectiveAt: string;
}
```

内置价格表随应用版本发布，记录来源和生效时间。用户覆盖价格与内置价格分开保存，只记录差异项；删除覆盖项即可恢复内置价格。用户可以为未知模型新增价格。

所有价格必须是大于或等于 0 的有限数字。首版币种固定为美元。

### 5.4 按时间和模型拆分的用量

自然周期和模型计价都不能只依赖会话级总量。解析器需要在保持现有 `UsageSession` 汇总字段兼容的同时，新增用量切片：

```ts
interface UsageSlice extends TokenUsage {
  occurredAt: string;
  modelId?: string;
}
```

- 每条有效的增量 `last_token_usage` 形成一个切片。
- 切片使用该 Token 记录的时间，并归属到当时生效的模型。
- 一个会话中发生模型切换时，各切片分别进入对应模型。
- 只有累计总量、没有增量记录时，使用最终累计记录形成一个兜底切片。
- 兜底切片只有在模型归属明确时才设置 `modelId`；否则进入未计价分组。
- 会话现有总量仍按原有增量优先、累计总量兜底的规则生成，不能同时叠加两种来源。

## 6. 计价规则

单个模型的预估费用按以下口径计算：

```text
普通输入 Token = max(inputTokens - cachedInputTokens, 0)
费用 = 普通输入 Token × 输入单价
     + cachedInputTokens × 缓存输入单价
     + outputTokens × 输出单价
```

单价均按每百万 Token 换算。`reasoningOutputTokens` 作为输出 Token 的明细展示，不额外计价，避免与 `outputTokens` 重复。

无法识别模型或价格缺失时：

- Token 继续正常统计和参与 Token 预算。
- 对应 Token 进入未计价分组，不使用统一单价或相近模型价格。
- 已知费用仍然汇总，并在达到阈值时正常预警。
- 只要周期内存在未计价数据，费用状态就标记为不完整；即使已知费用低于阈值，也不得展示为安全状态。
- 页面展示未计价 Token 数和模型，并提供进入模型价格设置的入口。

## 7. 系统架构

### 7.1 共享领域层

共享层负责类型和纯函数，不依赖 Electron 或 React：

- 自然日、周、月边界计算。
- 项目路径规范化和预算业务键生成。
- 模型别名匹配及价格合并。
- Token 费用计算和未计价数据汇总。
- 预算状态评估和阈值事件生成。
- 配置数据校验。

### 7.2 Electron 主进程层

主进程拆分为职责单一的服务：

- 预算存储服务：读取、校验、迁移和原子写入 JSON 配置。
- 价格目录服务：加载内置价格并合并用户覆盖。
- 用量监控服务：扫描会话、维护文件缓存、调度定时刷新。
- 预算评估服务：根据自然周期、项目和价格生成预算快照。
- 通知服务：发送系统通知、保存去重记录并处理通知点击。
- IPC 注册层：校验渲染进程输入并调用上述服务。

### 7.3 Preload 层

在现有 `window.codexUsage` 桥接对象下增加预算 API，不直接暴露 `ipcRenderer`：

- 获取当前预算快照。
- 新增或更新预算。
- 删除预算。
- 更新全局阈值。
- 保存或恢复模型价格覆盖。
- 订阅预算快照更新。

订阅 API 必须返回取消订阅函数，组件卸载时移除监听器。

### 7.4 React 渲染层

渲染层只负责页面状态和交互，不持久化预算，也不自行发送系统通知。主要界面单元包括：

- `BudgetsView`：预算中心页面和标签页切换。
- 预算摘要：展示即将超限、已超限和未计价模型数量。
- 预算列表：按全局与项目分组，展示 Token 和费用进度。
- 预算抽屉：新增和编辑预算。
- 模型价格列表：展示默认价格、用户覆盖和恢复操作。
- 应用内预警：展示当前周期新产生的预警。

复杂互斥界面使用明确的渲染状态模型；可从预算快照和抽屉状态推导的值不得保存为重复 React state。

## 8. 刷新与缓存

### 8.1 刷新触发

- 应用启动后立即扫描一次。
- 应用运行期间每 60 秒扫描一次。
- 窗口重新获得焦点时立即触发扫描。
- 聚焦刷新设置最短间隔，避免短时间反复切换窗口导致重复扫描。
- 同一时间最多执行一个扫描任务；新的触发复用正在执行的任务。

### 8.2 文件缓存

主进程维护不落盘的会话解析缓存，以文件路径、文件大小和修改时间作为缓存指纹：

- 新增或发生变化的文件重新解析。
- 未变化文件复用已有解析结果。
- 已删除文件从缓存和统计结果中移除。
- 修改预算、阈值或价格时只重新评估，不重新读取日志。
- 应用重启后的首次扫描读取全部文件。

扫描成功后，主进程重新计算预算快照并通过 IPC 推送给渲染进程。扫描失败时保留上一份成功快照，并将数据状态标记为过期。

## 9. 持久化设计

配置 JSON 包含：

- `schemaVersion`
- 预算策略列表
- 全局阈值
- 用户价格覆盖
- 系统通知去重记录

写入时先生成同目录临时文件，再替换目标文件。配置读取必须执行运行时校验，不能将反序列化结果直接断言为业务类型。

配置损坏时：

1. 将原文件重命名为带时间戳的损坏备份。
2. 恢复默认配置。
3. 在应用内显示可见警告。
4. 不删除会话日志或其他用户数据。

`schemaVersion` 用于后续迁移。无法识别的未来版本不得覆盖原文件，应返回明确错误。

## 10. 通知设计

应用内预警和系统通知使用同一批阈值事件。系统通知去重键包含：

- 预算 ID
- 自然周期开始时间
- 指标类型：Token 或费用
- 阈值级别及阈值数值

同一预算、同一自然周期、同一指标和同一阈值只发送一次系统通知。进入新自然周期后可再次通知。修改预算、阈值或价格后立即重新评估；如果生成一个尚未发送过的新阈值事件，则允许通知。

去重记录不保存完整通知历史，而是按预算、周期、指标和阈值保存最近一次已通知的周期开始时间。新周期覆盖旧周期值，避免配置文件随使用时间无限增长。预算或阈值被删除时，同步清理对应记录。

点击系统通知后，应用窗口需要恢复并获得焦点，随后导航到对应预算。系统通知不可用或发送失败时，只记录警告，不能影响预算计算和应用内预警。

## 11. 页面与交互

### 11.1 Budget overview

页面顶部包含标题和新增预算按钮，其下展示：

- 即将超限预算数量。
- 已超限预算数量。
- 未计价模型数量。

预算列表按全局预算和项目预算分组，并支持按范围及周期筛选。每条预算同时展示 Token 和费用进度；未启用的指标显示 `Not set`。

状态样式：

- 低于预警阈值：绿色。
- 达到预警阈值：琥珀色。
- 达到严重阈值：红色。
- 达到或超过 100%：明确标记已超预算。
- 存在未计价数据：费用使用不完整状态，不显示绿色安全状态。
- 进度超过 100% 时，进度条视觉宽度封顶，文字显示真实百分比。

### 11.2 预算抽屉

抽屉字段包括：

- 范围：全局或项目。
- 项目：仅项目范围显示。
- 周期：日、周、月。
- Token 限额开关及数值。
- 费用限额开关及美元数值。

至少启用一种限额。重复业务键不能新增，界面应提示用户编辑已有预算。删除预算需要二次确认；删除只移除配置，不影响历史会话数据。

### 11.3 Model pricing

模型价格标签页展示模型 ID、别名、输入价格、缓存输入价格、输出价格、生效时间和来源状态。用户可以：

- 覆盖内置模型价格。
- 为未知模型新增价格。
- 恢复某个模型的默认价格。
- 查看价格来源链接和生效时间。

## 12. 错误处理

- 表单字段错误：阻止保存，并在对应字段附近显示错误。
- 重复预算：阻止新增，提供编辑已有预算的操作。
- 配置损坏：备份原文件、恢复默认值并显示警告。
- 会话扫描失败：保留上一份成功快照，显示数据过期状态。
- 未知模型：Token 正常统计，费用标记不完整。
- IPC 输入不合法：主进程拒绝请求并返回可展示错误，不抛出未经处理的异常。
- 系统通知失败：保留应用内预警，不中断刷新。
- 内置价格表加载失败：Token 预算继续工作，所有费用标记为未计价。

- 自然日、周一开始的自然周、自然月边界。
- 跨月、跨年和本机时区场景。
- 项目路径规范化及预算唯一键。
- 全局和项目预算匹配。
- Token 与费用限额独立启用。
- 模型价格合并、别名匹配及用户覆盖。
- 缓存输入计价、输出计价和推理 Token 防重复。
- 未知模型和部分未计价状态。
- 默认及自定义阈值。
- 通知去重和新周期重置。

### 13.2 解析与扫描测试

- 单模型会话的用量切片。
- 会话内模型切换。
- 只有累计总量时的兜底切片。
- 无法归属模型时进入未计价分组。
- 增量与累计记录不会重复统计。
- 文件缓存处理新增、修改、删除和未变化文件。
- 并发刷新只执行一个扫描任务。

### 13.3 存储与 IPC 测试

## 14. 验收标准

- 用户可以分别创建全局和项目的日、周、月预算。
- 每条预算可以只设置 Token、只设置费用或同时设置二者。
- 预算使用量严格按本机自然周期和项目范围计算。
- 多模型会话按 Token 发生时的模型分别计价。
- 未知模型不产生猜测费用，并能从预算页面补充价格。
- 默认 80% 和 100% 阈值生效，用户可以全局修改。
- 同一自然周期内相同阈值的系统通知不会重复发送。
- 应用每 60 秒及窗口聚焦时刷新，重复触发不会并发扫描。
- 预算和价格配置在应用重启后保留。
- 配置损坏、扫描失败、未知模型或通知失败时，应用仍可继续使用并展示明确状态。
- 预算页面、右侧抽屉和模型价格页与现有 Lumo 风格保持一致。
