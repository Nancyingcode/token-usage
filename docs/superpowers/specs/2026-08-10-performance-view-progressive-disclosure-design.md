# 性能页概览与渐进式详情设计

## 1. 背景

当前性能页按“缓存效率、费用效率、活跃时段、回合错误率”的顺序直接展开全部内容。缓存、费用和错误卡片都包含汇总指标、构成、趋势及明细，页面因此需要较长的纵向滚动；用户进入页面后无法先快速判断整体状态，再决定查看哪一类诊断信息。

现有两列网格还存在布局不平衡：缓存、费用和错误卡片跨越全部列，活跃时段卡片只占一列，桌面宽度下会在其右侧留下空白。四类指标的主值字号和视觉权重也不一致，高峰时段缺少与其他指标同等级的首屏摘要。

本次调整聚焦第一轮信息架构优化：增加常驻 KPI 概览，将详细诊断收纳到单一标签详情区，并使活跃时段在详情状态下使用完整内容宽度。

## 2. 目标

1. 在性能页首屏常驻展示缓存命中率、有效单位成本、高峰时段和回合错误率四个 KPI。
2. 用户无需阅读完整趋势和明细即可判断当前所选时间范围的主要状态。
3. 缓存、费用、活跃时段和可靠性详情通过标签切换，同一时间只渲染一个详情面板。
4. 活跃时段详情占据完整内容宽度，不再产生半行空白。
5. 复用现有聚合结果、格式化工具和无障碍标签组件，不改变指标计算口径。
6. 在桌面、窄窗口和中英文界面中保持清晰、可键盘操作的布局。

## 3. 非目标

- 不新增“较上一周期”变化，因为当前 `UsageSummary` 没有同时提供上一周期数据。
- 不为缓存命中率、单位成本或错误率引入好坏阈值，也不猜测业务目标。
- 不改变缓存率、费用、活跃时段或回合错误率的计算逻辑。
- 不新增会话跳转、成本优化跳转、错误筛选、抽屉或弹窗。
- 不重构各详情卡内部的图表、tooltip、键盘数据点导航或错误列表。
- 不在本轮合并重复 CSS 规则或进行性能页之外的样式整理。
- 不修改 Electron 主进程、preload、IPC、持久化或 Codex 会话文件。

## 4. 信息架构

性能页从上到下分为三部分：

1. 页面标题与当前说明。
2. 四张常驻 KPI 概览卡。
3. 详情标签与当前选中的详情面板。

布局示意：

```text
性能
查看缓存效率、费用、活跃时段和应用错误

[缓存命中率] [有效单位成本] [高峰时段] [回合错误率]
[   主值   ] [    主值    ] [  主值  ] [    主值    ]
[ 辅助说明 ] [  辅助说明  ] [辅助说明] [  辅助说明  ]

[缓存] [费用] [活跃时段] [可靠性]
┌──────────────────────────────────────────────┐
│ 当前标签对应的完整详情                        │
└──────────────────────────────────────────────┘
```

默认选中“缓存”标签，延续当前页面的阅读顺序。切换全局时间范围或语言时保持当前标签；离开性能页后是否保留标签不属于本次持久化范围，组件重新挂载时恢复默认标签。

## 5. KPI 概览

### 5.1 共同结构

四张概览卡使用统一的语义和视觉结构：

- 指标名称；
- 一个高权重主值；
- 一行辅助数据；
- 必要时显示文本状态，但不只依赖颜色表达状态。

概览卡是只读信息，不伪装成按钮，也不承担详情标签的选择行为。详情切换由下方标准标签控件负责，避免卡片点击语义与标签键盘模型重复。

### 5.2 缓存命中率

- 主值：现有 `CacheEfficiency.percentage`。
- 辅助数据：缓存输入 Token / 总输入 Token。
- 无可计算输入时主值显示 `—`，不显示虚假的 `0%`。
- 数据不一致时保留简短文本状态；完整原因仍在缓存详情中展示。

### 5.3 有效单位成本

- 主值：现有 `CostEfficiency.unitCostUsdPerMillion`，单位为每百万 Token。
- 辅助数据：已计价或估算费用，以及定价覆盖率。
- 无可计价 Token 时主值显示 `—`。
- 存在未计价 Token 时明确显示“计价不完整”；存在兜底价格但无未计价 Token 时显示“包含未知模型假设”。
- 概览标题使用“有效单位成本”，避免把费用总额误称为效率主指标；现有详情卡标题与内部结构本轮保持不变。

### 5.4 高峰时段

- 主值：现有 `HourlyActivity.peakHour` 的本地小时范围。
- 辅助数据：该小时 Token 占比和 Token 数量。
- 没有可分配的活动时主值显示 `—`，辅助说明区分“暂无 Token 活动”和“时间无效、无法按小时分配”。

### 5.5 回合错误率

- 主值：现有 `ErrorRateDetail.errorRate`。
- 辅助数据：失败回合数，以及成功与失败组成的可判定回合数。
- 无可判定回合时显示 `—`，不显示 `0%`。
- 有失败回合时使用危险色并显示失败文本；真实零错误时使用中性或品牌色，并显示“所选时间范围内没有回合错误”。颜色不是唯一状态表达。

## 6. 渐进式详情

详情区使用现有 `AccessibleTabs`，标签值固定为：

- `cache`：渲染现有 `CacheEfficiencyCard`；
- `cost`：渲染现有 `CostEfficiencyCard`；
- `activity`：渲染包含标题和 `HourlyActivityChart` 的全宽面板；
- `reliability`：渲染现有 `ErrorRateCard`。

标签下方只存在一个可见 `tabpanel`。面板通过 `getTabId` 和 `getTabPanelId` 与当前标签关联，并根据当前标签条件渲染详情组件。未选中的复杂图表和大量可聚焦数据点不保留在 DOM 中，从而减少页面长度和 Tab 顺序，但不改变各图表自身的交互。

切换标签时不增加自动滚动，不把焦点移入图表；焦点继续停留在被选择的标签上。现有 `AccessibleTabs` 的左右方向键、Home 和 End 行为保持不变。

## 7. 组件与状态设计

### 7.1 `PerformanceView`

`PerformanceView` 继续负责构造四个现有视图模型，并新增唯一的本地界面状态 `activeDetail`。该状态由标签交互直接改变，符合项目 React 状态建模规则。

详情渲染使用明确的 `PerformanceDetailKey` 联合类型和具名渲染函数或组件，不在 JSX 中堆叠多层互斥三元表达式。

### 7.2 概览组件

新增性能概览组件，接收已经构造好的缓存、费用、活跃时段和错误视图模型，只负责本地化格式化与展示。建议拆为：

- `PerformanceSummary`：组织四张 KPI 卡；
- `PerformanceSummaryCard`：统一卡片语义、主值、辅助内容和状态样式。

组件 Props 使用明确 interface，不使用 `any`，不复制保存可从视图模型推导的数据。

### 7.3 计算与渲染

本次不合并现有四个聚合函数。可使用 `React.useMemo` 按 `summary`、`pricing` 和 `unknownModelPricing` 缓存构造结果，避免仅因标签切换重复扫描会话数据。缓存不改变数据口径，也不修改输入对象。

## 8. 视觉与响应式布局

KPI 概览使用自适应网格：

- 宽内容区优先显示四列；
- 空间不足时自然变为两列；
- 窄窗口变为单列；
- 卡片最小宽度通过布局 token 控制，不硬编码业务阈值。

四张 KPI 卡使用统一的标题字号、主值字号、内边距和最小高度。数值使用等宽数字特性以减少宽度跳动。

详情标签位于独立面板上方。标签空间不足时允许横向滚动或按现有 `AccessibleTabs` 响应式规则换行，但标签文字不得截断到无法辨认。当前详情面板始终占满可用宽度，活跃时段不再参与两列网格。

本轮保留各详情卡内部现有响应式规则；如果实施测试发现中间宽度仍产生裁切，只补充性能详情容器所需的最小规则，不扩展为全站响应式重构。

## 9. 国际化与可访问性

新增或调整的可见文案同时维护英文和简体中文资源，包括：

- 四个详情标签；
- 性能概览区域的无障碍名称；
- 有效单位成本概览标题；
- 概览辅助数据与简短状态文案。

金额、百分比和 Token 数量继续使用现有 locale formatter。小时范围沿用活跃时段的本地小时格式。

详情标签使用标准 ARIA tab 模型；`tabpanel` 设置 `role="tabpanel"`、`aria-labelledby` 和稳定 id。KPI 卡使用文章或列表项语义，不进入键盘顺序。状态始终包含可见文字，颜色只作为辅助提示。

## 10. 测试策略

按红—绿—重构执行：

1. 先更新 `PerformanceView` 回归测试，验证页面常驻四张 KPI 卡，默认只显示缓存详情。
2. 添加标签交互测试，验证点击及键盘切换后只渲染对应详情，活跃时段和错误详情不会同时留在 DOM 中。
3. 添加概览边界测试，覆盖正常数据、不可计算缓存率、不可计价费用、无可分配活跃时段、无终态数据和真实零错误。
4. 验证中英文文案以及金额、百分比、数量格式化。
5. 保留并运行缓存、费用、活跃时段和错误卡片现有测试，证明详情内容没有回归。
6. 完成前运行 `npm test`、`npm run typecheck`、`npm run lint`。

本次不修改构建配置、Electron 主进程、preload 或打包配置，因此无需额外执行 `npm run build`。

## 12. 验收标准

1. 性能页首屏常驻展示缓存命中率、有效单位成本、高峰时段和回合错误率四个 KPI。
2. 不可计算状态显示 `—` 和原因，真实零值与数据缺失明确区分。
3. 页面默认只显示缓存详情，用户可通过鼠标和标准标签键盘操作切换四类详情。
4. 任意时刻只渲染一个详情面板，未选中详情的图表和焦点目标不留在 DOM 中。
5. 活跃时段详情使用完整内容宽度，桌面端不再出现右侧空列。
6. 有错误与零错误使用不同的辅助视觉和明确文本，不只依赖颜色。
7. 窄窗口下 KPI 网格和详情标签可用，不出现不可访问的裁切。
8. 英文和简体中文文案完整，金额、百分比和数量遵循当前 locale。
9. 指标计算口径、Codex 会话目录只读约束和本地费用估算声明均保持不变。
10. 全量测试、类型检查和 lint 全部通过。
