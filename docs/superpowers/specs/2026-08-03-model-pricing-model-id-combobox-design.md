# 模型价格 Model ID 组合框设计

## 1. 背景

当前“模型价格”页面在新增价格时使用普通文本框填写 Model ID。用户无法直接从当前价格列表或扫描发现的未计价模型中选择，只能手工复制或输入；页面虽然会单独展示未计价模型，但新增价格抽屉没有复用这些候选。

本次变更把新增价格时的 Model ID 字段改为可输入的下拉组合框。组合框既提供当前模型候选，也允许用户直接输入新的真实 Model ID。完全缺失 Model ID 的用量继续统一显示为一个“未知模型”候选，但不会被错误地保存为名为 `unknown` 的价格条目。

## 2. 目标

- 新增价格时，Model ID 使用支持键盘操作的可输入组合框。
- 下拉候选包含当前合并价格列表中的规范 Model ID。
- 下拉候选包含扫描发现的、具有具体 ID 的未计价模型。
- 价格列表与未计价列表中的相同 Model ID 按现有规范化规则去重。
- 存在完全缺失 Model ID 的用量时，下拉只展示一个统一的“未知模型”项。
- 用户可以直接输入候选之外的新 Model ID，并按现有校验和保存流程新增价格。
- 编辑已有价格时继续锁定 Model ID，不允许借编辑操作把一个价格条目改成另一个模型。

## 3. 非目标

- 不为完全缺失 Model ID 的用量设置统一兜底价格。
- 不把显示文案“未知模型”或字符串 `unknown` 保存成真实 Model ID。
- 不修改价格匹配、别名匹配、费用计算、配置 schema 或主进程保存逻辑。
- 不自动猜测新模型的价格、别名或所属模型系列。
- 不改变模型价格表格中的编辑、恢复默认和删除自定义价格行为。

## 4. 核心语义

### 4.1 候选来源

新增价格组合框从 `pricing` 与 `unpricedModels` 构建候选：

1. `pricing` 中的规范 Model ID；
2. `unpricedModels` 中去除首尾空格后非空的具体 Model ID；
3. 当 `unpricedModels` 存在 `modelId` 缺失或去除首尾空格后为空的记录时，增加一个统一的“未知模型”提示项。

具体 Model ID 使用现有 `normalizeModelId` 规则去重。若同一 ID 同时存在于价格列表和未计价列表，保留价格列表中的展示值。已定价模型与未计价具体模型分别稳定排序，已定价模型在前，未计价具体模型在后；“未知模型”固定放在具体模型之前。

### 4.2 新增与选择

- 选择一个具体 Model ID 后，表单的 `modelId` 更新为该候选值。
- 用户直接修改输入文字时，表单进入自定义 Model ID 状态；候选中不存在该值也可以继续填写价格并保存。
- 选择已定价 Model ID 时，组合框只负责填入 ID，不自动复制或改写价格字段。现有表格的“编辑”按钮仍是修改已有价格的主要入口。
- 提交时继续调用现有 `toPricingOverride` 与 `getPricingFormIssues`；空白、自定义重复和服务端错误仍由现有边界处理。

### 4.3 未知模型

“未知模型”只代表会话用量中完全缺失真实 Model ID 的记录。价格匹配需要真实 Model ID，因此该项作为禁用提示项展示：

- 所有缺失 ID 的摘要统一为一个下拉项，不按记录重复显示；
- 项目使用本地化文案标明“缺少 Model ID，无法添加价格”；
- 键盘导航跳过该项，鼠标不能选中；
- 该项不会写入表单状态，也不会产生价格覆盖记录；
- 对应 Token 继续保留并明确标记为未计价。

若产品未来需要为所有缺失 ID 的用量设置统一价格，应另行设计显式的未知模型价格目标及费用覆盖语义，而不是复用字符串 Model ID。

## 5. 组件与数据流

### 5.1 纯函数候选构建

Renderer 工具层新增纯函数，根据 `pricing` 与 `unpricedModels` 返回不可变候选数组。候选使用显式联合类型区分具体模型与未知模型提示项，避免依赖特殊字符串：

```ts
type PricingModelOption =
  | { kind: 'model'; key: string; modelId: string; pricingState: 'priced' | 'unpriced' }
  | { kind: 'unknown'; key: 'unknown'; disabled: true };
```

该函数不修改输入数组，并复用共享层的 Model ID 规范化逻辑。

### 5.2 组合框

为模型价格表单提供独立的受控组合框组件。预算模块现有组合框包含“所有模型”和预算目标联合类型，不能直接作为价格字段使用；新组件可以复用相同的 ARIA 与键盘交互模式，但不把预算语义带入价格表单。

组件输入包括当前字符串值、候选、字段标签、错误信息和 `onChange`。组件只管理展开状态、显示值与当前高亮索引，不保存业务对象。

### 5.3 表单集成

`ModelPricingView` 将 `pricing` 和 `unpricedModels` 传入新增价格编辑器。新增模式渲染组合框；编辑模式继续渲染只读 Model ID 字段。由未计价模型行进入“添加价格”时，具体 ID 仍作为初始值；缺失 ID 的行不显示添加价格按钮。

此变更只发生在 Renderer，不增加文件系统访问，也不改变类型化 IPC 边界。

## 6. 交互与可访问性

- 输入元素使用 `role="combobox"`，并提供 `aria-expanded`、`aria-controls`、`aria-activedescendant` 和 `aria-autocomplete="list"`。
- 候选容器和候选项分别使用 `listbox` 与 `option` 语义。
- 支持输入、上下方向键移动、Enter 选择、Escape 关闭和 Tab 正常离开。
- 禁用的“未知模型”项使用 `aria-disabled="true"`，方向键导航时跳过。
- 当前选择、高亮、已定价/未计价和禁用状态不能只依赖颜色表达；候选项提供本地化辅助文字。
- 点击候选和键盘选择产生一致的表单状态。
- 新增或修改的用户可见文案同时维护英文和简体中文资源。

## 7. 错误处理

- 自定义输入为空时继续显示现有“Model ID 必填”校验错误。
- 选择候选不会绕过价格字段的非负有限数校验。
- 保存失败时抽屉保持打开，并继续使用现有字段级或表单级错误展示。
- “未知模型”禁用项不触发表单错误；其不可定价原因直接在候选中说明。
- 组合框候选为空时仍允许自由输入新 Model ID。

## 8. 测试策略

### 8.1 候选构建测试

- 包含已定价模型与未计价具体模型。
- 规范化去重后优先保留价格列表展示 ID。
- 具体候选稳定排序且不修改输入数组。
- 多个缺失或空白 Model ID 只生成一个“未知模型”项。
- 没有缺失 ID 时不生成“未知模型”项。

### 8.2 组合框测试

- 点击和键盘选择具体模型。
- 输入候选外的新 Model ID。
- Escape、Tab、方向键与 ARIA 属性正确。
- 键盘导航跳过禁用的“未知模型”项，点击也不改变值。
- 字段错误通过 `aria-invalid` 和 `aria-describedby` 暴露。

### 8.3 页面集成测试

- 新增价格抽屉展示组合框及当前候选。
- 从未计价具体模型进入时正确预填 ID。
- 编辑已有价格时 Model ID 仍只读。
- 英文和简体中文文案均可渲染。

### 8.4 完整验证

实现完成前运行受影响的最小测试集；声称完成前运行：

```text
npm test
npm run typecheck
npm run lint
```

本次不修改构建配置、Electron 主进程、preload 或打包配置，因此不强制增加 `npm run build`。

## 9. 验收标准

- 用户新增模型价格时可以从当前已定价和未计价具体模型中选择，也可以直接输入新 Model ID。
- 相同模型不会因大小写或首尾空格差异重复出现在候选中。
- 完全缺失 ID 的用量只显示一个不可定价的“未知模型”候选，不会生成无效价格覆盖。
- 未知模型 Token 继续保留并明确标记为未计价。
- 编辑已有价格、别名维护、价格校验和恢复操作保持现有行为。
- 组合框可完全使用键盘操作，新增文案具备英文和简体中文版本。
