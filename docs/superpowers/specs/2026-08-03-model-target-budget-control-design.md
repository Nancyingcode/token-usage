# 按模型目标控制预算设计

## 1. 背景

当前预算策略只能按全局或项目范围以及自然日、周、月周期控制 Token 和本地估算费用，不能单独约束某个模型。模型价格列表已经维护规范模型 ID、别名和扫描发现的未定价模型；用量切片也允许 `modelId` 缺失，但预算创建流程尚未使用这些信息。

本次变更为预算增加模型目标，使用户既能保留覆盖所有模型的汇总预算，也能为单个模型或日志中完全缺失 `modelId` 的用量设置独立预算。预算仍然只负责统计、预警和通知，不会阻止 Codex 运行。

## 2. 目标

- 保留现有“所有模型”预算能力，并让旧预算无损迁移为该目标。
- 添加预算或编辑预算时，通过可输入的下拉组合框选择模型目标。
- 下拉包含当前价格列表中的模型、扫描发现的未定价具体模型、“所有模型”和统一的“未知模型”。
- 允许直接输入任意新模型 ID；即使当前没有对应用量，也可以保存预算。
- “未知模型”仅代表日志切片完全缺失 `modelId`，不合并带有具体但未识别 ID 的模型。
- 具体已定价模型预算同时统计该价格条目的规范模型 ID 和全部别名。
- 未知或未定价模型继续保留 Token，不猜测价格，并明确标记费用数据不完整。

## 3. 非目标

- 不自动为新增模型补充价格。
- 不把所有未定价模型合并为一个预算目标。
- 不改变价格覆盖、费用计算公式、阈值规则或通知去重规则。
- 不新增按模型筛选预算列表的页面筛选器。
- 不依据模型名称猜测别名、价格或模型归属。

## 4. 核心语义

### 4.1 模型目标

预算策略使用显式判别联合表示模型目标：

```ts
type BudgetModelTarget =
  | { kind: 'all' }
  | { kind: 'unknown' }
  | { kind: 'model'; modelId: string };
```

- `all`：统计范围、项目和周期内的全部用量切片。
- `unknown`：只统计 `modelId` 缺失或去除首尾空格后为空的用量切片。
- `model`：统计与具体模型匹配的用量切片。

显示文案“所有模型”和“未知模型”不作为持久化 ID。即使用户新增名为 `Unknown model` 的价格条目或具体模型 ID，它也不会被用于给缺失 `modelId` 的日志计价。

### 4.2 具体模型匹配

具体模型匹配忽略首尾空格和大小写。若目标 ID 能在当前合并价格表中匹配到规范模型 ID 或别名，则该预算统计该价格条目的规范 ID 和全部别名。

例如价格条目以 `gpt-5.6-sol` 为规范 ID，并包含别名 `gpt-5.6` 时，选择 `gpt-5.6-sol` 的预算同时计入两种日志 ID。用户在组合框中直接输入已知别名时，保存边界将它规范化为当前价格条目的规范模型 ID。

若输入 ID 不在价格表中，则保留去除首尾空格后的原始 ID，并按忽略大小写的精确 ID 匹配。此类具体 ID 不归入 `unknown`。

### 4.3 预算唯一性

预算业务键由以下字段组成：

```text
范围 + 规范化项目路径 + 周期 + 规范化模型目标
```

模型目标键分别为稳定的 `all`、`unknown` 或忽略大小写的具体模型 ID。同一范围、项目和周期可以同时存在“所有模型”“未知模型”和多个具体模型预算，但不能重复创建同一模型目标的预算。

保存时已知别名会先转换为规范模型 ID，因此不能通过规范 ID 和别名创建两条重叠预算。若价格配置在预算保存后发生变化并使原本不同的 ID 成为别名，本次变更不自动合并或删除已有预算；评估仍按最新价格条目的别名关系执行。

## 5. 数据模型与持久化

### 5.1 类型变更

`BudgetPolicyInput` 和 `BudgetPolicy` 增加必需的 `modelTarget: BudgetModelTarget`。Renderer、Preload、IPC 和 Electron 主进程继续通过共享类型传递预算输入，不引入 Renderer 文件系统访问。

共享层提供无副作用的纯函数，用于：

- 规范化具体模型 ID。
- 根据合并价格表解析规范模型及别名。
- 构建模型目标业务键。
- 判断用量切片是否匹配模型目标。
- 构建并去重组合框候选项。

这些函数不修改输入对象。

### 5.2 配置迁移

预算配置 schema 从版本 1 升级到版本 2。加载版本 1 配置时：

1. 保留预算 ID、范围、项目、周期、限额和时间戳。
2. 为每条旧预算补充 `{ kind: 'all' }`。
3. 保留阈值、价格覆盖和通知记录。
4. 将迁移后的内存配置交给现有运行时；下一次正常保存时写成新 schema。

新 schema 中每条预算都必须显式包含合法 `modelTarget`。未来版本仍沿用现有拒绝覆盖策略；非法的新版本模型目标按现有损坏配置策略备份原文件并恢复默认配置，不修改 Codex 会话目录。

### 5.3 保存规范化

Electron 主进程在持久化预算前执行最终校验和规范化：

- `all` 和 `unknown` 原样保存。
- `model.modelId` 去除首尾空格后必须非空。
- 能匹配当前价格表规范 ID 或别名时，保存规范模型 ID。
- 未定价的新 ID 保存去除首尾空格后的值。
- 重复检查使用规范化后的模型目标。

Renderer 的规范化只用于即时交互，不能替代主进程校验。

## 6. 预算评估数据流

预算评估继续使用当前自然周期边界。每条策略的切片筛选顺序为：

1. 按切片时间筛选当前自然周期。
2. 按全局或规范化项目路径筛选范围。
3. 按 `modelTarget` 筛选模型。
4. 对筛选结果汇总 Token 并调用现有费用计算函数。
5. 使用现有阈值生成严重级别、应用内预警和系统通知。

三种目标的行为如下：

| 模型目标 | 纳入的切片 | 费用行为 |
| --- | --- | --- |
| 所有模型 | 全部切片 | 已定价部分正常汇总；存在未定价 Token 时标记不完整 |
| 未知模型 | 仅缺失或空 `modelId` 的切片 | Token 正常汇总；存在 Token 时费用不猜测并标记不完整，无用量时显示完整的 0 |
| 具体模型 | 规范 ID、其全部别名，或未定价 ID 的忽略大小写精确匹配 | 有价格时正常计算；无价格时保留 Token 并标记不完整 |

全局未定价模型摘要继续按当前规则保留带具体 ID 的未定价模型，并为缺失 ID 的用量提供单独的“未知模型”摘要。具体未定价模型之间不合并。

## 7. 组合框交互

### 7.1 候选项

预算抽屉中的“模型 ID”字段使用可输入的组合框。候选项顺序为：

1. 所有模型。
2. 未知模型。
3. 合并价格列表中的规范模型 ID。
4. 当前扫描发现的、尚未定价但具有具体 ID 的模型。

具体模型选项按规范化 ID 去重并稳定排序。价格条目的别名不重复显示为独立选项；用户仍可直接输入别名，保存时将其解析为规范 ID。缺失 `modelId` 的扫描摘要只产生一个“未知模型”固定项。

### 7.2 输入与选择

- 选择固定的“所有模型”或“未知模型”选项时，表单保存对应判别联合分支。
- 选择具体候选项时，表单保存 `{ kind: 'model', modelId }`。
- 用户开始自由输入后，表单进入具体模型分支。
- 仅输入空格时阻止保存，并在字段附近显示双语错误。
- 编辑预算时回显当前目标；旧预算迁移后显示“所有模型”。
- 输入与候选匹配忽略大小写和首尾空格，但列表展示保留规范或扫描到的可读 ID。

### 7.3 可访问性

组合框遵循 ARIA combobox 模式：

- 输入控件声明 `role="combobox"`、展开状态、候选列表关联和当前活动项。
- 候选容器及条目使用 `listbox` 和 `option` 语义。
- 支持文字输入、上下方向键移动、Enter 选择、Escape 关闭和 Tab 正常离开。
- 鼠标与键盘选择产生相同状态。
- 当前高亮、已选择状态和字段错误不只依靠颜色表达。
- “所有模型”“未知模型”、字段标签、帮助及错误文案同时维护英文和简体中文资源。

## 8. 预算列表展示

预算列表增加“模型”列：

- `all` 显示本地化的“所有模型”。
- `unknown` 显示本地化的“未知模型”。
- `model` 显示持久化的规范或自定义模型 ID。

现有全局/项目分组、范围和周期筛选保持不变。状态、Token 进度、费用进度以及编辑和删除操作不改变语义。

## 9. 校验与错误处理

- 具体模型目标缺少非空 ID 时返回模型字段校验错误并阻止保存。
- 非法判别值、额外必需字段缺失或不合法持久化结构不能被断言为有效配置。
- 重复业务键继续返回现有重复预算错误。
- 保存失败时保持抽屉打开，并在字段或表单附近显示可翻译错误。
- 未定价模型不是保存错误；Token 预算正常工作，存在未定价 Token 时费用预算明确显示不完整。
- 用量扫描失败时继续保留上一份成功快照和模型候选项，并显示现有过期数据提示。

## 10. 测试策略

### 10.1 共享领域测试

- 三种模型目标的运行时校验和不可变性。
- 模型目标业务键的大小写、空格、项目路径及周期边界。
- 规范模型 ID 和别名共同计入具体模型预算。
- 用户输入已知别名时规范化为规范模型 ID。
- 未定价具体模型只匹配自己的 ID，不进入“未知模型”。
- 缺失或空 `modelId` 的切片只进入“未知模型”和“所有模型”。
- 所有模型预算保持当前汇总结果。
- 未定价具体模型和未知模型的 Token 保留及费用不完整状态。

### 10.2 存储与运行时测试

- 旧 schema 配置无损迁移，所有旧预算变为“所有模型”。
- 新 schema 的读写往返及非法模型目标拒绝。
- 规范 ID、别名和大小写变体的重复预算拒绝。
- 同一范围、项目和周期下不同模型目标可以共存。
- 新模型预算在没有用量时保存成功且进度为 0。
- 保存、编辑和通知流程继续使用原策略 ID。

### 10.3 Renderer 测试

- 组合框包含固定项、价格模型和扫描发现的未定价具体模型。
- 候选项去重与稳定顺序。
- 自由输入、固定项选择、编辑回显和空输入校验。
- 方向键、Enter、Escape 和 ARIA 属性。
- 预算列表正确显示三种模型目标。
- 英文和简体中文资源结构一致且组件不硬编码用户可见文案。

### 10.4 完整验证

实现完成前先运行受影响的最小测试集；声称完成前运行：

```text
npm test
npm run typecheck
npm run lint
npm run build
```

本次修改涉及共享配置结构、Electron 主进程运行时和 Renderer，因此完整验证包含构建。

## 11. 验收标准

- 用户创建预算时可以选择“所有模型”“未知模型”、当前模型，或直接输入新模型 ID。
- 旧预算升级后行为与升级前一致，并显示为“所有模型”。
- 具体模型预算统计规范 ID 和别名；未知模型预算只统计完全缺失模型 ID 的日志。
- 带有具体未定价 ID 的用量不会被合并进“未知模型”。
- 同一范围和周期可以创建不同模型目标的预算，重复目标被阻止。
- 未定价数据不会产生猜测费用，Token 数据不会丢失。
- 组合框可用键盘完整操作，所有新增文案均提供英文和简体中文。
