# 自定义用量数据路径设计

## 背景

应用当前固定扫描 `~/.codex/sessions`，设置页只展示该路径。用户需要在设置页自定义数据路径，同时保持未配置时的默认路径和现有扫描行为不变。

## 目标

- 设置页允许输入并保存 Codex 会话目录。
- 没有用户配置时继续使用现有 `~/.codex/sessions` 默认目录。
- 保存成功后立即以新目录执行完整扫描，刷新预算与成本优化数据。
- 提供“恢复默认路径”操作。
- 配置只保存在 Electron `userData` 目录，不修改、移动或上传 Codex 会话数据。
- 设置页在默认目录不可读、目录为空或最近一次扫描失败时仍可访问和修改路径。

## 非目标

- 不移动或复制现有会话文件。
- 不修改 Codex 自己的配置或环境变量。
- 不支持同时聚合多个会话目录。
- 不把自定义路径解释为 Codex Home；用户选择的是包含 JSONL 会话文件的 `sessions` 目录。

## 用户体验

设置页的数据路径卡片改为表单：

- 只读路径框显示当前生效或刚通过系统文件夹选择器选择的绝对目录，不接受键盘输入。
- “选择文件夹”打开 Electron 原生目录选择器；取消选择不改变草稿或当前配置。
- “保存路径”在输入发生变化且当前没有提交时可用。
- “恢复默认路径”把配置恢复为 `~/.codex/sessions`；当前已是默认路径时禁用。
- 保存期间禁用相关控件并显示进行中状态。
- 成功后显示简短成功提示，并立即展示新扫描结果。
- 路径为空、不是绝对路径、不存在、不是目录或不可读时，在输入框附近显示本地化错误；原路径和最后一次成功扫描结果保持不变。

目录选择结果仍由主进程校验并使用 Node 路径工具规范化，Renderer 返回的任意字符串都不能绕过绝对路径、目录类型和可读性校验。

## 数据与持久化

新增版本化的 `usage-data-path.json`，写入 Electron `userData` 目录。配置只保存自定义目录：

```json
{
  "schemaVersion": 1,
  "sessionsDir": "D:\\Codex\\sessions"
}
```

- 文件不存在或内容无效时回退到现有默认目录。
- 恢复默认路径时保存“无自定义目录”的配置状态，避免把机器相关的默认绝对路径固化为用户配置。
- 写入使用临时文件加原子替换；写入失败时不切换运行时路径。

## 主进程职责

新增用量数据路径服务，集中负责：

1. 维护默认路径与当前生效路径。
2. 校验 Renderer 传入值是非空字符串、绝对路径、存在的可读目录。
3. 持久化自定义配置。
4. 切换扫描器使用的目录并触发一次新的扫描。

Renderer 不直接访问文件系统。IPC 返回结构化错误码，界面将其映射为中英文文案，不暴露主进程中的任意错误或私有配置路径。

会话索引路径按会话目录的父目录推导为 `session_index.jsonl`。索引缺失继续沿用当前容错行为：Token 会话仍可扫描，只是不补充任务名称。

## 扫描与一致性

用量运行时保存当前会话目录，每次扫描开始时捕获该目录。路径更新会等待正在执行的刷新结束，再以新目录启动一次独立刷新，避免复用旧目录的在途扫描结果。

目录变化时，扫描周期把 `requiresFullRebuild` 设为 `true`。因此：

- 扫描器文件缓存不会把旧目录文件带入新结果。
- 预算运行时收到新完整结果。
- 成本优化运行时按新目录重建索引；现有目录不匹配保护仍保留。

如果新目录验证、持久化或首次扫描失败，服务会恢复原配置和原运行时目录；界面继续保留最后一次成功结果并显示路径保存错误。只有新目录完成一次扫描后才视为切换成功，避免持久化配置、运行时和界面显示互相不一致。

## Renderer 状态

应用启动时并行读取数据路径设置和扫描结果。路径设置独立于 `UsageScanResult`，确保扫描失败时设置页仍有可编辑的当前路径与默认路径。

`SettingsView` 接收路径状态及保存、恢复回调，自身只管理草稿输入、提交状态和字段错误。成功的 IPC 响应由 `App` 更新路径状态和扫描结果；用量订阅仍负责后台刷新。

`AppContent` 在设置路由下优先渲染设置页，不受全局扫描的 loading、error、empty 或 period-empty 分支阻断。警告列表在没有成功扫描结果时显示为空，并由页面上的路径错误承担反馈。

## 国际化、可访问性与安全

- 所有新增标签、按钮、状态和错误同时维护英文与简体中文。
- 输入框有显式标签，错误通过 `aria-describedby` 与 `aria-invalid` 关联。
- 保存和恢复操作使用原生按钮，可键盘操作。
- 状态不只依赖颜色，错误和成功均有文本。
- 主进程只读取用户指定目录；不写入、删除或上传其中的数据。

## 测试策略

- 存储测试：缺失/损坏配置回退默认值，原子保存自定义值，恢复默认值。
- 服务测试：拒绝空值、相对路径、文件和不可读目录；成功时先持久化再切换并刷新。
- 运行时测试：目录切换等待在途扫描，并为新目录生成全量重建周期。
- IPC/preload 类型测试：get、update、reset 通道完整注册并转发结构化结果。
- Renderer 测试：路径表单、本地化、键盘可用属性、保存/恢复、错误状态，以及扫描失败时设置页仍可访问。
- 完成前运行完整测试、类型检查、lint；由于修改 Electron 主进程、preload 和构建输入，额外运行 build。
