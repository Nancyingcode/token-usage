# 性能页费用效率详情设计

## 1. 背景与问题

当前“性能”页的“费用效率”卡片只展示一个已计价费用总额，下面的折线却使用 `UsageDay.totalTokens` 绘制。用户无法从卡片中判断：

- 费用覆盖了多少 Token，是否存在未知模型或兜底价格；
- 相同 Token 用量下，当前模型和输入/输出结构是否让单位成本升高；
- 普通输入、缓存输入和输出分别贡献了多少费用；
- 哪一天费用较高，以及高费用来自用量增加还是单位成本增加。

现有折线表达的是 Token 用量而非费用，但没有图例或坐标说明，容易被误读为费用趋势。本次变更将该卡片升级为可解释的费用效率详情，并继续服从性能页的全局时间范围筛选。

所有费用仍是基于本地 Codex 会话与当前价格表生成的本地估算，不代表 OpenAI 实际账单。未知模型价格不得猜测；没有可用价格的 Token 必须保留并明确标记为未计价。

## 2. 目标

费用效率详情需要同时回答以下问题：

1. 当前所选范围内已估算出的费用是多少；
2. 每百万已计价 Token 的有效单位成本是多少；
3. 平均每个会话的已计价费用是多少；
4. 精确定价、未知模型兜底定价和未计价 Token 各占多少；
5. 普通输入、缓存输入和输出分别产生了多少已计价费用；
6. 最近最多 30 个有数据日期的费用如何变化；
7. 某一天的费用、单位成本、已计价 Token 和定价覆盖率分别是多少。

本次不替代“成本优化”页面的模型对比、异常检测、预测和节省建议；性能页只提供紧凑、可解释的费用健康度摘要。

## 3. 指标定义

### 3.1 已计价费用

沿用 `src/shared/pricing.ts` 的现有计算口径：

```text
普通输入费用 = max(inputTokens - cachedInputTokens, 0) × 普通输入单价
缓存输入费用 = cachedInputTokens × 缓存输入单价
输出费用 = outputTokens × 输出单价
已计价费用 = 普通输入费用 + 缓存输入费用 + 输出费用
```

单价均按每百万 Token 折算。`reasoningOutputTokens` 是输出 Token 的补充观测值，不再次单独计费，避免与 `outputTokens` 重复计算。

“总费用”只展示现有 `pricedCostUsd`。当存在未计价 Token 时，文案使用“已计价费用”，不得暗示该值是完整总费用。

### 3.2 定价覆盖

```text
已计价 Token = totalTokens - unpricedTokens
精确定价 Token = 已计价 Token - assumedTokens
定价覆盖率 = 已计价 Token / totalTokens × 100%
精确定价率 = 精确定价 Token / totalTokens × 100%
兜底定价率 = assumedTokens / totalTokens × 100%
未计价率 = unpricedTokens / totalTokens × 100%
```

所有 Token 数限制为非负值，百分比限制在 `0%–100%`。当 `totalTokens` 为 `0` 时，覆盖率为 `null`，界面显示 `—`，而不是伪造 `0%`。

兜底价格只适用于现有计价逻辑认可的无模型 ID 用量；具有未知模型 ID 且没有价格的 Token 继续保持未计价。卡片同时列出未计价模型 ID，帮助用户理解覆盖缺口。

### 3.3 有效单位成本

```text
有效单位成本 = pricedCostUsd / pricedTokens × 1,000,000
```

分母只使用已计价 Token，不能把未计价 Token 当作零费用加入分母，否则会人为压低单位成本。该指标综合反映模型单价、普通输入/缓存输入/输出结构，但不是模型价格本身。

当 `pricedTokens` 为 `0` 时，有效单位成本为 `null`，显示 `—` 和“暂无已计价 Token”。

### 3.4 会话均费

```text
会话均费 = pricedCostUsd / 当前筛选范围内的会话数
```

该值描述已计价费用在所有可见会话上的平均分布。存在未计价 Token 时，标签使用“已计价会话均费”，并与定价不完整提示同时展示。当会话数为 `0` 时显示 `—`。

### 3.5 费用构成

费用构成按普通输入、缓存输入和输出三类展示，只聚合能够精确或按现有兜底假设计价的用量切片。三项费用之和必须与 `pricedCostUsd` 一致；未计价用量不生成虚构的分类费用。

每个分类同时展示美元金额和占已计价费用的百分比。`pricedCostUsd` 为 `0` 时，分类百分比为 `null` 并显示空轨道。

### 3.6 每日趋势

每日数据按用量切片的本地日期聚合，沿用 `buildDailyCostEstimates` 的日期边界和排序，最多展示最近 30 个有数据日期。

趋势图的主图形展示“每日已计价费用”，不再复用 `summary.byDay.totalTokens`。每个日期的详情同时展示：

- 已计价费用；
- 有效单位成本；
- 已计价 Token；
- 定价覆盖率；
- 是否包含兜底定价；
- 未计价 Token 与未计价模型 ID。

主图使用从零开始的统一费用刻度，避免截断纵轴夸大微小变化。有效单位成本放入常驻汇总和逐日详情，不引入容易误解的双纵轴。

## 4. 界面设计

### 4.1 卡片布局

费用效率卡片在性能指标网格中改为跨两列的宽卡片；窄屏下自然回落为单列。缓存详情、活跃时段和错误率保持现有顺序与统计口径。

卡片从上到下分为四部分：

1. **汇总区**
   - 标题“费用效率”；
   - 主值为“估算费用”或存在未计价数据时的“已计价费用”；
   - 固定说明“基于本地会话与当前价格表的估算，不是实际账单”；
   - 三个常驻数据项：有效单位成本、会话均费、定价覆盖率。
2. **定价覆盖区**
   - 水平堆叠条展示精确定价、兜底定价和未计价 Token 占比；
   - 文本图例同时展示名称、Token 数和百分比；
   - 有未计价模型时列出模型 ID；颜色不能作为覆盖状态的唯一表达。
3. **费用构成区**
   - 普通输入、缓存输入和输出三项横向构成条或并列明细；
   - 每项常驻展示金额与占已计价费用比例；
   - 明确标注该构成只覆盖已计价费用。
4. **每日费用趋势**
   - 展示最近最多 30 个有数据日期的已计价费用；
   - 横轴常驻显示首日和末日，只有一个日期时只显示一次；
   - 每个日期使用可聚焦的数据点或柱形，鼠标悬停或键盘聚焦后显示完整逐日详情；
   - 图例、图表名称和详情文案明确写“费用”，不再让 Token 折线冒充费用趋势。

### 4.2 状态与降级

#### 全部数据均已精确定价

- 主值标签为“估算费用”；
- 定价覆盖率为 `100%`；
- 覆盖条全部为“精确定价”；
- 不显示警告。

#### 包含兜底定价但没有未计价 Token

- 主值仍为完整估算费用；
- 显示“包含未知模型假设”；
- 覆盖条区分精确定价与兜底定价；
- 单位成本、会话均费、构成和趋势均可展示，但逐日详情标明兜底定价状态。

#### 存在未计价 Token

- 主值标签改为“已计价费用”；
- 显示未计价 Token 数和模型 ID；
- 单位成本只除以已计价 Token；
- 会话均费标签改为“已计价会话均费”；
- 费用构成明确说明只覆盖已计价部分；
- 趋势中有部分未计价的日期仍展示其已计价费用，并在详情中标记覆盖缺口；
- 完全没有已计价 Token 的日期显示为“费用不可计算”，不得绘制为真实的 `$0` 费用点。

#### 有会话但没有 Token 或费用

- 主值显示格式化的 `$0`；
- 有效单位成本和定价覆盖率显示 `—`；
- 构成区显示空轨道；
- 趋势区显示“所选时间范围内暂无可计价用量”。

性能页整体没有会话时仍由现有上层页面处理，本次不新增第二套页面级空状态。

### 4.3 文案与格式化

新增或调整的用户可见文案同时维护英文和简体中文资源，不在 React 组件中硬编码。

- 美元金额使用现有 `formatUsd`；
- Token 数使用现有 locale number/compact-number formatter；
- 百分比使用现有 `formatPercent`；
- 日期使用现有本地化日期格式；
- 每百万 Token 的单位成本显示为“`$X.XX / 1M Token`”，中英文采用等价表达。

中文核心文案建议如下：

- 估算费用 / 已计价费用
- 有效单位成本
- 每百万已计价 Token
- 会话均费 / 已计价会话均费
- 定价覆盖率
- 精确定价 / 兜底定价 / 未计价
- 费用构成
- 普通输入 / 缓存输入 / 输出
- 每日费用趋势
- 本地估算，不代表实际账单
- 暂无已计价 Token

## 5. 组件与数据流

新增 Renderer 纯函数模块 `src/renderer/utils/costEfficiency.ts`，将当前筛选后的 `UsageSummary`、`ModelPricingEntry[]` 和可选 `UnknownModelPricing` 转换为稳定的费用效率视图模型。建议结构如下：

```ts
interface CostEfficiencyCoverage {
  totalTokens: number;
  pricedTokens: number;
  exactPricedTokens: number;
  assumedTokens: number;
  unpricedTokens: number;
  percentage: number | null;
  exactPercentage: number | null;
  assumedPercentage: number | null;
  unpricedPercentage: number | null;
  unpricedModelIds: string[];
}

interface CostEfficiencyBreakdownItem {
  kind: 'regular-input' | 'cached-input' | 'output';
  costUsd: number;
  percentage: number | null;
}

interface CostEfficiencyDay {
  date: string;
  pricedCostUsd: number;
  unitCostUsdPerMillion: number | null;
  coverage: CostEfficiencyCoverage;
}

interface CostEfficiency {
  pricedCostUsd: number;
  unitCostUsdPerMillion: number | null;
  averageSessionCostUsd: number | null;
  coverage: CostEfficiencyCoverage;
  breakdown: CostEfficiencyBreakdownItem[];
  days: CostEfficiencyDay[];
}
```

纯函数负责：

- 复用共享价格匹配语义，不能在 Renderer 中另写一套模型匹配规则；
- 计算汇总、分类费用、覆盖率、有效单位成本和会话均费；
- 按本地日期生成最近最多 30 个逐日视图模型；
- 保留 `null` 与真实 `$0`、`0%` 的区别；
- 限制异常数据产生的负数或越界百分比；
- 不修改传入的 summary、pricing 或其中数组。

为避免费用构成重复实现计价公式，可在 `src/shared/pricing.ts` 中新增返回普通输入、缓存输入和输出费用的纯函数，并让现有 `calculateUsageCost` 基于该函数求和。这样单一计价口径继续由共享层维护，现有调用者行为不变。

新增独立组件 `src/renderer/components/CostEfficiencyCard.tsx`，只消费费用效率视图模型，负责本地化格式化、覆盖条、费用构成、每日趋势、详情浮层和键盘焦点状态。`PerformanceView` 只负责调用聚合函数并组合卡片，同时删除当前错误的 Token `MiniLine`。

无需新增主进程、IPC、preload、持久化字段或扫描逻辑；所有数据来自当前已传入性能页的 `summary`、`pricing` 和 `unknownModelPricing`。

## 6. 交互与可访问性

- 趋势数据点或柱形可通过键盘聚焦，焦点样式清晰可见；
- 鼠标悬停和键盘聚焦共享同一详情状态，离开或失焦后关闭详情；
- 详情浮层只补充视觉信息，完整逐日数值同时存在于命中目标的 `aria-label`；
- 覆盖条和费用构成均提供文字图例、金额/Token 数和百分比，不以颜色作为唯一表达；
- 未计价状态使用文本与图标/边框辅助表达，不只改变颜色；
- 尊重 `prefers-reduced-motion`，禁用非必要过渡；
- 小屏允许趋势图横向滚动，汇总和图例自动换行，不压缩到不可读宽度。

## 7. 测试策略

按红—绿—重构执行：

1. 扩展共享计价测试，先覆盖普通输入、缓存输入、输出费用拆分之和与现有总费用完全一致，并验证未知模型仍不被计价；
2. 为费用效率纯函数添加测试，覆盖完整定价、兜底定价、部分/全部未计价、零 Token、零费用、逐日聚合、30 日截取、单位成本分母和输入不可变；
3. 为费用效率组件添加静态渲染测试，覆盖中英文文案、汇总指标、定价覆盖、费用构成、每日详情、空状态和本地估算说明；
4. 更新性能视图测试，先证明旧 Token 折线不满足费用趋势需求，再验证宽卡片接入，且缓存详情、活跃时段和错误率仍保留；
5. 若测试环境支持 DOM 事件，补充鼠标悬停、键盘聚焦和失焦的详情状态测试；否则通过组件标记、`tabIndex` 和完整 `aria-label` 验证静态契约；
6. 优先运行计价、费用效率聚合、费用组件和性能视图的最小测试集；完成后运行 `npm test`、`npm run typecheck` 和 `npm run lint`。

该变更只涉及共享纯函数、Renderer、样式和翻译资源，不要求额外运行生产构建；若实施时实际触及构建配置、Electron 主进程或 preload，则补充运行 `npm run build`。

## 8. 不纳入本次范围

- 不在性能卡片中新增模型、项目或会话排行榜；这些深度分析由“成本优化”与会话诊断页面负责；
- 不新增费用预测、异常检测、预算进度或节省建议；
- 不把未知模型按相似模型价格自动推断；
- 不把本地估算描述为 OpenAI 实际账单；
- 不修改价格管理、默认价格、用户覆盖和未知模型兜底价格配置；
- 不修改概览页现有费用摘要与 Token 趋势；
- 不修改 Codex 会话目录、扫描缓存或成本优化索引。

## 9. 验收标准

1. 费用卡片明确展示已估算费用、有效单位成本、会话均费和定价覆盖率；
2. 用户可以区分精确定价、兜底定价和未计价 Token，并看到未计价模型；
3. 普通输入、缓存输入和输出费用构成之和与已计价费用一致；
4. 每日趋势使用真实的每日已计价费用，不再使用 Token 总量冒充费用趋势；
5. 用户可以通过鼠标和键盘查看每个日期的费用、单位成本和覆盖详情；
6. 未计价 Token 不进入单位成本分母，不显示为虚构的零费用；
7. 零 Token、零费用、兜底定价和定价不完整状态均有明确且不误导的降级展示；
8. 中英文文案、locale 格式化、可访问标签和窄屏布局完整；
9. 与现有缓存详情和活跃时段详情共存，不覆盖其组件、样式、翻译或测试；
10. 最小相关测试和完整的测试、类型检查、lint 全部通过。
