# UI 视觉优化设计

## 1. 背景

当前 Renderer 已经覆盖概览、会话、项目、性能、预算、成本优化和设置等完整功能，但视觉实现随着功能扩展逐步分散：

- `src/renderer/styles.css` 已超过 3000 行，颜色、字号、圆角和间距缺少统一的语义入口。
- 界面大量使用 8–10px 字号，表格和辅助信息虽然紧凑，但长期阅读负担较高。
- 七个一级导航入口与多个页面内标签缺少清晰分组，品牌识别主要依赖通用图标和灰色选中态。
- 部分视觉表达与实际数据语义不一致，例如概览趋势图绘制总 Token，却展示输入、输出和缓存三项图例。
- 工具栏中的日期范围、侧栏图标和“守护进程”状态在部分页面或状态下缺少明确含义。

本设计在不改变核心计算、扫描方式、IPC 契约和本地只读边界的前提下，建立统一且具有辨识度的桌面数据工具视觉体系。

## 2. 设计目标

采用已经确认的 **Quiet Pro · Signature** 方向：

1. 呈现冷静、可信、专业的本地开发者工具气质。
2. 通过深墨绿、薄荷绿和“Token 双轨迹”视觉母题建立品牌辨识度。
3. 保留桌面仪表盘的高信息密度，同时显著改善字号、留白和交互目标尺寸。
4. 让概览、表格、筛选器、状态提示、抽屉和图表遵循同一套视觉规则。
5. 使用一次性数据叙事动效解释数据变化，并完整支持减少动态效果设置。
6. 修复影响视觉可信度的文案、图例、导航命名和无意义控件。

## 3. 非目标

本次不包含：

- 修改 Token、费用、预算、异常、诊断或节省建议的计算方式。
- 修改 Codex 会话扫描目录、只读策略、主进程运行时或 IPC 数据结构。
- 引入第三方 UI 组件库、动画库、图表库或 CSS-in-JS 框架。
- 新增深色主题、用户自定义主题或主题持久化。
- 新增侧栏折叠功能、全局搜索、命令面板或新的顶级页面。
- 用新的数据模块替换现有页面内容；视觉示意中的数据只代表展示方式，不扩大产品范围。
- 重写全部 React 组件或顺带重构与视觉优化无关的业务逻辑。

## 4. 视觉语言

### 4.1 品牌母题

应用使用“Token 双轨迹”作为核心视觉母题：两条相互呼应的轨迹代表输入与输出，也可延伸为趋势线、状态点和轻量同心圆背景。

品牌母题的使用范围为：

- 应用标志和侧栏品牌区。
- 当前导航项左侧轨迹线。
- 重点指标、图表关键点和加载完成状态。
- 少量空状态或背景装饰。

轨迹不得铺满所有卡片，也不得用于警告、错误等语义状态，避免品牌色与业务状态混淆。

### 4.2 颜色

首版采用单一浅色主题，基础令牌定为：

| 语义 | 值 | 用途 |
| --- | --- | --- |
| 品牌深色 | `#102b27` | 侧栏、主要按钮、重点表面 |
| 品牌强调 | `#37b786` | 图表线、选中态、品牌装饰 |
| 品牌浅色 | `#6ce0b5` | 焦点环、关键点、深色表面上的高亮 |
| 页面画布 | `#f3f7f6` | 主内容背景 |
| 内容表面 | `#ffffff` | 卡片、表格、抽屉 |
| 主要文字 | `#17251f` | 标题、正文、数字 |
| 次要文字 | `#71817b` | 辅助说明和元数据 |
| 默认描边 | `#dbe6e3` | 卡片、表格和控件边界 |

品牌强调色不直接作为白底小字号正文颜色。链接和状态文字使用经过对比度校验的更深变体。警告、严重、成功和未计价状态继续拥有独立的语义令牌，并同时显示图标或文字。

### 4.3 字体与数字

保留现有系统字体栈，不下载或打包新的网络字体。生产界面的字号约束为：

- 页面主标题：20–24px。
- 区块标题：14–16px。
- 正文与表格主体：至少 12px，常规场景使用 13px。
- 辅助标签、表头和徽标：至少 10px，且不得承载关键说明或唯一操作含义。
- 核心指标：22–28px。

金额、百分比、Token 和日期继续使用现有 locale formatter。表格中的金额和 Token 使用等宽数字特性，并按数值列右对齐。

### 4.4 间距、圆角与层次

- 间距以 4px 为最小单位，常用值为 8、12、16、24 和 32px。
- 紧凑控件高度为 32px，主要操作和表单控件优先使用 36px。
- 小控件、徽标和输入框使用 8px 圆角；卡片使用 12px；大浮层使用 16px。
- 页面层次固定为画布、内容表面、浮层三层。
- 常规卡片依靠画布差异与细描边区分；阴影只用于抽屉、对话框、浮层反馈和少量重点卡片。

## 5. 应用外壳与导航

### 5.1 侧栏

侧栏采用深墨绿背景，并增加品牌标志和产品名。现有一级入口不改变路由键和导航行为，只做以下视觉与命名调整：

- “概览、会话、项目、性能”归入“洞察”组。
- “成本优化、预算、设置”归入“控制”组。
- `tools` 的显示名称统一为英文 `Projects`、中文“项目”。
- `wrapped` 的显示名称统一为英文 `Settings`、中文“设置”。
- 当前项使用深绿亮面、左侧薄荷轨迹和文字加粗，不只依赖背景颜色。
- 预算和扫描告警徽标继续显示明确数量。

本次不实现折叠侧栏。最小窗口宽度下保持完整文字导航，避免当前接近最小宽度时自动隐藏标签导致发现性下降。

### 5.2 顶部工具栏

工具栏改为全局状态与操作区；页面名称和说明由内容区统一的 PageHeader 承担，避免同一标题在工具栏和页面中重复：

- 移除没有折叠行为的侧栏图标。
- 移除工具栏内重复的当前页面标题。
- 将固定绿色“守护进程”改为真实、可解释的扫描状态，例如“本地数据已同步”“正在扫描”“显示旧数据”。
- 同时显示最近成功扫描时间。
- 日期范围只在真正使用全局周期的页面显示：概览、会话、项目、性能和成本优化。
- 预算与设置页面不显示全局日期范围。
- 语言选择器和刷新操作保留在右侧，并统一使用 32px 紧凑控件。

## 6. 共享组件体系

### 6.1 指标卡

现有 `MetricCard` 继续作为共享组件，新增统一的层次和状态规则：

- 默认卡片为白色表面、细描边和无明显阴影。
- 每个页面最多一个重点卡片使用深绿品牌表面。
- 核心数值、标签和辅助说明形成固定三层排版。
- 趋势变化必须同时显示方向符号、数值和文字，不只使用红绿颜色。

### 6.2 页面标题与筛选器

为全部主页面统一 PageHeader 结构：标题、简短说明、范围筛选和主要操作。筛选器使用一致的标签、选择器高度和焦点样式。

日期范围使用分段控件。页面内部的模式切换继续使用标签页，但同一页面只保留一个主要标签层级，避免多个样式不同的切换控件并存。

### 6.3 表格与列表

- 表头使用 10px 高对比度辅助标签，不强制全大写中文。
- 表格主体至少 12px，行高约 48px。
- 主字段允许两行：名称与次要元数据。
- 数值列右对齐并使用等宽数字。
- 可进入详情的整行在悬停与键盘聚焦时显示浅绿底和左侧轨迹。
- 横向滚动继续作为狭窄窗口的兜底，但最常用字段必须优先留在可见区域。

### 6.4 状态、提示与空状态

成功、警告、严重、未计价、数据不足和旧数据使用统一的图标、标题、说明和操作结构。状态不得只通过颜色表达。

- 初次加载使用保留页面结构的骨架屏。
- 后台刷新时保留现有数据，不把整页替换为加载状态。
- 刷新失败时保留最后一次成功结果，并明确显示数据时间、影响范围和“重新扫描”操作。
- 操作成功使用非阻塞式短暂反馈；确认删除继续使用对话框。
- 空状态说明为什么为空，并只提供一个最相关的下一步。

### 6.5 抽屉与对话框

预算和成本优化设置抽屉共享标题、正文、底部操作区、遮罩和焦点管理。主要操作固定在右侧，关闭后焦点回到触发按钮。错误信息显示在对应字段附近，并保留现有结构化校验结果。

## 7. 概览与图表

### 7.1 概览指标

保留费用、总 Token、输出 Token、会话数和现有数据来源，不增加新的业务指标。费用卡作为概览页的唯一深绿重点卡，其余指标使用白色表面。

### 7.2 趋势图语义

当前趋势路径以每日 `totalTokens` 绘制，因此设计统一为单条“总 Token”趋势：

- 标题使用“Token 用量趋势”。
- 图例只显示“总 Token”。
- tooltip 继续展示日期、总量、输入、输出、缓存和估算费用。
- 未计价状态继续明确标注，不暗示费用完整。

如果未来需要输入、输出、缓存多序列图，必须先增加真实的多序列路径与可区分的辅助表达，再恢复三项图例；本次不扩大为该功能。

### 7.3 活动热力图

保留现有活动热力图，并补充月份或日期范围提示、强度图例和键盘可获得的单日说明。所选周期短于热力图窗口时，明确区分“周期外”与“零用量”，避免大片空单元被误解为零使用。

## 8. 动效设计

动效采用已经确认的“数据叙事”级别：

1. 数据首次进入 ready 状态时，指标卡在 0–240ms 内依次淡入上移。
2. 趋势线随后绘制，关键点和最新值说明依次出现。
3. 完整序列在约 1.4 秒内结束，结束后完全静止。
4. 后续刷新只有在数值确实变化时才播放 180ms 左右的数值交叉淡化和图表过渡。
5. 悬停、按压和焦点过渡使用 120–180ms；抽屉使用不超过 220ms。
6. 不使用永久漂浮、循环呼吸或持续闪烁动画。

当系统启用 `prefers-reduced-motion: reduce` 时，所有入场、位移、路径绘制和数字过渡立即显示最终状态，仅保留必要的焦点可见性。

## 9. 技术边界与样式组织

### 9.1 数据流

视觉优化只发生在 Renderer：

```text
现有主进程与 IPC 数据
        ↓
现有 hooks / view model / props
        ↓
页面与共享组件
        ↓
视觉令牌、布局和动效
```

主进程、preload、共享业务类型、扫描缓存和费用计算不因本设计发生变化。Renderer 不新增文件系统访问，也不读取会话正文。

### 9.2 CSS 组织

保留 `src/renderer/styles.css` 作为唯一样式入口，并按以下层次拆分导入：

- `styles/tokens.css`：颜色、字号、间距、圆角、阴影、动效时长。
- `styles/base.css`：全局排版、焦点、按钮和表单基础规则。
- `styles/shell.css`：应用外壳、侧栏、工具栏和响应式布局。
- `styles/components.css`：卡片、标签、表格、提示、抽屉和对话框。
- `styles/views.css`：仍然属于具体页面的图表和复杂布局。

迁移采用渐进方式。一个组件迁移完成后再移除其旧规则，不进行无关的全文件格式化。颜色和尺寸优先引用语义令牌，页面样式不新增业务含义不明的裸色值。

### 9.3 React 边界

只有同时承担结构或交互的重复单元才提取为 React 组件。纯视觉一致性优先通过共享 class 和令牌实现，避免创建只包装一个 `div` 的组件。

计划复用或收敛的组件包括：

- 现有 `MetricCard`。
- 页面标题和操作区。
- 状态徽标与提示条。
- 分段控件和标签页。
- 表格行的主字段结构。
- 抽屉标题与底部操作区。

## 10. 响应式与可访问性

- 重点验证默认窗口 `1280 × 820` 和最小窗口 `1024 × 680`。
- 不再在约 1050px 时隐藏全部侧栏文字；表格和复杂诊断内容可按现有方式横向滚动。
- 所有交互控件支持键盘操作，并提供统一的双层薄荷色 `:focus-visible` 样式。
- 现有使用 `role="tab"` 的标签页补齐左右方向键、Home、End 和 roving `tabIndex` 焦点管理，完整遵循 ARIA tab 模式。
- 正文与背景达到 WCAG AA 对比度；品牌浅色不作为白底正文颜色。
- 图表保留可访问名称、摘要和键盘可聚焦数据点。
- 英文和简体中文同时维护，中文不强制大写风格，长英文标签不得被固定宽度截断为不可辨认文本。

## 11. 错误与降级行为

- 初次扫描失败：显示完整错误状态与重新扫描操作。
- 后续扫描失败：保留最后一次成功数据并显示旧数据提示。
- 未知模型价格：保留 Token，明确标记未计价，不猜测费用。
- 诊断历史不足：显示“数据不足”及原因，不使用正常色伪装为无异常。
- 动画或 CSS 特性不可用：直接显示静态最终状态，不影响读取和操作。
- 内容超长：项目路径、模型 ID 和会话名称允许省略显示，但通过 title 或现有可访问说明保留完整值。

## 12. 验证策略

### 12.1 自动化测试

- 更新现有 Sidebar、Toolbar、Overview、预算和成本优化 React 测试，覆盖新结构和可访问名称。
- 为日期范围的页面能力映射添加纯函数测试，确保预算和设置页不显示无意义控件。
- 为概览趋势图添加回归测试，确保单条总 Token 曲线只对应一个图例。
- 为中英文导航名称添加测试，确保 `Projects` / “项目”和 `Settings` / “设置”一致。
- 为标签页键盘语义、状态非颜色表达和减少动态效果类名增加针对性测试。
- 增加轻量样式策略检查，防止迁移后的页面重新引入未登记的业务色值或低于生产下限的关键正文尺寸。

### 12.2 人工视觉检查

在以下组合中检查核心页面：

- `1280 × 820` 与 `1024 × 680`。
- 英文与简体中文。
- 正常、加载、旧数据、错误、未计价、空状态。
- 鼠标、键盘和系统减少动态效果。

重点检查概览、会话表格、预算、成本优化诊断详情、设置抽屉和确认对话框。

### 12.3 完成前验证

实现完成前至少运行：

```powershell
npm test
npm run typecheck
npm run lint
```

本次会修改 Renderer 样式与组件，但不修改 Electron 主进程、preload 或打包配置；如实施过程中触及这些范围，则额外运行 `npm run build`。即使未触及，仍建议在最终视觉验收前运行一次生产构建并启动 Electron 检查布局。

## 13. 分阶段交付

1. **视觉基础**：建立令牌、基础排版、焦点样式和样式文件分层。
2. **应用外壳**：更新侧栏、导航命名、工具栏和真实扫描状态。
3. **共享组件**：统一指标卡、按钮、筛选器、标签页、表格、提示和抽屉。
4. **页面迁移**：依次迁移概览、会话与项目、性能、预算、成本优化、设置。
5. **数据动效与收尾**：加入一次性数据叙事、减少动态效果降级和跨语言视觉检查。

每个阶段都应保持应用可运行，并只删除已经由新规则完整替代的旧样式。

## 14. 验收标准

- 应用呈现一致的 Quiet Pro · Signature 视觉语言，并具有明确的 Token 双轨迹品牌识别。
- 页面正文和关键操作不再依赖 8–10px 小字号。
- 默认与最小窗口尺寸下，侧栏文字、核心指标和常用操作保持可读可用。
- 同类组件在不同页面使用一致的间距、圆角、状态和焦点样式。
- 概览趋势图的路径、标题和图例语义一致。
- 设置和预算页面不显示无意义的全局日期范围。
- 英文与中文导航名称准确表达实际页面含义。
- 加载、旧数据、错误、空状态和未计价状态均有明确说明与恢复操作。
- 动效在约 1.4 秒内结束，数据不变化时不重复播放，并支持减少动态效果。
- 颜色不是状态或严重程度的唯一表达方式，鼠标与键盘均可完成主要操作。
- 不改变现有扫描、计算、预算、诊断、IPC 和本地只读行为。
- 测试、类型检查和 lint 全部通过；生产 Electron 视觉检查无明显布局回归。
