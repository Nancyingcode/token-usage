# 自定义标题栏设计

## 背景

当前 Electron 主窗口使用系统默认窗口边框与标题栏。应用主体已经拥有完整的品牌色、侧边导航和工具栏，系统标题栏在视觉上与应用界面割裂，也无法统一窗口标题、拖拽区域和窗口控制按钮的交互样式。

本次改动将主窗口切换为无系统边框窗口，并由 Renderer 绘制标题栏。窗口能力仍由 Electron 主进程持有，Renderer 只能通过 preload 暴露的类型化 API 发起有限的窗口操作。

## 目标

- 不显示操作系统自带标题栏和窗口边框。
- 提供可拖动的自定义标题栏。
- 提供最小化、最大化/还原和关闭三个窗口控制按钮。
- 最大化状态变化后，最大化按钮能够同步显示“最大化”或“还原”语义。
- 标题栏视觉与现有深色侧边栏、浅色内容区自然衔接。
- 保持当前安全边界：Renderer 不直接访问 Electron 或 Node.js API。
- 控件支持键盘操作、可访问名称以及中英文文案。

## 非目标

- 不实现窗口吸附、窗口置顶、全屏或多窗口管理。
- 不保存或恢复窗口尺寸与位置。
- 不替换现有应用菜单策略。
- 不为 macOS 仿制红黄绿交通灯按钮；本次使用统一的应用内窗口控件。

## 交互与布局

### 标题栏结构

标题栏高度为一个具名常量对应的固定紧凑高度，位于内容区顶部；深色侧边栏继续占满窗口左侧。侧边栏中的品牌区域和标题栏空白区域共同作为窗口拖拽区域，使用户可从窗口顶部左侧或中部拖动窗口。

标题栏右侧依次放置：

1. 最小化
2. 最大化或还原
3. 关闭

窗口控制按钮使用 `lucide-react` 图标，与现有图标体系保持一致。普通按钮使用中性悬停态，关闭按钮使用危险悬停态。按钮区域必须声明为非拖拽区域，避免点击被窗口拖动吞掉。

标题栏不重复显示侧边栏已有的产品名称，以避免出现两个品牌标题。标题栏中部保留为大面积拖拽区域，右侧仅承载窗口控制按钮。

### 窗口行为

- 点击最小化按钮调用当前 `BrowserWindow.minimize()`。
- 点击最大化按钮时：未最大化则调用 `maximize()`，已最大化则调用 `unmaximize()`。
- 点击关闭按钮调用当前 `BrowserWindow.close()`，保留 Electron 原有关闭生命周期。
- 主进程监听窗口的 `maximize` 与 `unmaximize` 事件，并将最新状态推送给 Renderer。
- 标题栏组件挂载时主动读取一次当前最大化状态，避免首次渲染依赖事件时序。
- CSS 拖拽区域使用 `-webkit-app-region: drag`；所有按钮使用 `-webkit-app-region: no-drag`。

## 技术设计

### 主进程

`BrowserWindow` 设置 `frame: false`，彻底关闭系统标题栏。保留当前窗口尺寸、最小尺寸、背景色和安全相关 `webPreferences`。

新增独立窗口控制模块，负责：

- 注册窗口操作 IPC handler；
- 从 IPC 事件定位请求所属的 `BrowserWindow`，避免依赖可变全局窗口引用；
- 执行最小化、最大化/还原、关闭；
- 查询当前最大化状态；
- 发送最大化状态变化事件；
- 在应用退出时完整注销 handler 和事件监听。

窗口控制逻辑与用量业务 IPC 分离，防止继续扩大 `registerUsageIpc` 的职责。

### 共享协议与 preload

共享 IPC 常量新增以下窗口通道：

- `window:minimize`
- `window:toggle-maximize`
- `window:close`
- `window:get-state`
- `window:state-changed`

共享类型定义窗口状态：

```ts
interface WindowState {
  isMaximized: boolean;
}
```

preload 在 `window.codexUsage.window` 下暴露最小权限 API：

- `minimize(): Promise<void>`
- `toggleMaximize(): Promise<WindowState>`
- `close(): Promise<void>`
- `getState(): Promise<WindowState>`
- `onStateChanged(listener): () => void`

Renderer 不获得任意通道调用能力，也不接触 `ipcRenderer`。

### Renderer

新增 `TitleBar` 组件，负责窗口控制按钮、最大化状态订阅和可访问名称。组件只调用 preload API，不持有业务状态。

`App` 布局调整为两列两行：

- 左列侧边栏跨越标题栏行与内容行；
- 右列第一行为自定义标题栏；
- 右列第二行为现有主内容区。

这样可以保留现有侧边栏品牌区，同时让标题栏与内容区共享浅色背景。主内容区单独滚动，侧边栏与标题栏固定可见。

### 国际化与无障碍

英文与简体中文资源新增窗口操作文案：

- 最小化 / Minimize
- 最大化 / Maximize
- 还原 / Restore
- 关闭 / Close

每个窗口控制按钮使用原生 `button`，带有随状态更新的 `aria-label` 与 `title`，支持 Tab 聚焦、Enter 和 Space 激活。图标标记为装饰性内容，状态含义不只依靠颜色表达。

## 错误处理

窗口操作失败不阻塞应用主体。标题栏读取状态失败时默认按“未最大化”渲染；后续状态事件仍可纠正显示。关闭和最小化等按钮不会在界面上展示技术错误提示，因为这些操作没有可恢复的业务输入。

## 测试策略

按红—绿—重构执行：

1. 为窗口控制模块添加回归测试，验证每个 IPC 操作、最大化切换、状态查询、状态广播和注销行为。
2. 为 `TitleBar` 添加组件测试，验证三个按钮、双语可访问文案、最大化/还原状态切换和 API 调用。
3. 更新样式策略测试，验证拖拽区、非拖拽按钮和无原始颜色约束。
4. 增加或调整主窗口配置测试，验证 `frame: false`。
5. 运行最小相关测试后，完整运行 `npm test`、`npm run typecheck`、`npm run lint` 和 `npm run build`。本次修改 Electron 主进程，因此构建验证是必需项。

## 风险与边界

- 无边框窗口会失去系统自动提供的标题栏交互，因此拖拽区域和窗口按钮必须在首个实现中完整交付。
- 最大化状态可能由按钮以外的系统手势改变，因此必须监听主进程窗口事件，不能只在 Renderer 中乐观切换状态。
- 标题栏占用垂直空间后，主内容区与侧边栏高度必须使用网格剩余空间，避免出现双滚动条或内容被裁切。
- Windows 是当前主要打包目标；统一控件在其他平台仍可工作，但不模拟平台专属标题栏外观。
