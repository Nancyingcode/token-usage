# 项目分析工作台设计

## 背景与目标

当前“项目”页以全量项目环形图和图例为主。它能展示 Token 占比，并支持进入项目会话，但项目数量增加后会出现颜色循环、小扇区难以比较、完整信息依赖悬浮以及缺少搜索与排序的问题。

本次将页面升级为面向日常分析的项目工作台，优先解决三个任务：快速判断整体规模、比较主要项目、定位并进入具体项目的会话。变更只使用当前周期已经聚合出的 `UsageProject[]`，不扩大到项目详情、费用、预算和异常模块。

## 页面结构

页面从上到下分为四层：

1. 保留现有标题、说明和项目总数。
2. 增加四项概览指标：项目数、总 Token、总会话数、最高占比项目。
3. 保留占比图，但只展示 Token 最高的七个项目；其余项目聚合为不可下钻的“其他项目”，避免颜色循环和过多小扇区。图例同步展示相同口径。
4. 增加项目列表面板，提供搜索、排序和明确的“查看会话”按钮。列表展示项目名、路径、Token、占比、会话数、平均 Token/会话、缓存输入占输入 Token 的比例和最后活跃时间。

项目列表是完整数据入口，环形图只承担概览职责。环形图中的真实项目仍可点击进入对应会话；“其他项目”只展示汇总信息，不伪造项目路径，也不执行导航。

## 搜索与排序

- 搜索同时匹配项目名与完整路径，忽略大小写并去除输入首尾空白。
- 排序项包括 Token、会话数、最后活跃时间和项目名。
- Token、会话数和最后活跃时间默认降序；项目名默认升序。
- 切换排序项时采用该项默认方向；再次激活当前排序项不额外引入隐藏行为。
- 搜索无结果时在列表面板内显示专用空状态，并提供清除搜索操作。

筛选和排序是当前页面的局部状态，不写入磁盘，也不修改传入数组。

## 指标口径

- 项目数：当前周期 `projects.length`。
- 总 Token：所有项目 `totalTokens` 之和。
- 总会话数：所有项目 `sessionCount` 之和。
- 最高占比项目：Token 排序第一的项目及其占比；无数据时显示占位值。
- 平均 Token/会话：`totalTokens / sessionCount`；零会话时显示 0。
- 缓存率：`cachedInputTokens / inputTokens`；输入 Token 为零时显示 0%。该值描述缓存输入占输入 Token 的比例，不扩展为服务端缓存命中率承诺。

## 导航与可访问性

- 列表使用语义化表格，表头和数值列提供明确标签。
- 搜索框有本地化可访问名称。
- 排序使用原生 `select`，键盘可直接操作。
- 每行使用原生按钮进入项目会话，按钮的可访问名称包含项目名。
- 环形图继续支持 Tab、Enter、Space、hover 和 focus。
- “其他项目”不声明为按钮，仅提供汇总的可访问说明。
- 颜色仍只用于区分类别，不作为状态表达。

## 国际化与边界情况

- 所有新增可见文案同时维护英文和简体中文资源。
- `Unknown Project` 只作为内部稳定标识，展示时本地化为“未知项目”或“Unknown project”。
- 同名项目在主标题下显示完整路径，避免仅凭目录末级名称产生歧义。
- 项目数组为空时通常由上层周期空状态接管；组件自身仍保持零值安全，避免除零和不可操作图形。
- 总 Token 为零时不生成可操作图段，但列表仍可展示项目。

## 非目标

- 不新增项目详情抽屉、项目对比、别名、标签或项目合并规则。
- 不接入费用、预算、异常、诊断或导出能力。
- 不修改主进程、preload、IPC、会话扫描与项目聚合算法。
- 不读取或修改 Codex 会话目录。

## 验证策略

按红—绿—重构执行：

1. 先为 Top 七加“其他项目”、概览指标、搜索、排序、表格字段和明确导航添加失败测试。
2. 用纯函数实现 Top N 聚合、过滤与排序，并验证输入不变。
3. 完成组件、文案和响应式样式后运行项目视图最小测试集。
4. 最终运行 `npm test`、`npm run typecheck` 和 `npm run lint`。
