# 应用稳定版在线更新设计

状态：用户已明确要求按推荐方案实施；不包含正式发布、Git 提交、推送或实际安装验收。

## 范围

使用 electron-updater、现有 NSIS 和 GitHub Releases；发布源沿用项目
`Nancyingcode/token-usage`。首期只有手动检查、明确下载、确认重启安装，始终保留下载离线包修复入口。
不自动下载、不在普通退出时安装、不支持预发布或降级，不改变现有产品身份、数据路径和安装范围。
首次接入在线更新的版本仍需由现有用户手动安装一次。价格目录同步继续独立运行。

## 客户端

主进程持有更新状态与 electron-updater；preload 暴露无 URL/路径参数的类型化检查、下载、安装和
打开发布页接口。设置页展示当前版本、目标稳定版本、纯文本说明、进度、失败重试与离线修复说明。
中英文同时维护，状态向辅助技术播报。重启安装由主进程原生确认框确认，取消为默认选项。

状态为 unavailable、idle、checking、up-to-date、available、downloading、downloaded、preparing、
installing、error。并发操作合并或拒绝，只有当前已确认下载的更高稳定版本可安装；异常和过期回调不能
将状态恢复成可安装。开发环境及不支持的平台禁用在线更新。发布者身份未配置的本地构建不允许下载与安装。
更新仅通过固定 HTTPS GitHub 发布源获取，不能接受 Renderer 提供的 URL、令牌或执行参数。
安装包须通过上游摘要与 Windows 发布者签名验证，并在下载完成和安装前重新核对摘要与系统签名。
系统验证工具不可用时拒绝安装；发行构建强制代码签名，禁止绕过签名验证。

## 安装前数据保护

用户确认安装后，暂停新业务操作和后台生产任务，等待已开始的应用数据写入完成，再启动 NSIS。
准备失败不启动安装器；恢复可继续工作的状态并提示错误。所有数据源仍按只读处理；更新日志不包含
真实会话内容或上传本地配置。原生安装后的失败不承诺任意阶段回滚，问题版本通过更高版本修复发布。

## 构建与发布

普通构建明确使用 `--publish never`。增加手动触发的 Windows 草稿构建流程，验证标签与 package
版本一致、稳定版本格式、签名身份与产物齐全；只允许创建新的草稿 Release，不覆盖已有发布。
没有证书或发布者配置时发布流程失败关闭。本次不执行发布流程，也不创建远程草稿。
安装包、latest.yml 与 blockmap 属于同一次构建。已核对目标仓库为公开仓库；客户端不内置 GitHub Token。

## 验证

实际服务采用可注入 updater 端口，测试显式授权、稳定版本、并发、错误、取消、重试与退出准备。
IPC 验证调用窗口与参数边界；Renderer 验证中英文、状态、确认入口及失败反馈。
对发布配置、草稿限制和签名门禁做自动化检查。运行 npm test、typecheck、lint、build 和 Windows
NSIS 构建；实际联网更新、签名及 UAC 场景在隔离环境恢复验收后执行，不操作现有安装。

依据：[官方更新机制](https://www.electron.build/v26/docs/features/auto-update/)、
[发布配置](https://www.electron.build/v26/docs/publish/)及本项目已确认的安装器维护设计。
