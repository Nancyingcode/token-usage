# 成本优化功能设计

## 1. 背景

当前应用已经能够从本地 Codex 会话中解析 Token 用量，按日期、项目和会话展示统计结果，并结合模型价格估算费用。预算模块已经提供模型价格维护、费用预算和未计价模型提示。

本次功能在这些基础能力之上新增独立的“成本优化”中心，帮助用户回答以下问题：

1. 不同模型分别产生了多少费用，相同历史负载换用其他模型时费用会如何变化？
2. 哪些日期、项目、模型或会话出现了异常消耗？
3. 按当前趋势，未来 7 天或 30 天可能产生多少费用，何时可能超过预算？
4. 哪些优化动作具有可量化的节省空间，其依据和风险是什么？

功能继续遵守本地只读边界：只读取 Codex 会话数据，不上传分析结果，不修改 Codex 会话文件或运行配置。

## 2. 目标

- 新增独立的“成本优化”顶级导航入口，同时保留现有“性能”页面。
- 提供历史实耗与可配置模型替代场景。
- 在日、项目、模型、会话四个层级检测成本上升异常。
- 根据数据量自适应选择预测方法，输出预测区间和预算超限日期。
- 生成可量化、可解释、带置信度和风险说明的节省建议。
- 支持异常、预测和建议规则配置，并安全持久化。
- 在扫描阶段维护可逆的增量贡献索引，避免每次刷新都全量重建分析数据。
- 对未计价模型、历史不足、配置损坏和扫描失败提供明确降级状态。

## 3. 非目标

- 不接入 OpenAI 账单 API，也不声称估算费用等同于实际账单。
- 不推断模型质量、速度或能力等价。
- 不自动切换模型，不自动修改 Codex 配置。
- 不生成无法量化金额的泛化经验建议。
- 第一版不发送异常或节省建议系统通知。
- 不使用外部机器学习服务或上传本地会话数据。

## 4. 已确认的产品决策

- 产品定位：专业、可配置的本地分析工具。
- 页面入口：独立“成本优化”中心。
- 模型对比：历史实耗与可配置替代场景同时提供。
- 异常层级：日、项目、模型、会话四层。
- 预测策略：数据不足时使用加权日均，数据充足时加入星期周期。
- 建议策略：仅输出可量化、可解释、只读建议。
- 现有页面：保留“性能”页面，与“成本优化”并列。
- 实现路线：扫描阶段增量预计算并持久化贡献索引。

## 5. 总体架构

### 5.1 组件关系

```text
Codex JSONL 文件
  ↓
UsageScanner
  ├─ 完整 UsageScanResult → 现有用量与预算功能
  └─ UsageChangeSet
       ↓
CostOptimizationIndex
  ├─ 来源文件贡献
  ├─ 日聚合
  ├─ 项目聚合
  ├─ 模型聚合
  └─ 会话聚合
       ↓
CostOptimizationEngine
  ├─ 模型成本对比
  ├─ 异常检测
  ├─ 趋势预测
  └─ 节省建议
       ↓
CostOptimizationRuntime
  ├─ 配置与缓存持久化
  ├─ 价格与设置失效控制
  └─ CostOptimizationSnapshot
       ↓ IPC / preload
CostOptimizationView
```

### 5.2 单一扫描协调

当前预算运行时拥有扫描监控器。新增第二个分析运行时后，不能分别扫描同一批文件。因此新增用量协调边界：

- `UsageRuntime` 统一拥有 `UsageScanner` 和 `UsageMonitor`。
- `UsageRuntime` 向现有预算运行时发布完整 `UsageScanResult`。
- `UsageRuntime` 向成本优化运行时同时发布完整结果和 `UsageChangeSet`。
- Renderer 继续只接收原有 `UsageScanResult`，不会接收内部文件指纹或重复的增量负载。
- 窗口聚焦刷新和 60 秒定时刷新仍由一个监控器控制。

预算运行时不再直接发起文件扫描，只在收到完整用量结果后重新评估预算。这样既避免重复扫描，也使预算和成本优化成为平级的数据消费者。

成本优化运行时订阅预算快照以复用合并后的模型价格和适用费用预算。预算快照变化时，成本优化运行时分别比较价格签名和预算签名：价格签名变化触发费用重算，只有预算签名变化时仅重算预算线与预计超限日期。成本优化运行时不写入预算配置。

## 6. 增量贡献索引

### 6.1 扫描变更集

扫描器在现有“文件大小 + 修改时间”指纹缓存基础上产生内部变更集：

```ts
interface UsageChangeSet {
  upserted: UsageSourceChange[];
  removedSourceFiles: string[];
  requiresFullRebuild: boolean;
}

interface UsageSourceChange {
  sourceFile: string;
  fingerprint: string;
  session: UsageSession;
}
```

首次扫描时，所有成功解析的文件都属于 `upserted`。后续扫描仅包含新增或指纹变化的文件；已不存在的文件进入 `removedSourceFiles`。

### 6.2 可逆来源贡献

每个来源文件保存独立的标准化贡献，至少包含：

- 来源文件与指纹
- 会话 ID、项目标识和时间范围
- 每个用量切片的本地日期、模型 ID
- 输入 Token、缓存输入 Token、输出 Token、推理输出 Token 和总 Token
- 对日、项目、模型、会话聚合桶的引用键

索引更新遵循以下顺序：

1. 修改文件：从所有关联聚合桶减去旧贡献。
2. 删除文件：减去旧贡献并删除来源记录。
3. 新增或修改文件：标准化新会话并加入对应聚合桶。
4. 删除归零的聚合桶。
5. 仅对受影响范围重算派生费用与分析。

索引保存价格无关的 Token 维度，不保存不可逆的最终美元金额。因此价格变更无需重新读取 JSONL。

### 6.3 持久化格式

缓存文件为 `<Electron userData>/cost-optimization-cache.json`，包含：

- `schemaVersion`
- `sessionsDir`
- `generatedAt`
- 来源贡献记录
- 日、项目、模型、会话聚合桶

缓存采用临时文件替换方式原子写入。以下情况触发全量重建：

- 缓存无法解析或结构校验失败；结构校验包括来源贡献总量与聚合桶顶层总量一致
- `schemaVersion` 不兼容
- 会话目录发生变化
- 扫描器明确返回 `requiresFullRebuild`
- 来源贡献与聚合桶一致性校验失败

全量重建只读取当前扫描结果中的会话数据，不额外读取一遍 JSONL。

## 7. 配置模型

配置文件为 `<Electron userData>/cost-optimization-config.json`。

```ts
interface CostOptimizationSettings {
  anomalyHistoryWindow: number;
  anomalyMinimumSamples: number;
  anomalySensitivity: number;
  forecastHorizonDays: 7 | 30;
  forecastMinimumHistoryDays: number;
  candidateModelIds: string[];
  minimumSavingsUsd: number;
  targetCachePercentage: number;
  minimumPricingCoveragePercentage: number;
}
```

默认值：

- 异常历史窗口：28 个观测
- 异常最低样本数：7
- 异常灵敏度：3.5
- 预测周期：30 天
- 预测最低历史：7 个日历日
- 候选模型：当前已计价模型
- 最低节省额：1 美元
- 目标缓存占比：80%
- 最低定价覆盖率：80%

配置校验范围：

- 异常历史窗口必须是 7–90 的整数。
- 异常最低样本数必须是 3 到异常历史窗口之间的整数。
- 异常灵敏度必须是 1–10 的有限数值。
- 预测周期只能是 7 天或 30 天，预测最低历史必须是 7–28 的整数。
- 候选模型 ID 必须去重，且必须能匹配当前价格表。
- 最低节省额必须是大于或等于零的有限数值。
- 目标缓存占比和最低定价覆盖率必须是 0–100 的有限数值。

校验失败时返回结构化字段错误，不写入配置，也不替换当前快照。价格表变化导致已有候选模型失去定价时，保留原配置但忽略该候选模型，并在设置界面显示修复提示。

配置文件带 `schemaVersion` 并采用原子写入。文件损坏时保留备份并恢复默认配置。

## 8. 模型成本对比

### 8.1 实际成本

按模型汇总以下指标：

- 输入、缓存输入、输出和总 Token
- 已计价费用
- 总费用占比
- 会话数
- 平均会话费用
- 定价覆盖率

未知模型的 Token 保留在用量统计中，但不计入已计价费用。

### 8.2 替代场景

替代场景保持历史负载的 Token 构成不变，只将目标模型价格应用到相同的输入、缓存输入和输出 Token：

- 默认比较当前实际模型和用户候选白名单中的已计价模型。
- 可按全局或项目范围运行场景。
- 只展示达到最低节省额的正向节省结果。
- 目标模型缺少价格时不生成场景结果。
- 每个结果明确标注“仅比较价格，不代表质量、速度或能力等价”。

模型替代不会改变原始数据，也不会自动修改任何配置。

## 9. 异常消耗检测

### 9.1 检测对象

仅检测正向成本异常：

- 日：每日总费用
- 项目：每个项目的每日费用
- 模型：每个模型的每日费用
- 会话：单会话费用

会话基线优先使用“同项目 + 同模型”历史会话；样本不足时依次退化到同模型历史会话和全局历史会话。退化层级必须展示在异常依据中。

### 9.2 稳健基线

默认使用最近 28 个有效观测的中位数和 MAD 构建稳健基线，避免异常峰值污染平均值。稳健尺度为 `1.4826 × MAD`，偏离分数为“实际费用减中位数”除以稳健尺度。

- 有效观测少于配置的最低样本数时，不生成异常结论。
- MAD 大于零时，偏离分数达到配置的灵敏度产生警告，达到灵敏度的两倍产生严重异常。
- MAD 为零时，稳健尺度降级为 `max(中位数 × 25%, 0.01 美元)`，再使用相同偏离分数阈值。
- 只有分析范围的定价覆盖率达到安全阈值时，才生成费用异常。

每条异常包含：

- 层级、范围和发生时间
- 实际费用与基线费用
- 偏离倍数和严重级别
- 使用的样本数与基线退化层级
- 对异常贡献最大的项目、模型或会话
- 定价覆盖率和数据完整性状态

日、项目、模型、会话异常通过共同的贡献键关联，使用户能够从日期逐层定位到具体会话。

## 10. 趋势预测

### 10.1 输入序列

- 使用连续本地日历日序列。
- 无使用日期按零费用处理。
- 异常检测可以标记峰值，但不会直接删除真实历史数据。
- 预测使用已计价费用，并携带定价覆盖率。

### 10.2 自适应方法

- 历史少于配置的预测最低历史天数：显示样本不足，不生成预测。
- 历史达到配置的最低天数但少于 28 天：使用指数加权日均，最近一天权重为 1，向前每天乘以 0.85；未来每日点预测为该加权日均。
- 历史达到 28 天：使用最近最多 8 个同星期观测的中位数作为星期基线，并将最近 28 天的 Theil–Sen 稳健斜率按预测天数加入基线。
- 使用历史拟合残差的 `1.4826 × MAD` 估计离散程度，点预测上下各 `1.28 × 稳健残差尺度` 形成标注为“80% 经验区间”的范围。
- 所有点预测和区间下界最小为零。

页面展示：

- 未来 7 天或 30 天逐日预测
- 预测中值与上下区间
- 当前报告期末预计费用；报告期为“总计”时改为展示所选预测周期的累计费用
- 所有适用费用预算的预计超限日期；总览默认展示最早超限项
- 使用的方法、样本范围和定价覆盖率

当最低定价覆盖率不足时，不展示完整费用预测，只显示“已计价部分下界”和补充价格入口。存在多个适用预算时，预测标签允许选择预算线；适用范围包括全局费用预算和当前所选项目的项目费用预算。

## 11. 节省建议

第一版包含三类规则：

### 11.1 模型替代

对真实历史 Token 构成应用候选模型价格，计算费用差。该建议金额确定性较高，但必须独立显示能力等价风险。

### 11.2 缓存占比提升

在当前输入 Token 规模不变的前提下，将缓存输入占比提升到配置目标，计算价格情景差额。由于应用无法确认全部输入是否可缓存，该建议最多为中等置信度，并标记“需验证可缓存性”。

### 11.3 异常回落

计算异常实际费用回落至稳健基线后的差额。只有已满足异常最低样本要求的记录才能产生该建议。

### 11.4 建议输出

每条建议包含：

- 类型和适用范围
- 预计节省额及换算周期
- 计算依据
- 数据覆盖率
- 置信度
- 风险说明
- 涉及的贡献键

低于最低节省额的建议不展示。置信度不由用户手动填写，规则如下：

- 模型替代在来源与目标价格均完整且至少覆盖 7 个会话时为高置信度，否则不展示。
- 异常回落在定价完整且基线至少有 28 个样本时为高置信度，达到最低样本数但少于 28 个样本时为中置信度。
- 缓存提升始终为中置信度，因为本地日志不能证明全部输入都可缓存。
- 定价覆盖率低于安全阈值时，所有费用节省建议都不展示。

建议金额默认使用当前报告期。只有预测可用时，界面才额外展示按预测周期换算的节省金额。

### 11.5 重叠去重

模型替代、缓存提升和异常回落可能覆盖同一批用量。顶部“保守可节省”不能直接相加建议金额。

分析引擎按贡献键和费用组成识别重叠部分；对同一贡献范围采用不重复计费的保守节省值，再汇总为顶部金额。建议列表仍可分别展示各场景，但必须提示存在重叠。

## 12. 页面与交互

### 12.1 导航

侧栏新增 `costOptimization` 顶级入口，位于“预算”和“会话”之间。现有“性能”入口保留。

成本优化页包含五个页内标签：

1. 总览
2. 模型对比
3. 异常
4. 预测
5. 节省建议

### 12.2 总览

顶部指标：

- 当前报告期已计价费用与定价覆盖率
- 报告期末预计费用与预测区间
- 当前报告期异常数与严重异常数
- 去重后的保守可节省金额

主要区域：

- 实际费用、预测区间和预算线
- 按节省额排序的优先建议
- 最新异常及其逐层定位摘要

### 12.3 查询与设置

- 现有全局周期选择继续作为成本优化报告期。
- 页面新增项目范围筛选，默认全部项目。
- 项目和报告期属于临时查询状态，不写入分析配置。
- “分析设置”打开抽屉，编辑异常、预测和建议规则。
- 预测始终可以读取完整历史基线，不会因当前报告期筛选而丢失必要样本。

### 12.4 专项标签

- 模型对比：实际成本表、候选模型选择和替代场景结果。
- 异常：按层级、严重程度和范围筛选，支持展开贡献链。
- 预测：完整趋势图、预测区间、预算线、方法和样本说明。
- 节省建议：按金额、置信度和类型筛选，展开计算依据与风险。

## 13. 快照与状态模型

`CostOptimizationSnapshot` 至少包含：

- `generatedAt`
- `dataState: 'fresh' | 'stale'`
- `staleReason`
- 当前设置
- 当前查询范围
- 定价覆盖摘要
- 总览指标
- 模型对比结果
- 异常列表
- 预测结果或样本不足原因
- 建议列表和去重后节省摘要
- 缓存统计，包括本轮新增、修改、删除和复用来源数

Renderer 使用明确的渲染状态模型：

- `loading`
- `error`
- `ready`
- `stale`

定价不完整和样本不足属于模块级状态，不应升级为整个页面错误。

## 14. 失效与重算规则

| 变化来源 | 处理方式 |
| --- | --- |
| JSONL 新增 | 加入来源贡献，更新受影响聚合桶和派生结果 |
| JSONL 修改 | 撤销旧贡献，加入新贡献，更新受影响范围 |
| JSONL 删除 | 撤销贡献并删除归零桶 |
| 模型价格变化 | 复用 Token 索引，重算费用及依赖费用的结果 |
| 异常设置变化 | 仅重算异常及依赖异常的建议 |
| 预测设置变化 | 仅重算预测 |
| 建议设置变化 | 仅重算建议与去重摘要 |
| 本地日期跨日 | 更新报告期、预测起点和预算超限日期 |
| 缓存结构不兼容 | 使用当前完整扫描结果全量重建索引 |

每类重算由显式版本或签名控制，禁止通过比较完整 JSON 字符串隐式决定所有缓存失效。

## 15. 错误与降级

- 扫描失败：保留最后成功快照并标记 `stale`。
- 缓存损坏：丢弃缓存并从当前完整扫描结果重建。
- 配置损坏：保留备份，恢复默认设置并展示一次性警告。
- 未知模型价格：Token 统计继续可用，费用结果标记不完整。
- 定价覆盖率低于安全阈值：隐藏总节省额和完整费用预测。
- 历史不足：显示需要的样本数量，不返回零预测或零异常。
- 单个分析项失败：隔离该项并保留其他模块结果。
- 配置保存失败：保留当前配置和快照，展示可重试错误。

## 16. IPC 与安全边界

新增 IPC 能力：

- 获取成本优化快照
- 按查询范围请求快照
- 更新成本优化设置
- 订阅成本优化快照更新

Renderer 不能直接访问文件系统。主进程必须验证所有配置和查询输入，项目筛选只能引用当前扫描结果中存在的项目标识。

IPC 通道继续采用显式白名单注册和卸载。错误载荷使用结构化校验问题，不向 Renderer 暴露任意文件内容。

## 17. 国际化与可访问性

- 所有新增文案同时提供英文和简体中文资源。
- 金额、百分比、日期和数字继续使用当前语言环境格式化。
- 图表提供可访问名称和文本摘要。
- 标签、筛选器、设置抽屉和异常展开均可通过键盘操作。
- 颜色不作为严重程度、预测类型或置信度的唯一表达方式。
- 未计价、样本不足和风险说明必须以可见文字呈现。

## 20. 验收标准

- 用户能够查看按模型汇总的真实费用，并运行候选模型替代场景。
- 用户能够从日级异常逐层定位到项目、模型和会话。
- 历史满足条件时能够查看 7/30 天预测区间和预算超限日期。
- 用户能够查看带金额、依据、置信度和风险的建议。
- 顶部节省额不会重复累计覆盖同一用量的建议。
- 价格或分析设置变化不需要重新扫描 JSONL。
- 新增、修改和删除会话文件都能正确更新增量索引。
- 定价不完整、样本不足、缓存损坏和扫描失败均有明确且安全的降级行为。
- 所有新增界面支持英文、简体中文和键盘操作。
- 应用仍不修改或上传 Codex 会话数据。
