# GitHub 价格更新修复与无缓存价格模型支持

状态：用户已批准本版设计并完成本地实施与完整验证；后续于 2026-10-21 授权提交并合入 master，仍不推送。实施记录见[实施计划](../plans/2026-10-21-pricing-collector-repair.md)。

## 1. 问题与目标

[GitHub Actions 第 41 次运行](https://github.com/Nancyingcode/token-usage/actions/runs/39395124625)在 `npm run pricing:update` 阶段报错：`Standard text pricing section or unit is missing.`。依赖安装和 32 个价格相关测试通过，验证与发布步骤未执行。最近 6 次运行均在更新阶段失败。

2026-10-21 读取官方模型 Markdown 后确认：

- 解析器在 `## Pricing` 后遇到 `### Text tokens` 就截断内容；实际价格使用 `Metric / Price / Unit` 三列表格，每行单位为 `1M tokens`，现有解析器不支持该格式。
- 发现的 42 个 GPT/Codex 文本模型中，34 个有输入、缓存输入、输出三类价格，8 个只有输入和输出价格。现有目录与计算类型强制要求缓存价为数值，因此只修复格式仍无法完成更新。
- 远程 `pricing/catalog.json` 当前返回 HTTP 404，尚无可读取的已发布目录；仓库种子不含这 8 个缺缓存价格的模型。

原文示例：[Codex Mini](https://developers.openai.com/api/docs/models/codex-mini-latest.md)、[GPT-3.5 Turbo](https://developers.openai.com/api/docs/models/gpt-3.5-turbo.md)、[GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra.md)。旧解析器对 Codex Mini 原文已稳定复现同一错误。

目标是正常收录全部 42 个模型：有明确单价的用量正常计算，缺缓存单价的用量明确标记未计价，不猜价，也不将缺价当作免费。

## 2. 范围和不变量

本次修改采集与发布脚本、价格目录类型和校验、主进程同步与缓存、共享费用计算及其下游汇总、价格与计价质量界面、中英文文案和测试。复用现有 IPC、订阅、条件计价与格式化工具，不新增依赖。

继续遵守[联网价格设计](./2026-09-10-network-pricing-design.md)与[条件计价设计](./2026-09-10-conditional-pricing-design.md)中的本地估算、用户覆盖优先、逐请求条件计费和数据源只读原则。本设计补充“基础价格部分缺失”的语义，并升级目录格式。

- 不改动真实 Codex 会话目录，不上传会话内容。
- 不扩展模型发现范围到当前规则以外的模型系列，也不自动推导新的条件倍率。
- 不更改已有用户手动价格、未知模型兜底或预算配置的存储格式。
- 最初本地实施范围不包含 commit、push 或远程发布；后续用户已单独授权提交并合入 master，远程验收仍待推送及发布授权。

## 3. 缺缓存价的数据语义

新增目录 v3，`cachedInputUsdPerMillion` 为必填的 `number | null`：

| 值 | 含义 | 行为 |
| --- | --- | --- |
| 有限非负数，包括 0 | 明确记录的缓存输入单价 | 按数值计价，0 是明确免费 |
| `null` | 官方价格表未提供独立缓存输入单价 | 缓存用量保持未计价 |
| 缺字段、字符串、非法数值 | 无效目录 | 拒绝整次更新 |

`null` 不代表模型不支持缓存，也不代表普通输入单价适用于缓存 Token。即使官方说明“没有缓存折扣”，本次也不自动推导缓存单价。

`ModelPricingEntry` 与手动覆盖的价格输入类型解耦，仅目录条目允许缓存价为 `null`。`ModelPricingOverrideInput` 和未知模型兜底仍要求三项有限非负数，避免改写已有用户假设或引入无关迁移。

## 4. 官方 Markdown 采集

- 按标题层级定位唯一 Pricing 节，保留子标题，遇到同级或更高级标题才结束；只读取唯一的 Text tokens 基础价格表。
- 支持官方的 `Metric / Price / Unit` 表，逐行验证美元数值和 `1M tokens` 单位。已知缓存写入行独立识别，不用它补充缓存读取价格。
- 不读取 Quick comparison、音频价格或其他模型价格；独立 Batch/Flex/Fast 价表不能被当作标准基础价。条件倍率说明仍由现有已核对规则处理。
- 对当前三列格式，输入与输出行必须存在且有效。缓存行完全不存在、表格结构完整、指标名均被识别时，返回显式 `null`；不再使用模型例外名单。旧分行格式仍保持原有严格要求，不凭不完整文本推断 `null`。
- 畸形行、改名的缓存指标、重复指标、重复价格节、无效缓存值、错误单位、缺输入或输出、网络异常均使整次采集失败。
- 历史模型从未提供缓存价时可继续为 `null`；以后出现明确价格则正常转为数字并更新观察日期。已有数字缓存价突然消失时拒绝自动降为 `null`，要求维护者核对，避免页面变化静默降低覆盖率。
- 保留官方目录中不再出现的历史模型。历史身份按规范化 modelId 与 aliases 检查，别名冲突继续拒绝。
- 失败信息包含模型 ID、来源 URL 和原因。所有模型成功采集、合并并校验后才进入文件写入阶段。

当前无缓存价的 8 个模型是 `gpt-3.5-turbo`、`gpt-4`、`gpt-4-turbo`、`gpt-4-turbo-preview`、`gpt-5-pro`、`gpt-5.2-pro`、`gpt-5.4-pro`、`gpt-5.5-pro`。该列表仅记录核对结果，不是程序筛选名单。

## 5. 目录发布与版本兼容

在独立 pricing 分支并行提供三份文件：

| 文件 | 格式 | 模型集合 |
| --- | --- | --- |
| `catalog-v3.json` | schemaVersion 3，保留条件规则，允许显式空缓存价 | 完整模型集合，包括无缓存价模型 |
| `catalog-v2.json` | schemaVersion 2，三类价格必须为数值 | v3 中缓存价为数值的条目，保留条件规则 |
| `catalog.json` | schemaVersion 1，三类价格必须为数值 | 与 v2 相同集合，去除条件规则 |

三份目录共享 version 和 publishedAt。旧客户端继续获得其可表达的完整价格模型；无缓存价模型需要新客户端读取 v3 才能计入输入和输出费用。

采集器读取历史基准时优先 v3，仅 HTTP 404 时逐级读取 v2、v1；全部 404 才读取仓库种子。其他网络或格式错误不得当作首次发布。解析后的目录版本必须与文件版本匹配，不能将 v2 内容伪装成有效 v3。

已有数字价不能自动退化为空价，因此兼容目录不会丢失原已计价模型。历史保留检查涵盖 v3 的空价和数值价条目，并检查既有 v1/v2 模型在各自兼容视图中仍然存在。

发布前使用同一校验器检查三份目录，并验证 v1/v2 正好是 v3 的上述投影，不能只比较时间戳。全部文件由一个 Git tree、一个提交和一次非强制 ref 更新对外生效。发布器针对读取到的父提交核对历史模型和发布时间；父提交变化时非强制更新失败，避免覆盖并发发布。

本地多文件写入不宣称跨文件原子性：采集或校验失败时不写入；写入失败时命令失败，工作流不进入发布。发布器拒绝版本或内容不一致的残留文件，旧远程目录保持有效。

## 6. 客户端同步与缓存

客户端下载顺序为 v3 → v2 → v1，仅 404 回退；现有超时、响应大小、无凭据和拒绝重定向限制不变。界面来源 URL 与实际使用的目录版本一致。

继续拒绝 schema 降级、发布时间倒退、历史模型减少；补充拒绝已知数字缓存价降为 `null` 的更新。已经成功缓存 v3 后，远程暂时只剩旧版本时保留 v3 缓存并报告失败，不用旧目录覆盖。

为保留应用回滚能力，新版使用 userData 内的 `pricing-cache-v3.json`，外层缓存结构保持现有格式。仅新文件不存在时，只读导入旧 `pricing-cache.json` 中的有效 v1/v2 目录和偏好，原子保存到新路径；后续只写新文件。新缓存损坏、权限错误或读取失败不伪装成“文件不存在”，沿用现有错误与内置价格回退流程。旧缓存不修改、不删除，旧版应用仍能读取。

价格变更仍沿现有预算与成本分析订阅重新计算；当前价格签名已经序列化完整条目，应测试数值与 `null` 切换会使派生结果失效。不修改会话扫描数据格式，不通过重新扫描真实会话补造价格。

## 7. 部分计价与覆盖率

继续逐请求划分普通输入、缓存读取、缓存写入和输出，再汇总。缓存 Token 沿用现有合法范围归一化，不重复包含在普通输入里。

- 缓存价为 `null` 且缓存用量为 0：正常计算输入和输出，不产生缓存缺价提示。
- 缓存价为 `null` 且缓存用量大于 0：保留普通输入、输出及有明确规则的缓存写入金额；仅缓存读取 Token 进入未计价数量，并记录 `cached-input-price-unavailable` 原因。
- 不用普通输入价补齐，不把未计价 Token 归入未知模型兜底，也不把整个请求判为未计价。
- 手动覆盖补齐缓存单价后，按现有用户覆盖优先级重新计价；删除覆盖后恢复官方缺价状态。

计算结果显式携带已知费用、费用构成、未计价 Token 和原因。`UsagePricingResult` 区分完整与部分计价，所有汇总使用真实数量，不能仅凭“找到模型价格条目”判为完整计价。对包含空价的价格条目，数值型便捷函数不能成为丢弃未计价信息的路径；相关调用改用结构化结果。

新增缺价原因与现有条件假设独立。条件不完整时，假设计价数量只覆盖已计价部分；未计价原因即使条件假设数量为 0 也必须传递。每个有效用量汇总满足：

`规则匹配 Token + 未知模型假设 Token + 条件假设 Token + 未计价 Token = 总 Token`。

示例仅用于测试语义：输入 1,000、其中缓存 200、输出 100；输入价每百万 $10、输出价每百万 $50、缓存价 `null`。已知费用为 $0.013，未计价 200 Token，价格覆盖率为 900/1,100。若该请求没有缓存用量，则输入和输出全部计价。费用仍是本地估算，部分金额不能描述为完整费用。

## 8. 汇总、预算和建议

- 概览、每日趋势、项目/会话汇总、预算和费用效率使用同一部分计价结果；保留已知金额，同时显示未计价数量和原因。
- 预算沿用 `unpricedTokens > 0` 的不完整标记，已知金额仍可触发已达到的阈值；未超过阈值不能被解释为完整用量都在预算内。
- 未计价模型列表纳入部分计价模型，但只累计其未计价 Token，不重复统计整个请求。
- 价格覆盖率为已计价 Token / 总 Token，精确覆盖率为规则匹配 Token / 总 Token；两者分母保留未计价部分。单位成本使用已计价 Token 作分母，不将缺价显示为零费用带来的效率提升。
- 现金节省建议、模型替换比较和模型费用诊断，必须在相关实际用量和假设场景均完整计价时才给出金额结论。缺缓存价的模型不生成“提升缓存命中率可以节省多少”的建议，即使原始用量恰好无缓存。
- 有数据不足的场景保留现有解释入口，不将缺价候选模型排成最便宜，也不扩展现有候选模型系列范围。

## 9. 界面与用户覆盖

模型价格表对空缓存价显示“官方未提供”/“Not published”，不能传给金额 formatter 显示成 $0。提供可通过键盘访问的说明：输入和输出仍计价，有缓存用量时该部分未计价。

费用质量提示独立显示缓存缺价原因和未计价数量，不依赖条件假设数量大于 0。费用构成中已知缓存费用可以为 0，但必须结合缺价说明，避免看起来是免费。

编辑无缓存价模型时缓存输入框为空，并提示用户覆盖需要填写明确数值；空白不得通过 `Number('')` 变成 0，也不显示字符串 `null`。用户只使用官方输入/输出价格时无需创建覆盖；提交完整手动价格和恢复默认继续沿用现有流程。

新增文案同时维护英文和简体中文资源，错误、状态与说明具有可访问名称，不仅靠颜色表达。沿用已有抽屉焦点管理，不新增交互模式。
