# 未知模型计价设计

## 1. 背景

当前应用已经支持两类常规模型价格：

- 随应用发布的内置模型价格；
- 用户按具体 Model ID 新增或覆盖的自定义价格。

扫描结果中的“未计价”实际上包含两种不同情况：

1. 日志带有具体 Model ID，但该 ID 没有匹配到价格；用户已经可以为该 ID 单独新增价格。
2. 日志完全缺少 Model ID；现有实现只能显示为“未知模型”，无法创建一个安全的具体模型价格条目。

本功能只解决第二种情况。它新增一条独立的“缺失 Model ID 兜底计价规则”，让用户可以主动为无法归属模型的 Token 设置估算单价。兜底规则不是官方价格，也不表示应用识别出了真实模型；所有由它产生的费用必须持续标记为“假设计价”。

## 2. 目标

- 用户可以为完全缺失 Model ID 的用量配置输入、缓存输入和输出单价。
- 兜底计价默认关闭；未配置时继续保持当前未计价行为。
- 应用不根据模型名称、相近型号、时间或历史记录自动猜测价格。
- 有具体 Model ID 的未计价用量继续要求逐模型补价，不使用缺失 ID 兜底规则。
- 费用汇总、预算、成本分析和预测可以纳入兜底估算，同时明确区分精确计价、假设计价和未计价 Token。
- 原始 Token、模型归属和会话日志始终保持不变；兜底规则只影响派生费用。
- 配置修改后只重新计算派生结果，不重新扫描或修改 Codex 会话目录。

## 3. 非目标

- 不联网识别未知模型或自动抓取价格。
- 不把字符串 `unknown`、`Unknown model` 或其他展示文案保存为真实 Model ID。
- 不为带有具体但未定价 Model ID 的用量自动应用兜底规则。
- 不提供按项目、日期或会话分别配置多条未知模型价格。
- 不尝试还原缺失 Model ID 的真实模型。
- 不把本地估算描述为 OpenAI 实际账单。
- 不在首版引入价格生效区间或历史版本；与现有用户价格覆盖一致，当前配置会重新估算当前可见历史数据。

## 4. 核心语义

### 4.1 三种计价状态

费用计算必须区分以下状态：

| 状态 | 条件 | 费用处理 | 用户可见语义 |
| --- | --- | --- | --- |
| 精确计价 | 具体 Model ID 命中内置或用户价格 | 按命中价格计算 | 已计价 |
| 假设计价 | Model ID 缺失且用户启用了兜底规则 | 按兜底价格计算 | 包含未知模型假设 |
| 未计价 | 具体 Model ID 无价格，或 Model ID 缺失且未启用兜底 | 不产生费用 | 计价不完整 |

“精确计价”仅表示价格表与日志中的具体 Model ID 匹配，不表示费用等同于实际账单。应用中的所有费用仍是本地估算。

### 4.2 匹配优先级

每个用量切片按以下顺序选择价格：

1. `modelId` 去除首尾空格后非空：只按规范 Model ID 和别名查找价格。
2. 具体 Model ID 未命中：保持未计价，不使用未知模型兜底规则。
3. `modelId` 缺失或去除首尾空格后为空：若已配置兜底规则，则按该规则假设计价。
4. 缺失 Model ID 且未配置兜底规则：保持未计价。

该顺序确保兜底规则不会掩盖新增具体模型价格的需求，也不会因某个未来模型暂时不在内置表中而被静默套用错误价格。

### 4.3 费用公式

兜底规则沿用现有模型计价公式：

```text
普通输入 Token = max(inputTokens - cachedInputTokens, 0)
假设费用 = 普通输入 Token × 兜底输入单价
         + cachedInputTokens × 兜底缓存输入单价
         + outputTokens × 兜底输出单价
```

单价均按每百万 Token、美元计。`reasoningOutputTokens` 仍作为 `outputTokens` 的明细，不重复计价。

### 4.4 汇总口径

`pricedCostUsd` 继续表示当前价格配置下可计算的费用总和，包含精确费用和假设费用，以减少现有预算与汇总调用方的破坏性迁移；同时新增假设计价明细，使调用方不能把全部 `pricedCostUsd` 误当成具体模型价格：

```ts
interface CostEstimate {
  pricedCostUsd: number;
  assumedCostUsd: number;
  assumedTokens: number;
  unpricedTokens: number;
  unpricedModelIds: string[];
}
```

约束：

- `assumedCostUsd` 是 `pricedCostUsd` 的子集。
- `assumedTokens` 不计入 `unpricedTokens`。
- 具体 ID 无价格时，该 ID 继续进入 `unpricedModelIds`。
- 缺失 ID 且未配置兜底时，仍使用本地化“未知模型”展示，但领域层不以该文案作为业务键。
- 原始 Token 总量可由精确计价 Token、`assumedTokens` 和 `unpricedTokens` 完整对账。

成本优化模块的 `PricingCoverage` 同步增加 `assumedTokens`、`assumedPercentage` 和 `exactPercentage`。现有 `pricedTokens` 与 `percentage` 表示“已有某种价格规则覆盖”，其中包含假设计价；界面必须同时展示精确覆盖率或假设 Token，避免把 100% 规则覆盖误读为 100% 模型识别。

## 5. 数据模型与持久化

### 5.1 独立兜底配置

兜底规则使用独立类型，不复用 `ModelPricingOverride`，从类型层阻止其被当成普通 Model ID 或别名参与索引：

```ts
interface UnknownModelPricingInput {
  inputUsdPerMillion: number;
  cachedInputUsdPerMillion: number;
  outputUsdPerMillion: number;
}

interface UnknownModelPricing extends UnknownModelPricingInput {
  updatedAt: string;
}
```

`PersistedBudgetConfig` 新增可选字段：

```ts
unknownModelPricing?: UnknownModelPricing;
```

字段缺失代表兜底计价关闭。删除兜底规则时移除该字段，缺失 Model ID 的历史用量立即恢复为未计价。

### 5.2 Schema 迁移

预算配置 schema 从版本 2 升级到版本 3：

- 版本 1 继续先补齐现有模型预算目标，再迁移到版本 3。
- 版本 2 配置迁移时设置 `unknownModelPricing` 为缺失，不改变任何费用结果。
- 版本 3 对兜底单价和更新时间执行运行时校验。
- 无效兜底字段不应静默变成零价规则；配置读取沿用现有损坏配置处理策略。
- 未来版本继续拒绝覆盖。

### 5.3 校验

- 三项价格必须是大于或等于 0 的有限数字。
- 表单字段不能为空。
- 允许显式保存三项均为 0 的规则，以覆盖确实无需计费的本地或特殊环境；保存前界面必须展示“所有未知模型用量将按零费用估算”的明确确认提示。
- 主进程重复执行相同校验，不能只依赖 Renderer。
- 保存时间由主进程生成，Renderer 不提交或信任 `updatedAt`。

## 6. 领域计算与数据流

### 6.1 统一计价上下文

预算计价和成本优化目前各自构建模型价格索引。实现时新增共享的纯函数计价上下文，至少包含：

- 规范 Model ID 与别名索引；
- 可选的未知模型兜底规则；
- 单个 Token 用量按指定价格计算费用的纯函数；
- 单个切片返回精确、假设或未计价结果的判别函数。

预算汇总与成本优化必须复用同一判别逻辑，防止一个页面把缺失 ID 计价、另一个页面仍显示未计价。

### 6.2 预算

- 费用预算的 `used` 使用精确费用与假设费用之和。
- 仍有真正未计价 Token 时，费用进度保持 `incomplete`。
- 只有假设计价、没有未计价 Token 时，费用进度不再是“不完整”，但增加 `assumedTokens` 或等价状态字段，并显示“包含未知模型假设”。
- 假设费用参与预警、严重和超预算阈值计算；通知文案必须说明费用包含未知模型假设。
- 低于阈值时不能只用绿色表达安全状态；假设标识始终保留。
- “未计价模型数量”不再包含已被兜底规则覆盖的缺失 ID 分组；预算摘要新增“假设计价”状态，不把它伪装成具体模型已定价。

### 6.3 成本优化

- 总费用、模型费用表、异常检测和预测纳入假设费用。
- 缺失 ID 继续单独显示为“未知模型”，并标记兜底假设来源。
- 预测的价格覆盖门槛使用包含兜底规则的覆盖率，但同时展示精确覆盖率与假设占比。
- 因缺少真实模型身份，未知模型分组不得作为模型替换建议的来源模型，也不得生成“模型费用主导”诊断。
- 依赖假设费用生成的异常、预测或节省建议必须携带假设覆盖信息；推荐置信度最高为中等。
- 候选替代模型仍必须是带具体 ID 且已配置价格的模型，未知模型兜底规则不能成为候选模型。

### 6.4 刷新

保存或删除兜底规则后：

1. 主进程原子写入配置；
2. 使用内存中的最近一次扫描结果重新评估预算；
3. 重新评估成本优化快照；
4. 通过现有类型化 IPC 推送新快照。

该流程不得重新读取、修改、删除或上传 Codex 会话文件。

## 7. IPC 与运行时

在现有预算 API 中新增两项操作：

- 保存未知模型兜底价格；
- 删除未知模型兜底价格。

主进程负责输入校验、时间戳生成、配置持久化和重新评估。Preload 只暴露类型化方法，不向 Renderer 暴露文件系统或 `ipcRenderer`。

预算快照和成本优化快照都携带当前可选兜底规则，Renderer 不在本地复制一份持久状态。

如果预算配置已保存但成本优化重新评估失败，预算配置仍然有效；界面保留最近成功的成本优化快照并标记过期，不能回滚或丢失已写入配置。

## 8. 页面与交互

### 8.1 模型价格页面

在普通模型价格表上方增加独立卡片“未知模型兜底计价”：

- 未启用：说明缺失 Model ID 的 Token 保持未计价，并提供“设置兜底价格”。
- 已启用：展示三项单价、更新时间、“用户假设”来源标识，以及“编辑”和“停用”操作。
- 说明文字明确：“只应用于缺失 Model ID 的用量；不会应用于带有具体但未定价 ID 的模型。”
- 未计价列表中缺失 ID 的“未知模型”行可提供同一设置入口；带具体 ID 的行继续进入逐模型新增价格流程。
- 兜底规则不进入普通模型价格表、模型组合框、别名列表或候选替代模型列表。

编辑沿用右侧抽屉视觉结构，但不显示 Model ID 和别名字段。停用需要确认，并说明历史费用会恢复为未计价；该操作只删除配置，不删除任何 Token 数据。

### 8.2 费用结果

所有受影响页面使用一致状态文案：

- `已计价`：只有具体模型价格。
- `包含未知模型假设`：至少有一个缺失 ID 切片使用兜底规则。
- `计价不完整`：仍存在没有任何价格规则的 Token。

当假设计价和未计价同时存在时，优先显示“计价不完整”，并在明细中继续展示假设 Token 和未计价 Token。

新增或修改的文案同时维护英文和简体中文资源；金额、百分比和日期继续使用现有 locale formatter。所有按钮支持键盘操作，状态不只依赖颜色表达。

## 9. 错误与边界场景

- 兜底配置不存在：行为与当前版本完全一致。
- 具体 Model ID 仅由空格组成：按缺失 ID 处理，不能保存空白模型价格。
- 有具体 Model ID 但价格缺失：不应用兜底，继续未计价。
- 兜底规则三项均为 0：确认后允许，费用为 0，但仍显示“包含未知模型假设”。
- 兜底保存失败：抽屉保持打开并展示字段级或表单级错误。
- 停用保存失败：保留现有规则和当前估算结果。
- 配置损坏或未来 schema：沿用现有备份、恢复或拒绝覆盖策略，不能修改会话日志。
- 历史数据重新估算：页面明确当前规则会应用于当前可见历史数据，不暗示价格在历史发生时已经生效。
- 别名碰撞和大小写差异：只影响具体模型价格索引，不影响缺失 ID 兜底规则。

## 10. 测试策略

### 10.1 领域回归测试

- 未配置兜底时，缺失 ID 继续未计价。
- 配置兜底后，缺失 ID 使用正确的普通输入、缓存输入和输出公式。
- 假设费用是总已计费用的子集，Token 能完整对账。
- 带具体但未定价 ID 的切片不会错误使用兜底。
- 空白 ID 与缺失 ID 使用相同语义。
- 具体模型、别名、假设和未计价切片混合时汇总正确。
- 输入对象与价格配置不被纯函数修改。

### 10.2 存储、运行时与 IPC 测试

- schema 2 无损迁移到 schema 3，费用行为不变。
- 有效配置往返持久化；无效、非有限和负数价格被拒绝。
- 保存时间由主进程生成。
- 保存与删除后复用内存用量重新计算预算和成本优化快照。
- IPC 输入错误返回可展示的类型化错误。
- 配置文件写入失败时不发布虚假的成功快照。

### 10.3 预算与成本优化测试

- 假设费用参与预算阈值和通知，且带有假设标识。
- 真正未计价 Token 仍使费用状态不完整。
- 规则覆盖率、精确覆盖率和假设占比正确。
- 未知模型行能展示假设费用。
- 未知模型不生成模型替换来源或模型费用主导诊断。
- 依赖假设费用的分析结果不会获得高置信度。

### 10.4 React 与国际化测试

- 未启用和已启用卡片状态。
- 新增、编辑、全零确认和停用确认流程。
- 缺失 ID 与具体未定价 ID 的入口不同。
- 预算、成本概览和价格页展示一致的假设计价文案。
- 英文和简体中文资源均可渲染。
- 按钮、抽屉和确认交互可使用键盘完成。

### 10.5 完整验证

实现完成前至少运行：

```text
npm test
npm run typecheck
npm run lint
npm run build
```

本功能修改共享类型、Electron 主进程、Preload、IPC 和持久化 schema，因此按项目规范额外运行构建验证。

## 11. 实施边界

该功能是跨共享领域层、主进程、Preload、Renderer、持久化和国际化的行为变更。设计确认后另行在 `docs/superpowers/plans/` 编写中文实施计划，并按以下依赖顺序拆分红—绿—重构任务：

1. 数据类型、校验和 schema 迁移；
2. 统一计价纯函数与预算回归；
3. 成本优化覆盖与分析保护；
4. 主进程运行时、IPC 和 Preload；
5. 模型价格页面与双语状态展示；
6. 完整验证和文档更新。

实现不得覆盖当前工作区中与本功能无关的模型价格组合框改动。

## 12. 验收标准

- 默认状态下，未知模型计价行为与当前版本一致。
- 用户可以显式配置、编辑和停用缺失 Model ID 的兜底价格。
- 兜底规则只应用于真正缺失 Model ID 的用量。
- 具体未定价模型仍要求按真实 Model ID 新增价格。
- 假设费用参与汇总、预算和允许的成本分析，但始终带有可见假设标识。
- 未知模型不会进入依赖真实模型身份的替换或模型主导诊断。
- 所有 Token 始终保留，并能在精确计价、假设计价和未计价三类之间完整对账。
- 所有费用继续明确为本地估算，不描述为 OpenAI 实际账单。
- 配置持久化、schema 迁移、IPC 和 UI 均通过回归测试、完整测试、类型检查、lint 与构建验证。
