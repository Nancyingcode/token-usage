# 概览活动日历 GitHub 式布局设计

## 1. 背景

概览页当前使用 84 个连续日期单元展示 Token 活动，但 CSS 将其排成 3 行、28 列，日期按行从左到右填充。左侧却显示周一、周三、周五标签，因此日期位置与星期标签不对应，也无法形成 GitHub 贡献日历常见的“每列一周、每行一个星期”的阅读方式。

当前活动单元已经提供可聚焦的 `aria-label`，但鼠标悬停或键盘聚焦时没有可见说明。用户只能依赖颜色判断强度，无法直接读取某天的日期和 Token 数量。

本次调整参考 GitHub contribution calendar 的信息结构，而不是复制 GitHub 的品牌视觉。GitHub 官方将该区域定义为按日期查看活动概况的 contributions calendar，并支持从日期方格查看单日活动；本项目将相同交互语义映射为本地 Token 用量。

## 2. 目标

1. 将活动改为 53 个完整自然周的年度日历布局：横向为周，纵向为星期。
2. 在日历顶部显示月份提示，左侧显示周一、周三、周五，与实际日期行严格对齐。
3. 鼠标悬停或键盘聚焦任意可用日期时显示 tooltip，包含本地化日期和当天 Token 总量。
4. 保留 5 档强度语义，并增加“少—多”图例，避免仅凭色阶猜测。
5. 明确区分零用量、当前筛选周期之外和扫描日期之后三种状态。
6. 保持活动日历只读，不增加点击、日期筛选或导航行为。

## 3. 非目标

- 不扩展为无限历史或分页日历；活动面板固定显示最近 53 个自然周。
- 不复制 GitHub 的绿色色值、边框、字体或贡献计数文案。
- 不改变 Today、Week、Month、All time 的全局筛选语义。
- 不增加按天会话明细、弹窗或跳转。
- 不改变 Token 聚合、费用估算或会话扫描逻辑。

## 4. 日历数据模型

### 4.1 日期窗口

`anchorDate` 仍取最近扫描时间的 UTC 日期。展示窗口按自然周对齐：

- 找到 `anchorDate` 所在周的周日。
- 向前取 52 个完整周，作为第一列。
- 生成 53 周 × 7 天，共 371 个日期单元。
- 最后一列持续到 `anchorDate` 所在周的周六。

这样每列始终是周日到周六，星期标签不会随扫描日期漂移。`anchorDate` 之后、但位于最后一周内的日期属于未来占位，不展示用量，也不进入键盘焦点顺序。

### 4.2 单元状态

`ActivityCell` 在现有 `date`、`tokens`、`level`、`inPeriod` 基础上补充足以表达布局和状态的字段，例如 `weekIndex`、`weekday` 与 `isFuture`。具体字段名可在实施计划中按测试需要确定，但必须保持模型为无副作用纯函数。

单元状态按以下优先级决定：

1. `future`：日期晚于 `anchorDate`。视觉上为空占位，`aria-hidden="true"`，不可聚焦。
2. `outside-period`：日期不晚于扫描日，但早于当前滚动周期起点。使用现有斜线纹理，`aria-hidden="true"`，不可聚焦。
3. `level-0`：位于周期内且 Token 为零。显示最低档中性色，可聚焦并可显示“0 Token” tooltip。
4. `level-1` 至 `level-4`：位于周期内且有用量，沿用产品品牌色阶。

强度最大值只从“当前周期内且不晚于扫描日”的日期计算，未来日期和周期外日期不影响色阶。

### 4.3 月份标签

日历模型为 53 个周列生成月份标签槽位。当某个周列包含当月 1 日时，在该周列上方显示本地化月份缩写。窗口第一列即使不包含 1 日，也显示该列所处月份，确保左侧不会出现无上下文的空白。

月份通过 `Intl.DateTimeFormat` 使用当前 Renderer locale 格式化，不在组件中硬编码英文月份。

## 5. 布局与响应式行为

### 5.1 桌面布局

活动区域由四部分组成：

1. 顶部月份标签行。
2. 左侧星期标签列，仅显示周一、周三、周五。
3. 53 列 × 7 行日期网格，每列代表一个自然周。
4. 底部强度图例，显示本地化的“少”和“多”以及 5 个色阶单元。

日期 DOM 顺序保持从最早到最晚，CSS 使用按列填充的 7 行网格，使视觉顺序和读屏顺序都按日期递增。格子尺寸、间距和面板 token 延续当前设计系统。

### 5.2 窄窗口

不把日历改回 14 或 28 列的多段换行，因为这会破坏自然周语义。53 周使用固定尺寸方格自然铺开宽面板；空间不足时活动日历容器允许横向滚动，星期标签固定在左侧或保持在滚动区之前，年度周序列不折行、不压缩方格。

## 6. Tooltip 交互

`ActivityGrid` 维护唯一的活动日期状态，由单元的 `mouseenter` / `mouseleave` 与 `focus` / `blur` 更新。tooltip 只负责展示派生数据，不单独保存 Token 或坐标业务状态。

可见 tooltip 包含：

- 本地化的完整日期。
- 当天格式化后的 Token 总量。

tooltip 在当前格子上方居中显示；靠近左右边界时切换对齐方式，避免溢出面板。其本身不接收指针事件。单元继续保留与 tooltip 等价的本地化 `aria-label`，保证键盘和读屏用户不依赖浮层内容。

hover 与 `:focus-visible` 同时提供清晰轮廓，颜色不作为当前活动单元的唯一提示。移动指针离开或焦点移出时关闭 tooltip。

## 7. 国际化与可访问性

英文和简体中文资源同步增加：

- 强度图例的“Less / More”“少 / 多”。
- tooltip / `aria-label` 所需的单日 Token 文案，如现有 `activityDay` 能满足则复用。

月份和完整日期由 locale formatter 产生。活动格使用 `role="img"` 和 `tabIndex={0}`，不使用按钮角色，因为它没有点击动作。周期外与未来占位均不进入读屏和键盘顺序。

## 8. 测试策略

遵循红—绿—重构：

1. 先扩展 `activityGrid` 回归测试，验证自然周对齐、371 个单元、未来占位、周期边界、月份标签和强度计算。
2. 扩展 Overview 渲染测试，验证 53 周 × 7 行结构、星期与月份标签、强度图例、可聚焦单元及初始无 tooltip。
3. 使用 DOM 交互测试触发 hover、mouseleave、focus 和 blur，验证可见 tooltip 文案与关闭行为。
4. 检查中英文资源与 locale 日期格式。
5. 完成前运行 `npm test`、`npm run typecheck`、`npm run lint`。本次不修改 Electron 主进程、preload 或构建配置，无需额外执行 `npm run build`。

## 10. 验收标准

- 任意扫描日期下，横向每列均代表周日到周六，左侧星期标签与日期位置一致。
- 日历固定展示 53 个周列，共 371 个日期槽位，最后一列包含扫描日。
- 未来日期与周期外日期不能被误认为零用量。
- 任意周期内日期在 hover 和键盘 focus 时显示日期与 Token 数量 tooltip。
- tooltip 在左右边缘不超出活动面板。
- 底部显示 5 档强度图例，并有“少—多”文本语义。
- 中英文界面均无硬编码或缺失翻译。
- 全量测试、类型检查和 lint 全部通过。
