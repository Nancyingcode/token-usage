# 网络价格目录：第一阶段设计

状态：用户已确认方案 C 第一阶段，并确认使用当前仓库的 pricing 分支托管。

## 范围

同步标准文本输入、缓存读取输入、输出三类美元每百万 Token 单价。所有费用继续为本地估算，按当前价格重算历史用量；不支持长上下文倍率、Fast、Batch、缓存写入等条件费用，不声称等同实际账单。

## 数据流

GitHub Actions 定时读取官方模型目录与模型 Markdown 文档，严格解析基础价格，生成版本化 JSON，并发布到独立 pricing 分支。保留旧模型；发现新模型自动收录，无法解析时保留旧数据并使任务失败，禁止猜价或发布不完整更新。发布任务只在用户启用工作流后运行。本次本地开发不提交、不推送。

客户端固定读取 https://raw.githubusercontent.com/Nancyingcode/token-usage/pricing/catalog.json 。主进程联网，不需要 API Key，不上传模型列表、路径或会话内容。禁止重定向；限制超时和响应大小。目录包含 schemaVersion、version、publishedAt、currency、unit、模型 ID、显式别名、三类价格、来源 URL 和观察日期。观察日期不是官方历史调价日期。

## 合并与存储

用户覆盖优先于远程目录，远程目录优先于内置目录；跨模型别名冲突拒绝，用户显式覆盖具有最高匹配优先级。未知模型保持未计价。远程目录必须为非空有效目录，价格必须有限且非负，币种和单位固定，时间与来源必须有效。缓存原子替换，失败保留上次有效目录。缓存和自动更新偏好位于应用 userData，与会话目录隔离。缓存损坏可回退内置目录并显示错误。

## 生命周期

启动先读取本地缓存，预算与成本运行时使用同一目录初始化，网络请求不阻塞首屏。默认开启自动更新；启动和运行期间每 24 小时检查，失败或发现未计价模型最多每小时重试；手动刷新不受自动开关影响。并发刷新合并，销毁后停止定时器和请求。更新预算快照后沿现有订阅链使成本分析失效并重新计算，不重新扫描会话。仅价格改变不触发桌面预算通知，扫描 stale 状态保持。

## 用户界面

模型价格页提供自动更新开关、立即更新、状态、最后检查时间、目录版本与来源地址。价格来源区分联网、内置、用户覆盖。展示标准基础价格限制与历史重算口径。失败信息通过可访问状态区域呈现，中文和英文同步维护。

## 验证

使用 fixture、模拟网络和临时目录验证校验、合并、超时、大小限制、缓存失败、并发刷新、自动更新开关、停止清理、预算重算、IPC 与界面交互。脚本验证官方 Markdown 解析和异常不发布。最终运行 npm test、npm run typecheck、npm run lint、npm run build。
