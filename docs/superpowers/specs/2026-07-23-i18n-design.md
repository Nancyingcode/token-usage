# 中英文国际化设计

## 1. 背景

当前 Electron 应用的 Renderer 界面、表单校验、日期与数字格式以及主进程系统通知均使用硬编码英文。需要引入统一的国际化能力，首期支持英语和简体中文，并确保语言切换同时作用于 React 界面与 Electron 主进程生成的用户可见内容。

## 2. 目标

- 支持 `en` 与 `zh-CN` 两种语言。
- 首次启动默认跟随系统语言：所有中文区域映射为 `zh-CN`，其他语言映射为 `en`。
- 在工具栏提供“中文 / English”语言选择器。
- 持久化用户手动选择，并在应用重启后恢复。
- 国际化所有应用自有的可见文案，包括无障碍属性、校验消息、扫描警告说明和系统预算通知。
- 日期、数字、百分比与美元金额按当前语言格式化。
- 保持业务数据、模型标识和错误诊断信息不受界面语言影响。

## 3. 非目标

首期不包含：

- 英语和简体中文以外的语言。
- 在线翻译资源、远程加载或翻译管理平台。
- 根据语言切换货币或重新计算价格。
- 翻译用户数据、文件路径、模型 ID、项目名称和底层操作系统错误详情。
- 提供“恢复跟随系统”选项；系统语言只用于没有用户偏好时的初始选择。

## 4. 技术选型

使用 `i18next` 与 `react-i18next`：

- `i18next` 负责资源、回退、插值、复数和主进程翻译。
- `react-i18next` 通过 `initReactI18next` 与 `useTranslation` 将语言变化传播到 React 组件。
- 不使用浏览器语言检测、HTTP backend 或文件系统 backend。两种语言的资源随应用静态打包，当前语言由主进程统一解析。
- Renderer 与主进程分别通过 `createInstance()` 创建 i18next 实例，避免跨 Electron 进程共享可变单例。

官方参考：

- [react-i18next Quick start](https://react.i18next.com/guides/quick-start)
- [i18next instance API](https://www.i18next.com/overview/api)
- [i18next plural rules](https://www.i18next.com/translation-function/plurals)

## 5. 语言与资源模型

### 5.1 语言类型

共享层定义：

```ts
type SupportedLocale = 'en' | 'zh-CN';
```

只接受上述值进入存储、IPC 和 i18next 实例。系统 locale 归一化规则为：

- locale 去除首尾空白并忽略大小写。
- 以 `zh` 开头的合法区域值映射到 `zh-CN`。
- 其他值、空值和无法识别的值映射到 `en`。

模型 ID、别名和路径等业务归一化仍固定使用现有的 `en-US` 或语言无关规则，不能随界面语言改变。

### 5.2 资源组织

资源位于 `src/shared/i18n/`，按功能命名空间组织：

- `common`：通用按钮、状态、导航、日期范围和无障碍文案。
- `overview`：概览、项目、会话与性能页面。
- `budgets`：预算中心、抽屉、价格表、校验和应用内告警。
- `settings`：本地数据、隐私、扫描警告与空状态。
- `notifications`：系统预算通知。

英语是基准资源，简体中文必须具有相同命名空间和键结构。TypeScript 的 i18next module augmentation 从资源结构推导合法键，阻止组件引用不存在的键。

动态内容使用插值。计数统一使用名为 `count` 的参数，并按 i18next JSON v4 的 `_one`、`_other` 规则定义英文复数；中文使用符合中文表达习惯的单一结果。

## 6. 进程架构

### 6.1 共享层

`src/shared/i18n/` 只包含语言类型、资源、归一化函数和公共 i18next 初始化选项，不依赖 Electron 或 React。

预算告警由语义字段组成，例如 `metric`、`thresholdPercent` 和 `severity`。预算评估层不再生成固定英文 `message`；Renderer 告警横幅和主进程通知分别使用当前实例翻译同一语义事件。

已知表单校验和扫描警告使用稳定错误代码。界面将代码映射到翻译键；文件路径、行号和原始异常详情作为插值或附加诊断内容保留原样。

### 6.2 主进程

主进程在 `app.whenReady()` 之后：

1. 读取语言偏好。
2. 若不存在有效偏好，则从 `app.getLocale()` 解析初始语言。
3. 初始化主进程 i18next 实例。
4. 初始化预算运行时、通知服务和 IPC。
5. 创建 BrowserWindow。

通知服务在通知创建时读取主进程 i18next 实例，因此语言切换后产生的新通知立即使用新语言。已经显示的操作系统通知不追溯更新。

### 6.3 Renderer

Renderer 在创建 React root 之前通过 IPC 获取当前语言，并等待 i18next 初始化完成，避免启动时先渲染英文再切换。若启动 IPC 失败，Renderer 使用 `en` 启动，应用不得因国际化初始化失败而白屏。

函数组件通过 `useTranslation(namespace)` 获取 `t` 与 i18n 实例。需要格式化数字或日期的组件将当前 `resolvedLanguage` 传入纯格式化函数，不让格式化工具依赖隐藏的全局状态。

根 HTML 元素的 `lang` 属性随当前语言设置为 `en` 或 `zh-CN`。

## 7. 持久化与 IPC

### 7.1 偏好存储

主进程在 Electron `userData` 目录保存独立的语言偏好 JSON 文件，包含 schema version 与显式 locale。写入采用同目录临时文件替换目标文件，避免半写入内容。

文件不存在、结构损坏、schema 不支持或 locale 非法时，不采纳文件内容并回退到系统语言。国际化偏好损坏不能阻止应用启动，也不能改动预算或 Codex 会话数据。

### 7.2 IPC 契约

新增：

- `locale:get`：返回当前 `SupportedLocale`。
- `locale:set`：接收并校验 `SupportedLocale`，成功后返回最终 locale。
- `locale:updated`：主进程向所有窗口广播已提交的语言变化。

Preload 在 `window.codexUsage.locale` 下暴露类型安全的 `get`、`set` 和 `onUpdated`，不直接暴露 `ipcRenderer`。

### 7.3 切换一致性

主进程是语言状态的唯一真值。语言切换按以下顺序执行：

1. 校验 IPC 输入。
2. 记录旧语言并切换主进程 i18next 实例。
3. 原子保存新偏好。
4. 保存成功后广播 `locale:updated`。
5. Renderer 收到广播后调用自己的 `changeLanguage()`。

若持久化失败，主进程切回旧语言、不广播更新并拒绝 IPC 请求。Renderer 保持旧语言，在工具栏语言选择器旁显示带 `role="status"` 的本地化非阻塞错误；下一次成功切换时清除错误。这样不会让两个进程长期处于不同语言。

## 8. 界面设计

工具栏操作区在日期范围与刷新按钮之外增加紧凑的语言选择器，选项固定为：

- `English`
- `中文`

语言名称使用其自身语言书写，避免当前语言下难以识别目标选项。选择器提供本地化 `aria-label`，并沿用现有控件的尺寸、圆角、边框和焦点样式。

国际化覆盖：

- 侧栏、工具栏与页面标题。
- 概览、项目、会话、性能和设置页面。
- 预算中心、预算抽屉、模型价格、确认框和应用内告警。
- 加载、错误、空状态和扫描警告。
- 表单标签、占位符、校验消息、按钮与筛选项。
- `aria-label`、`title`、图表辅助文本等无障碍内容。
- 主进程系统预算通知。

用户数据与技术标识保持原样。未预期的文件系统、IPC 或解析异常显示本地化上下文标题，并附带原始错误详情，不对详情做字符串替换式翻译。

## 9. 格式化

现有格式化函数改为显式接收 `SupportedLocale`：

- `Intl.NumberFormat` 格式化普通数值与紧凑 Token 数。
- `Intl.NumberFormat` 使用固定 `USD` 币种格式化估算费用。
- `Intl.DateTimeFormat` 格式化短日期时间。
- 百分比继续由数值规则生成，并使用当前 locale 的 `Intl.NumberFormat`。

无效日期返回本地化的“未知日期”。切换语言只改变展示格式，不改变日期边界、预算周期、价格、排序键或领域计算。

## 10. 错误处理

- 缺失翻译键：运行时回退英语，资源契约测试负责在提交前发现缺失。
- 非法 locale IPC 输入：主进程拒绝请求且不修改状态或文件。
- 偏好读取失败：回退系统语言并继续启动。
- 偏好写入失败：回滚主进程语言，Renderer 保持旧语言并显示非阻塞错误。
- Renderer 初始 locale IPC 失败：使用英语继续渲染。
- i18next 初始化失败：记录错误并使用内置英语资源重试；仍失败时阻止空白翻译键直接显示。
- 未知业务或系统错误：本地化上下文，保留原始详情。

## 11. 测试策略

### 11.1 共享层

- 系统 locale 映射：`zh`、`zh-CN`、`zh-HK` 等映射为 `zh-CN`，其他值映射为 `en`。
- 支持语言的运行时校验。
- 英文和中文命名空间、键结构完全一致。
- 插值、英文单复数和中文计数表达。
- 告警和校验领域对象不包含固化界面语言。

### 11.2 主进程

- 首次启动跟随系统语言。
- 保存用户选择并在重启后恢复。
- 文件缺失、损坏、非法 locale 与不支持 schema 时安全回退。
- 原子写入失败时不覆盖有效偏好。
- `locale:get`、`locale:set`、非法输入拒绝和更新广播。
- 中英文系统通知标题与预算阈值正文。
- 切换后新通知使用新语言。

### 11.3 Renderer

- 使用每个测试独立的 i18next 实例和 `I18nextProvider`，避免全局语言状态导致测试互相污染。
- 侧栏、工具栏、空状态、预算表单、设置页和无障碍属性的代表性中英文渲染。
- 切换语言后当前页面即时更新。
- 切换失败保持原语言并显示本地化状态消息。
- `<html lang>` 与当前语言一致。
- 英语和中文日期、数值、金额及无效日期格式。

### 11.4 完整验证

实现完成后执行：

- `npm test`
- `npm run lint`
- `npm run typecheck`
- `npm run build`

## 12. 验收标准

- 无已保存偏好时，中文系统启动为简体中文，其他系统启动为英语。
- 用户可以从工具栏在 `English` 与 `中文` 间切换，当前页面无需重启即可更新。
- 用户选择在应用重启后保留。
- Renderer 与主进程通知始终使用同一语言。
- 所有应用自有的可见文案和无障碍文本都有英文与简体中文资源。
- 英文缺失中文键时测试失败；运行时意外缺失仍安全回退英语。
- 日期、数字、Token、百分比和美元金额按当前语言显示，业务计算结果不变。
- 已知校验与扫描警告本地化，原始路径和技术错误详情不被改写。
- 非法 locale、偏好损坏或写入失败不会造成白屏、数据损坏或跨进程长期语言不一致。
- 完整测试、lint、类型检查和构建全部通过。
