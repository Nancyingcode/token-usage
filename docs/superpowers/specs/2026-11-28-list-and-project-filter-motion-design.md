# 会话、项目列表与成本优化筛选动效设计

设计已于 2026-11-28 确认。先改会话和项目列表，让用户连续输入时能一直看清结果，再改成本优化页，让键盘用户在查询期间也能继续切换项目。两项可独立验收。[实施计划](../plans/2026-11-28-list-and-project-filter-motion.md)

## 当前体验

- **搜索和刷新。** 会话页把搜索、筛选和分页条件用作行组的 React key。项目页还把可见项目的路径及顺序放进表体 key。有效搜索词变化时，即使同一行仍然匹配，也会随表体重新挂载。行的入场从透明开始，每行延后 32 ms，到第七行封顶。按样式计算，第七行起等待 192 ms，再播放 180 ms，共 372 ms 才完全显示。[会话列表](../../../src/renderer/components/SessionsView.tsx) · [项目列表](../../../src/renderer/components/ProjectsView.tsx) · [延迟计算](../../../src/renderer/utils/motion.ts) · [行样式](../../../src/renderer/styles/components.css)
- **切换成本优化项目。** 查询条件改变后，成本优化页等待与新条件匹配的快照。加载和就绪状态都参与外层页面 key，状态变化会连同页头的项目选择按钮一起重新挂载。菜单选择结束时，焦点刚回到按钮就可能随原节点移除。[应用入口](../../../src/renderer/App.tsx) · [查询快照](../../../src/renderer/hooks/useCostOptimizationSnapshot.ts) · [成本优化页](../../../src/renderer/components/CostOptimizationView.tsx) · [选择菜单](../../../src/renderer/components/SelectMenu.tsx)

在 `2d432a1` 的应用入口用合成数据和 jsdom 复核了三个场景。展开项目详情后输入仍能匹配该项目的搜索词，搜索框保有焦点，原详情节点被替换并收起。重新展开并聚焦详情，再推送一个新增项目，原详情也收起，焦点落到 `body`。在成本优化页用键盘选取一个项目并挂起查询，加载中和返回结果时按钮各被替换一次，焦点均在 `body`。这些观察覆盖 DOM 和焦点，实际窗口里的播放时长、滚动位置和视觉效果留待 Electron 验收。[合成应用入口](../../../tests/nodeHelpers/rendererMotionFixture.tsx)

## 优先一　会话和项目列表

| 用户操作 | 画面与操作反馈 |
| --- | --- |
| 首次进入页面 | 沿用 180 ms 页面入场。标题、表头和可见行一起出现，直接使用最终顺序。 |
| 在搜索框输入、退格或清空文字 | 每次输入直接更新匹配行，会话页同步更新命中数。项目页的总览和圆环继续显示全部项目。始终匹配的行复用原节点，已展开的详情继续展开，光标留在搜索框。匹配数降为零时立即显示现有空态。 |
| 主动切换会话筛选项、页码、每页条数，或更改项目排序 | 选项、总数、页码和新顺序即时生效。有结果时，表体整体从 90% 到 100% 不透明度淡入一次，使用现有 140 ms 令牌，零延迟。表头、控件和项目圆环保持稳定。主动换组沿用详情收起规则。快速连按直接呈现最后一次选择，重选当前值跳过反馈。 |
| 同条件后台刷新 | 数值与行顺序就地更新。原会话或项目仍在当前结果内时，保留其展开状态和控件上的焦点。若后台更新移除了正聚焦的行且列表页面仍在，焦点回到该列表的搜索框。用户已移到其他控件时，刷新尊重当前焦点。 |

上轮允许筛选时收起详情，本轮建议在打字搜索时保留仍然匹配的展开行。整行退出可见结果后释放其详情。项目主动排序后详情收起，会话翻页再返回时仍从折叠状态开始。窄窗口用 Enter 和空格开合时，字段继续即时出现或收起，箭头沿用原有反馈。[窄窗口列表设计](2026-11-27-compact-usage-tables-design.md) · [现有列表交互测试](../../../tests/analyticsViews.test.tsx)

## 优先二　成本优化页切换项目或时间范围

进入成本优化页时沿用页面入场。留在本页改变项目或时间范围时，页头和项目按钮保持原节点，触发控件立即显示新选择并可再次操作。结果区立即撤下不匹配的旧数据，查询期间显示现有加载提示。匹配的新结果到达后，仅结果区做一次 140 ms 的轻淡入，从 90% 不透明度开始，文字和操作从第一帧可用。快速返回的查询直接呈现结果，无需等骨架或动画播完。[成本优化页](../../../src/renderer/components/CostOptimizationView.tsx) · [加载提示](../../../src/renderer/components/LoadingSkeleton.tsx) · [动效令牌](../../../src/renderer/styles/tokens.css)

连续选择 A、B、C 时，只允许当前项目及时间范围的结果或错误进入结果区。当前查询失败时，保留所选项目、可见错误和键盘操作入口。用户在等待期间重新打开菜单或把焦点移到别处，响应到达后维持其操作位置。同条件快照推送只更新数据。[查询状态规则](../../../src/renderer/utils/costOptimizationSnapshotState.ts) · [项目选择测试](../../../tests/costOptimizationProjectSelect.test.tsx)

## 验收条件

| 场景 | 操作与通过条件 |
| --- | --- |
| 连续输入与翻页 | 准备 30 条会话及至少 8 个同前缀项目。输入、退格、清空，检查每次匹配集合、会话命中数、输入焦点和仍匹配行的身份，逐行入场事件为零。每页 10 条，连续从第 1 页切到第 3 页，检查最终 10 条、页码播报和按钮禁用状态。每次主动排序或翻页最多触发一次表体反馈，时长 140 ms。 |
| 窄窗阅读中刷新 | 在表格容器宽度低于 68rem 时，用键盘展开并聚焦项目 A 的详情。先新增 B，再更新数据使 A 的排序变化。检查 A 的详情仍展开、焦点仍在原控件且可见，页面没有滚回顶部。移除 A 后检查焦点回搜索框。切回宽版再缩窄，复核未被移除行的开合状态。 |
| 异步切项目 | 从应用入口用键盘选择 B，请求尚未返回就选择 C。先返回 C，再让 B 成功或失败。检查项目按钮仍为同一节点、只显示 C 的结果，打开的菜单仍可用。另测当前查询失败、再切换恢复，以及从工具栏改变时间范围，核对焦点留在实际触发控件。 |
| 普通与减少动态效果 | 使用合成数据在 1440 × 900 和 900 × 680 窗口覆盖中英文、深浅主题。普通模式用动画事件与计算样式核对作用元素、延迟和时长。开启减少动态效果时直接显示最终状态。播放中途切换偏好时，当前数据、选项和焦点一次到位。 |

实施验收使用 `npm run test:layout` 检查静态布局，扩展 `npm run test:layout -- --motion` 检查真实动效。若涉及真实 Windows 键盘回绕，以安装窗口中的操作为准。上轮的概览刷新保焦、日期弹窗回焦和窄窗行详情仍作为回归场景。[Electron 动效脚本](../../../scripts/check-renderer-motion.cjs) · [上轮验收记录](../plans/2026-11-27-animation-upgrade.md)
